 # RAG（Retrieval-Augmented Generation，检索增强生成）

在企业级应用中，直接用 LLM（大语言模型）有三个致命伤，只有 RAG 能解决：

- 幻觉 (Hallucinations)： 大模型喜欢一本正经地胡说八道。RAG 强迫它基于事实回答：“请根据以下检索到的内容回答，不知道就说不知道。”

- 时效性 (Freshness)： 大模型训练一次几百万美元，不可能天天更新。RAG 可以随时把今天的财报塞给它。

- 数据隐私 (Privacy)： 公司的合同、代码、工资条不能拿去公网训练模型。RAG 让模型在本地处理这些私有数据。

## 1. RAG 系统的标准流程

1. 第一阶段：数据准备（Indexing）

    这是“备考”阶段，提前把资料整理好。

2. 切片 (Chunking)： 把长文档（PDF/Word）切成一个个小片段（比如 500 字一段）。

    难点： 切太大容易包含噪音，切太小容易丢失上下文。

3. 向量化 (Embedding)：

    把这些文字片段扔进 BGE 或 OpenAI 模型，变成向量。

4. 入库 (Storage)： 
    
    把向量存入 向量数据库 (Vector DB)（如 Milvus, Pinecone, Chroma）。

## 2. RAG 的进化
现在的 RAG 已经不仅仅是简单的“搜一下、答一下”，业界主要分为三种形态：

#### 1. Naive RAG (初级 RAG)
*   **逻辑：** 只有最简单的“切片-索引-检索-生成”。
*   **缺点：** 经常搜不到（准确率低），或者大模型回答时因为资料太多而“迷失中间”。

#### 2. Advanced RAG (高级 RAG) - *目前的主流*
为了解决搜不准的问题，增加了很多优化手段：
*   **预检索 (Pre-Retrieval)：** 比如**查询重写 (Query Rewriting)**。
    *   用户问：“它怎么样？” -> 系统改成：“Qwen-2.5 模型在代码能力上的表现怎么样？”（补全语义）。
*   **混合检索 (Hybrid Search)：** 同时用**向量检索**（看语义）和**关键词检索**（看字面匹配，BM25）。
    *   *解决：* 搜专有名词（如产品型号“X-2000”）时，向量经常搜不到，关键词检索很准。
*   **后检索 (Post-Retrieval)：** 就是你学的 **Rerank**，以及**重组 (Re-ranking & Compression)**，把不相关的信息过滤掉。

#### 3. Modular RAG & GraphRAG (模块化与图 RAG) - *未来的趋势*
*   **GraphRAG (知识图谱 RAG)：** 微软最近带火的概念。
    *   *原理：* 不只是把文字切片，而是提取出实体关系（A 是 B 的父亲，C 收购了 D）。
    *   *解决：* “跨文档的复杂推理”。比如问“路飞的爷爷的同事的敌人的弱点是什么？”，传统 RAG 很难把散落在不同文档里的关系串起来，图谱可以。

## 组件关系

* Embedding 决定了你能不能在海量数据里大概找到相关的书。

* Rerank 决定了你能不能从那几本书里精准翻到对的那一页。

* LLM 决定了能不能把这一页的内容人话讲给用户听。
