“代码分析类提示词”是 **LLM 在开发者领域最常用、最有威力** 的一种 prompt 类型。
它的目标是让模型“理解、解释、重构或优化代码”。

我们可以把这类提示词分成几大类型来看👇

---

## 🧩 一、基础类：理解与解释代码

### 🎯 目的

帮助模型“读懂”代码逻辑、功能或结构。

### 💡 常见提示词模板

```text
请详细解释以下代码的作用，并逐行说明逻辑：
```

```text
用通俗的方式解释这段代码，就像在教一个新手程序员。
```

```text
这段代码是否存在潜在的逻辑漏洞？请指出原因。
```

### 🧠 进阶技巧

加上上下文提示会更精准：

```text
你是一个资深 Python 架构师，请从性能、风格和可维护性角度分析以下函数。
```

---

## 🧱 二、结构类：分析依赖与调用关系

### 🎯 目的

梳理项目结构或模块之间的调用关系。

### 💡 示例提示词

```text
请分析这段代码中各个函数之间的调用关系，并画出层级结构。
```

```text
根据以下文件内容，推测这个项目的模块划分和主要职责。
```

```text
请解释这段类继承结构中父类与子类之间的关系。
```

---

## ⚙️ 三、性能与复杂度分析类

### 🎯 目的

让模型从算法角度分析效率、空间复杂度或可优化点。

### 💡 示例提示词

```text
请分析这段代码的时间复杂度和空间复杂度。
```

```text
如何优化这段代码的性能？请列出三种方法。
```

```text
请指出这段循环中可能的性能瓶颈。
```

---

## 🔒 四、安全与漏洞分析类

### 🎯 目的

让模型找出潜在的安全隐患或不安全调用。

### 💡 示例提示词

```text
请检查以下 Python 代码是否存在注入风险或未验证输入的问题。
```

```text
请找出这段代码可能被攻击或利用的地方，并说明攻击方式。
```

```text
这段 Java 代码中是否可能存在并发安全问题？
```

---

## 🧠 五、风格与规范检查类

### 🎯 目的

检测代码是否符合风格指南（如 PEP8、Airbnb JS、Google Style 等）。

### 💡 示例提示词

```text
请根据 PEP8 检查以下 Python 代码风格，并给出修改建议。
```

```text
请指出这段 JavaScript 代码中不符合 Airbnb Style 的地方。
```

```text
请把以下代码改写成更易读、更规范的版本。
```

---

## 🧩 六、AI 辅助代码审查（Code Review）类

### 🎯 目的

模拟团队中的代码审查流程。

### 💡 示例提示词

```text
假设你是高级后端工程师，请审查这段代码并提出具体的改进意见。
```

```text
请帮我做一次代码审查，关注性能、异常处理和命名规范。
```

```text
请总结这段代码的优点与缺点，并给出优化建议。
```

---

## 🧠 七、综合分析类（多角度 Prompt）

### 🎯 目的

让模型从多个维度同时分析。

### 💡 模板

```text
请你从以下四个角度分析这段代码：
1. 功能逻辑  
2. 性能表现  
3. 可维护性  
4. 潜在安全风险
请分条说明。
```

或者：

```text
请先简要总结代码功能，然后指出两个可优化的点，并解释原因。
```

---

## 🧩 小结表格

| 类型   | 示例提示词关键句      | 典型场景        |
| ---- | ------------- | ----------- |
| 理解分析 | “解释以下代码的作用”   | 阅读陌生代码      |
| 调用结构 | “分析函数之间的调用关系” | 理解项目架构      |
| 性能分析 | “分析时间复杂度”     | 优化算法        |
| 安全分析 | “是否存在安全漏洞”    | 安全审计        |
| 风格检查 | “是否符合规范”      | Code Review |
| 综合分析 | “从多角度分析代码”    | 技术面试/审查     |
