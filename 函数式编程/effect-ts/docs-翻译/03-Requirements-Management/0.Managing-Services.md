# 管理服务和依赖

在编程语境中，service（服务）指的是一种可复用的组件或功能，它可以被应用程序的不同部分使用。服务通常被设计为提供某种特定能力，并且能够在多个模块或组件之间共享。

服务通常用于封装应用中多个部分都会用到的通用任务或操作，并把这些任务整理成独立、可复用、可替换的功能模块。它们的职责往往比普通函数更明确，也比工具类更具结构性，因此在现代应用架构中扮演着核心角色。。

服务通常被设计成模块化并且与应用程序的其他部分解耦，这样它们就能独立演化，而不会牵动整个系统的结构或行为。模块化和解耦是服务设计的核心原则，它们直接带来可维护性、可测试性和可替换性。

把服务和依赖整合到应用里时，如果不使用任何高级机制（比如依赖注入、Context、Layer），就只能靠最原始的方式,把服务当作函数参数手动传来传去:

```ts
const processData = (data: Data, databaseService: DatabaseService) => {
  // Operations using the database service
}
```

为了让这一过程更简化，你可能会考虑使用一个环境对象，把各种服务打包在一起。

```ts
type Context = {
  databaseService: DatabaseService
  loggingService: LoggingService
}

const processData = (data: Data, context: Context) => {
  // Using multiple services from the context
}
```

然而，这又带来了新的复杂性：你必须确保环境对象在使用前已经正确配置了所有必需的服务，这会导致代码之间的紧密耦合，并让函数式组合与测试变得更加困难。

## 使用 Effect 管理服务

Effect 库通过利用类型系统来简化这些依赖项的管理。

不同手传递服务或环境对象，Effect 允许你在函数类型签名中直接使用 Effect 类型的 `Requirements `参数声明服务依赖：


```
                         ┌─── Represents required dependencies
                         ▼
Effect<Success, Error, Requirements>
```

在实际使用 Effect 时，它是这样工作的：

* 依赖声明：你直接在类型中指定函数需要什么服务，将依赖管理的复杂性推入类型系统。

* 服务提供：`Effect.provideService` 用于将某个服务的实现提供给需要它的函数。通过在程序开始阶段提供服务，你可以确保应用的所有部分都能一致地访问所需的服务，从而保持架构的整洁与解耦。

这种方法抽象了手动服务处理，让开发人员专注于业务逻辑，同时编译器确保所有依赖项都被正确管理。它还使代码更加可维护和可扩展。

让我们逐步了解 Effect 中管理服务的方式：

1. **创建服务**: 定义具有唯一功能和接口。
2. **使用服务**: 在应用程序的函数中访问和利用服务。
3. **提供服务的实现**: 提供服务的实际实现来满足声明的需求。

## 工作原理

到目前为止，我们使用 Effect 框架的例子都是处理那些独立于外部服务运行的效果。这意味着我们的 `Effect` 类型签名中的 `Requirements` 参数设置为 `never`，表示没有依赖项。

然而，现实世界的应用程序通常需要依赖特定服务才能正确运行的效果。这些服务通过一个称为 `Context` 的构造来管理和访问。

`Context` 充当效果所需的所有服务的仓库或容器。它就像一个存储，维护这些服务，允许应用程序的不同部分根据需要访问和使用它们。

存储在 `Context `中的服务直接反映在 Effect 类型的



Requirements `参数”。Context `的每个服务都由一个唯一的 `tag` 标识，这本质上就是服务的唯一标识符。

当效果需要使用特定服务时，服务的标签就包含在 `Requirements` 类型参数中。

## 创建服务

要创建新服务，你需要两件事：

1. 一个唯一的 **标识符**。
2. 一个描述服务可能操作的 **类型**。

**示例**（定义随机数生成器服务）

让我们创建一个用于生成随机数的服务。

1. **标识符**。我们使用字符串 `"MyRandomService"` 作为唯一标识符。
2. **类型**。服务类型将有一个名为 `next `的操作，返回一个随机数。

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}
```

导出的 `Random` 值在 Effect 中被称为 **tag**。它充当服务的表示，并允许 Effect 在运行时定位和使用此服务。

服务将存储在一个名为 `Context `的集合中，可以将其视为 `Map`，其中键是标签，值是服务：

```ts
type Context = Map<Tag, Service>
```

---

***为什么要使用标识符?***

> 你需要指定一个标识符，使这个 tag 成为全局的。这样可以确保两个具有相同标识符的 tag 实际上引用的是同一个全局 tag，也就是说它们会指向同一个实例。使用唯一的标识符在可能发生热重载的场景中特别有用，因为它能帮助在重载过程中保留同一个实例，避免实例被重复创建（尽管理论上不应该发生，但某些打包工具或框架可能会有不可预测的行为）。

---

以下是我们到目前为止所涵盖的概念摘要：

| 概念  | 描述 |
| ---| --- |
| **service** | 一个用于表示某个服务的唯一标识符，使 Effect 能够定位并使用该*服务*(service)。|
| **tag**     | 一个可复用的组件，提供特定功能，并可在应用程序的不同部分中使用。|
| **context** | 一个用于存储服务的集合，其工作方式类似于一个映射结构，以 tag 作为键、以 service |

## 使用服务

现在我们已经定义了服务标签，让我们通过构建一个简单的程序来看看如何使用它。

**示例**（使用 Random 服务）

---
### 使用 Effect.gen

```ts
import { Effect, Context } from "effect"

// 为一个生成随机数的服务声明一个 Tag
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

// Using the service
//
//      ┌─── Effect<void, never, Random>
//      ▼
const program = Effect.gen(function* () {
  const random = yield* Random
  const randomNumber = yield* random.next
  console.log(`random number: ${randomNumber}`)
})
```

### 使用 pipe

```ts
import { Effect, Context, Console } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

// Using the service
//
//      ┌─── Effect<void, never, Random>
//      ▼
const program = Random.pipe(
  Effect.andThen((random) => random.next),
  Effect.andThen((randomNumber) =>
    Console.log(`random number: ${randomNumber}`)
  )
)
```

---

在上面的代码中，我们可以看到，我们能够像对待一个 effect 一样对 Random 这个 tag 进行 flat‑map。这使我们能够在 Effect.andThen 的回调中访问该服务的下一步操作。

值得注意的是，`program` 变量的类型在 `Requirements` 类型参数中包含 `Random`：

```ts
const program: Effect<void, never, Random>
```

这表明我们的程序需要 `Random` 服务才能成功执行。

如果我们尝试在没有提供必要服务的情况下执行效果，我们将遇到类型检查错误：

**示例**（未提供服务的类型错误）

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

// Using the service
const program = Effect.gen(function* () {
  const random = yield* Random
  const randomNumber = yield* random.next
  console.log(`random number: ${randomNumber}`)
})

Effect.runSync(program)
//             ^^^^^^^
//Error ts(2379) ― Argument of type 'Effect<void, never, Random>' 
//is not assignable to parameter of type 'Effect<void, never, never>'
//  with 'exactOptionalPropertyTypes: true'. Consider adding
//  'undefined' to the types of the target's properties. Type 'Random'
//  is not assignable to type 'never'.
```

为了解决这个错误并成功执行程序，我们需要提供 `Random` 服务的实际实现。

在接下来的部分中，我们将探索如何实现并向程序提供 `Random` 服务，使我们可以成功运行它。

## 提供服务的实现

为了提供 `Random` 服务的实际实现，我们可以利用 `Effect.provideService` 函数。

**示例**（提供随机数实现）

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

// Using the service
const program = Effect.gen(function* () {
  const random = yield* Random
  const randomNumber = yield* random.next
  console.log(`random number: ${randomNumber}`)
})

// Providing the implementation
//
//      ┌─── Effect<void, never, never>
//      ▼
const runnable = Effect.provideService(program, Random, {
  next: Effect.sync(() => Math.random())
})

// Run successfully
Effect.runPromise(runnable)
/*
Example Output:
random number: 0.8241872233134417
*/
```

在上面的代码中，我们为之前定义的程序提供了 `Random` 服务的具体实现。

我们使用 Effect.provideService 函数，将 Random 这个 tag 与它的实现关联起来,一个带有 next 操作、用于生成随机数的对象。

请注意，可运行的 effect 的 Requirements 类型参数现在是 never。这表示该 effect 不再需要任何服务被提供。

随着 Random 服务的实现已经就位，我们现在能够在没有任何额外需求的情况下运行这个程序。

## Extracting the Service Type | 提取服务类型

要从标签获取服务类型，请在使用 `Context.Tag.Service` 实用类型。

**示例**（提取服务类型）

```ts
import { Effect, Context } from "effect"

// Declaring a tag
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

// Extracting the type
type RandomShape = Context.Tag.Service<Random>
/*
This is equivalent to:
type RandomShape = {
    readonly next: Effect.Effect<number>;
}
*/
```

## 使用多个服务

当我们要求使用多个服务时，其过程与我们在定义服务时所学到的相似，只需针对每个所需的服务重复该过程即可。

示例（使用 Random 和 Logger 服务）

让我们来看一个需要两个服务的例子，即 Random 和 Logger：

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  {
    readonly next: Effect.Effect<number>
  }
>() {}

// Declaring a tag for the logging service
class Logger extends Context.Tag("MyLoggerService")<
  Logger,
  {
    readonly log: (message: string) => Effect.Effect<void>
  }
>() {}

const program = Effect.gen(function* () {
  const random = yield* Random
  const logger = yield* Logger

  const randomNumber = yield* random.next

  yield* logger.log(String(randomNumber))
})
```

该程序的 effect 现在具有 Random | Logger 作为它的 Requirements 类型参数。

```ts
const program: Effect<void, never, Random | Logger>
```

这表明它需要同时提供 Random 和 Logger 两个服务。

要执行这个程序，我们需要同时为这两个服务提供各自的实现：

**示例**（提供多个服务）

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  {
    readonly next: Effect.Effect<number>
  }
>() {}

// Declaring a tag for the logging service
class Logger extends Context.Tag("MyLoggerService")<
  Logger,
  {
    readonly log: (message: string) => Effect.Effect<void>
  }
>() {}

const program = Effect.gen(function* () {
  const random = yield* Random
  const logger = yield* Logger
  const randomNumber = yield* random.next
  return yield* logger.log(String(randomNumber))
})

// Provide service implementations for 'Random' and 'Logger'
const runnable = program.pipe(
  Effect.provideService(Random, {
    next: Effect.sync(() => Math.random())
  }),
  Effect.provideService(Logger, {
    log: (message) => Effect.sync(() => console.log(message))
  })
)
```

或者，而不是多次调用 `provideService`，我们可以将服务实现组合到一个单独的 `Context` 中，然后使用 `Effect.provide` 函数提供整个上下文：

**示例**（合并服务实现）

```ts
import { Effect, Context } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  {
    readonly next: Effect.Effect<number>
  }
>() {}

// Declaring a tag for the logging service
class Logger extends Context.Tag("MyLoggerService")<
  Logger,
  {
    readonly log: (message: string) => Effect.Effect<void>
  }
>() {}

const program = Effect.gen(function* () {
  const random = yield* Random
  const logger = yield* Logger
  const randomNumber = yield* random.next
  return yield* logger.log(String(randomNumber))
})

// Combine service implementations into a single 'Context'
const context = Context.empty().pipe(
  Context.add(Random, { next: Effect.sync(() => Math.random()) }),
  Context.add(Logger, {
    log: (message) => Effect.sync(() => console.log(message))
  })
)

// Provide the entire context
const runnable = Effect.provide(program, context)
```

## 可选服务

有些情况下，我们可能只想在服务可用时访问服务实现。在这种情况下，我们可以使用 `Effect.serviceOption` 函数来处理这种情况。

`Effect.serviceOption` 函数返回仅在在执行该效果之前实际提供了实现时才可用的格式。为了表示这种可选性，它返回一个 [Option](/docs/data-types/option/) 类型。

**示例**（处理可选服务）

为了确定要执行的操作，我们可以使用 Option 模块提供的 `Option.isNone` 函数。该函数允许我们通过检查服务是否可用来检查服务是否存在，在服务不可用时返回 `true`。

```ts
import { Effect, Context, Option } from "effect"

// Declaring a tag for a service that generates random numbers
class Random extends Context.Tag("MyRandomService")<
  Random,
  { readonly next: Effect.Effect<number> }
>() {}

const program = Effect.gen(function* () {
  const maybeRandom = yield* Effect.serviceOption(Random)
  const randomNumber = Option.isNone(maybeRandom)
    ? // the service is not available, return a default value
      -1
    : // the service is available
      yield* maybeRandom.value.next
  console.log(randomNumber)
})
```

在上面的代码中，我们可以看到，尽管我们正在处理服务，但 `program` 效果的 `Requirements` 类型参数是 `never`。这允许我们仅在在执行效果之前实际提供了它时才访问上下文中的一些内容。

当我们不向 `program` 效果提供 `Random` 服务时运行它：

```ts
Effect.runPromise(program).then(console.log)
// Output: -1
```

我们看到的日志消息包含 `-1`，此为服务不可用

When we don't provide the `Random` service to the `program` effect:

```ts
Effect.runPromise(program).then(console.log)
// Output: -1
```

我们看到的日志消息包含 `-1`，即服务不可用时我们提供的默认值。

However, if we provide the `Random` service implementation:

```ts
Effect.runPromise(
  Effect.provideService(program, Random, {
    next: Effect.sync(() => Math.random())
  })
).then(console.log)
// Example Output: 0.9957979486841035
```

我们可以看到日志消息现在包含由 `Random` 服务的 `next` 操作生成的随机数。

## 处理具有依赖的服务

有时，应用程序中的服务可能依赖于其他服务。为了保持清晰的架构，重要的是在无需在服务的接口中显式说明的情况下管理这些依赖项。相反，你可以使用 **layers** 在服务构建过程中处理这些依赖项。

**示例**（定义具有配置依赖的 Logger 服务）

考虑一个多个服务相互依赖的场景。在这种情况下，`Logger` 服务需要访问配置服务 (`Config`)。

```ts
import { Effect, Context } from "effect"

// Declaring a tag for the Config service
class Config extends Context.Tag("Config")<Config, {}>() {}

// Declaring a tag for the logging service
class Logger extends Context.Tag("MyLoggerService")<
  Logger,
  {
    // ❌ 避免将 Config 暴露为一个 requirement
    readonly log: (message: string) => Effect.Effect<void, never, Config>
  }
>() {}
```

为了以结构化的方式处理这些依赖项，防止它们泄漏到服务接口中，你可以使用 `Layer` 抽象。关于使用 layers 管理依赖的更多详细信息，请参阅 [Managing Layers](/docs/requirements-management/layers/) 页面。

---
**使用 Layer 来管理依赖**

> 当一个服务本身也有依赖时，最好的做法是将实现细节拆分到 Layer 中。Layer 充当服务的构造器，让我们能够在构造阶段处理依赖，而不是在服务本身的层级处理。
