# 两种错误类型

与其他任何程序一样，Effect 程序可能会因为预期或非预期的原因而失败。非 Effect 程序与 Effect 程序之间的区别在于，当程序失败时提供给你的细节信息。Effect 尝试尽可能多地保留导致程序失败的原因信息，以生成详细、全面且易于理解的失败消息。

在 Effect 程序中，程序有两种可能的失败方式：

- **预期错误 (Expected Errors)**：这些是开发者在程序正常执行过程中预见并期待的错误。
- **非预期错误 (Unexpected Errors)**：这些是意外发生的、不属于预期程序流程的错误。

## 预期错误 (Expected Errors)

这些错误也被称为“失败 (failures)”、“类型化错误 (typed errors)”或“可恢复错误 (recoverable errors)”，是开发者在程序正常执行过程中预见的错误。它们的作用类似于受检异常 (checked exceptions)，并在定义程序的领域模型和控制流中发挥作用。

预期错误在 `Effect` 数据类型的“错误 (Error)”通道中通过类型层面进行**追踪**：

```ts "HttpError" showLineNumbers=false
const program: Effect<string, HttpError, never>
```

从类型中可以明显看出，该程序可能会因 `HttpError` 类型的错误而失败。

## 非预期错误 (Unexpected Errors)

非预期错误也被称为“缺陷 (defects)”、“非类型化错误 (untyped errors)”或“不可恢复错误 (unrecoverable errors)”，是开发者不希望在程序正常执行过程中发生的错误。与被视为程序领域和控制流一部分的预期错误不同，非预期错误类似于非受检异常 (unchecked exceptions)，且存在于程序的预期行为之外。

由于这些错误是不可预见的，Effect **不会**在类型层面追踪它们。然而，Effect 运行时会追踪这些错误，并提供多种方法来辅助从非预期错误中恢复。
