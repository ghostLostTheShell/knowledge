# Expected error | 预期错误

预期错误在类型级别通过 [Effect 数据类型](/docs/getting-started/the-effect-type/) 的“错误通道（Error channel）”进行追踪：

```text showLineNumbers=false "Error"
         ┌─── 代表成功类型
         │        ┌─── 代表错误类型
         │        │      ┌─── 代表所需的依赖
         ▼        ▼      ▼
Effect<Success, Error, Requirements>
```

这意味着 `Effect` 类型不仅捕获了程序成功时返回的结果，还捕获了它可能产生的错误类型。

**示例**（创建一个可能失败的 Effect）

在这个示例中，我们定义了一个可能会随机发生 `HttpError` 错误的程序。

```ts
import { Effect, Random, Data } from "effect"

// 使用 Data.TaggedError 定义一个自定义错误类型
class HttpError extends Data.TaggedError("HttpError")<{}> {}

//      ┌─── Effect<string, HttpError, never>
//      ▼
const program = Effect.gen(function* () {
  // 生成一个 0 到 1 之间的随机数
  const n = yield* Random.next

  // 模拟一个 HTTP 错误
  if (n < 0.5) {
    return yield* Effect.fail(new HttpError())
  }

  return "some result"
})
```

`program` 的类型告诉我们，它要么返回一个 `string`，要么会因 `HttpError` 而失败：

```ts "string" "HttpError" showLineNumbers=false
const program: Effect<string, HttpError, never>
```

在这种情况下，我们使用一个类来表示 `HttpError` 类型，这允许我们同时定义错误类型和构造函数。

当使用 `Data.TaggedError` 时，类中会自动添加一个 `_tag` 字段：

```ts showLineNumbers=false
// 此字段用作错误的判别标识（discriminant）
console.log(new HttpError()._tag)
// 输出: "HttpError"
```

当我们讨论像 [Effect.catchTag](#catchtag) 这样有助于处理特定错误类型的 API 时，这个判别字段将会非常有用。

---
**为什么 Tagged Errors 很有用**
> 添加一个判别字段（例如 `_tag`）有助于在错误处理过程中区分不同类型的错误。它还可以防止 TypeScript 进行类型合并（unification），确保每个错误都能根据其判别值被唯一地对待。
有关构建 Tagged Errors 的更多信息，请参阅 Data.TaggedError。

---

## 错误追踪

在 Effect 中，如果一个程序可能因多种类型的错误而失败，它们会被自动追踪为这些错误类型的联合类型（union）。
这让你能够确切地知道执行过程中可能发生哪些错误，从而使错误处理更加精确且可预测。

下面的示例展示了错误是如何为你自动追踪的。

**示例**（自动追踪错误）

```ts twoslash
import { Effect, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  // 生成两个 0 到 1 之间的随机数
  const n1 = yield* Random.next
  const n2 = yield* Random.next

  // 模拟一个 HTTP 错误
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  // 模拟一个验证错误
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }

  return "some result"
})
```

Effect 会自动将程序执行期间可能发生的潜在错误记录为一个联合类型：

```ts "HttpError | ValidationError" showLineNumbers=false
const program: Effect<string, HttpError | ValidationError, never>
```

这表明该程序可能会因 `HttpError` 或 `ValidationError` 而失败。
## 短路机制 (Short-Circuiting)

在使用像 [Effect.gen](/docs/getting-started/using-generators/#understanding-effectgen)、[Effect.map](/docs/getting-started/building-pipelines/#map)、[Effect.flatMap](/docs/getting-started/building-pipelines/#flatmap) 以及 [Effect.andThen](/docs/getting-started/building-pipelines/#andthen) 这样的 API 时，理解它们如何处理错误至关重要。这些 API 被设计为在遇到**第一个错误**时立即**短路执行**。

这对作为开发者的你意味着什么？假设你有一系列操作或一组需要顺序执行的 Effect。如果在其中一个 Effect 的执行过程中发生了任何错误，后续的计算将被跳过，错误将传播到最终结果中。

简而言之，短路行为确保了如果程序的任何步骤出错，它都不会浪费时间执行不必要的计算。相反，它会立即停止并返回错误，让你知道出了问题。

**示例**（短路行为）

```ts twoslash {14-15}
import { Effect, Console } from "effect"

// 定义三个代表不同任务的 Effect。
const task1 = Console.log("Executing task1...")
const task2 = Effect.fail("Something went wrong!")
const task3 = Console.log("Executing task3...")

// 组合这三个任务以按顺序运行它们。
// 如果其中一个任务失败，后续任务将不会执行。
const program = Effect.gen(function* () {
  yield* task1
  // 在 task1 之后执行 task2，但它会因错误而失败
  yield* task2
  // 由于前一个任务失败，该计算将不会被执行
  yield* task3
})

Effect.runPromiseExit(program).then(console.log)
/*
输出：
Executing task1...
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: { _id: 'Cause', _tag: 'Fail', failure: 'Something went wrong!' }
}
*/
```

这段代码片段演示了发生错误时的短路行为。每个操作都依赖于前一个操作的成功执行。如果发生任何错误，执行就会短路，且错误会被传播。在这个特定的例子中，由于 `task2` 中发生了错误，`task3` 永远不会被执行。
## 捕获所有错误

### either

`Effect.either` 函数将 `Effect<A, E, R>` 转换为一个将潜在的失败和成功封装在 [Either](/docs/data-types/either/) 数据类型中的 Effect：

```ts showLineNumbers=false
Effect<A, E, R> -> Effect<Either<A, E>, never, R>
```

这意味着如果你有一个如下类型的 Effect：

```ts showLineNumbers=false
Effect<string, HttpError, never>
```

并且对其调用 `Effect.either`，类型将变为：

```ts showLineNumbers=false
Effect<Either<string, HttpError>, never, never>
```

得到的 Effect 不会失败，因为潜在的失败现在由 `Either` 的 `Left` 类型表示。返回的 `Effect` 的错误类型被指定为 `never`，这确认了该 Effect 的结构是不失败的。

通过 yield 一个 `Either`，我们获得了对该类型进行“模式匹配（pattern match）”的能力，从而可以在生成器函数（generator function）内部同时处理失败和成功的情况。

**示例**（使用 `Effect.either` 处理错误）

```ts twoslash
import { Effect, Either, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = Effect.gen(function* () {
  //      ┌─── Either<string, HttpError | ValidationError>
  //      ▼
  const failureOrSuccess = yield* Effect.either(program)
  if (Either.isLeft(failureOrSuccess)) {
    // 失败情况：你可以从 `left` 属性中提取错误
    const error = failureOrSuccess.left
    return `Recovering from ${error._tag}`
  } else {
    // 成功情况：你可以从 `right` 属性中提取值
    return failureOrSuccess.right
  }
})
```

如你所见，由于处理了所有错误，得到的 Effect `recovered` 的错误类型为 `never`：

```ts showLineNumbers=false
const recovered: Effect<string, never, never>
```

我们可以通过使用 `Either.match` 函数来简化代码，该函数直接接受两个用于处理错误和成功值的回调函数：

**示例**（使用 `Either.match` 进行简化）

```ts twoslash collapse={3-19}
import { Effect, Either, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = Effect.gen(function* () {
  //      ┌─── Either<string, HttpError | ValidationError>
  //      ▼
  const failureOrSuccess = yield* Effect.either(program)
  return Either.match(failureOrSuccess, {
    onLeft: (error) => `Recovering from ${error._tag}`,
    onRight: (value) => value // 成功时不进行额外处理
  })
})
```

### option

使用 [Option](/docs/data-types/option/) 数据类型转换一个 Effect，以同时封装失败和成功的情况。

`Effect.option` 函数将 Effect 的成功或失败包装在 `Option` 类型中，使这两种情况都变得显式。如果原始 Effect 成功，其值将被包装在 `Option.some` 中；如果失败，则失败将被映射为 `Option.none`。

得到的 Effect 不会直接失败，因为其错误类型被设置为 `never`。然而，像 defect（缺陷）这样的致命错误不会被封装。

**示例**（使用 `Effect.option` 处理错误）

```ts twoslash
import { Effect } from "effect"

const maybe1 = Effect.option(Effect.succeed(1))

Effect.runPromiseExit(maybe1).then(console.log)
/*
输出：
{
  _id: 'Exit',
  _tag: 'Success',
  value: { _id: 'Option', _tag: 'Some', value: 1 }
}
*/

const maybe2 = Effect.option(Effect.fail("Uh oh!"))

Effect.runPromiseExit(maybe2).then(console.log)
/*
输出：
{
  _id: 'Exit',
  _tag: 'Success',
  value: { _id: 'Option', _tag: 'None' }
}
*/

const maybe3 = Effect.option(Effect.die("Boom!"))

Effect.runPromiseExit(maybe3).then(console.log)
/*
输出：
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: { _id: 'Cause', _tag: 'Die', defect: 'Boom!' }
}
*/
```
### catchAll

通过提供一个备用（fallback）Effect 来处理 Effect 中的所有错误。

`Effect.catchAll` 函数会捕获 Effect 执行过程中可能发生的任何错误，并允许你通过指定一个备用 Effect 来处理它们。这确保了程序能够通过提供的备用逻辑从错误中恢复，从而继续运行而不会失败。

<Aside type="note" title="仅限可恢复错误">
  `Effect.catchAll` 仅处理可恢复错误。它不会从不可恢复的缺陷（defects）中恢复。有关处理所有类型失败的信息，请参阅 [Effect.catchAllCause](#catchallcause)。
</Aside>

**示例**（为可恢复错误提供恢复逻辑）

```ts twoslash
import { Effect, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = program.pipe(
  Effect.catchAll((error) =>
    Effect.succeed(`Recovering from ${error._tag}`)
  )
)
```

我们可以观察到，程序错误通道中的类型已经变为了 `never`：

```ts showLineNumbers=false
const recovered: Effect<string, never, never>
```

这表明所有错误都已得到处理。
### catchAllCause

通过提供一个恢复 Effect 来处理可恢复和不可恢复的错误。

`Effect.catchAllCause` 函数允许你通过提供一个恢复 Effect 来处理所有错误，包括不可恢复的缺陷（defects）。其恢复逻辑基于错误的 `Cause`，`Cause` 提供了有关失败的详细信息。

**示例**（从所有错误中恢复）

```ts twoslash
import { Cause, Effect } from "effect"

// 定义一个可能因可恢复或不可恢复错误而失败的 Effect
const program = Effect.fail("Something went wrong!")

// 通过检查 cause 从所有错误中恢复
const recovered = program.pipe(
  Effect.catchAllCause((cause) =>
    Cause.isFailType(cause)
      ? Effect.succeed("Recovered from a regular error")
      : Effect.succeed("Recovered from a defect")
  )
)

Effect.runPromise(recovered).then(console.log)
// 输出: "Recovered from a regular error"
```

---
**缺陷中恢复**

> 缺陷（Defects）是意外的错误，通常不应该被恢复，因为它们往往预示着严重的问题。但在某些情况下，例如处理动态加载的插件时，可能需要进行受控的恢复。

## 捕获部分错误

### either

[`Effect.either`](#either) 函数（之前作为捕获所有错误的一种方式展示过）也可以用来捕获特定的错误。

通过 yield 一个 `Either`，我们获得了对该类型进行“模式匹配（pattern match）”的能力，从而可以在生成器函数（generator function）内部同时处理失败和成功的情况。

**示例**（使用 `Effect.either` 处理特定错误）

```ts twoslash
import { Effect, Random, Either, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, ValidationError, never>
//      ▼
const recovered = Effect.gen(function* () {
  const failureOrSuccess = yield* Effect.either(program)
  if (Either.isLeft(failureOrSuccess)) {
    const error = failureOrSuccess.left
    // 仅处理 HttpError 错误
    if (error._tag === "HttpError") {
      return "Recovering from HttpError"
    } else {
      // 重新抛出 ValidationError
      return yield* Effect.fail(error)
    }
  } else {
    return failureOrSuccess.right
  }
})
```

我们可以观察到，程序错误通道中的类型已经变为了仅显示 `ValidationError`：

```ts "ValidationError" showLineNumbers=false
const recovered: Effect<string, ValidationError, never>
```

这表明 `HttpError` 已经得到了处理。

如果我们也想处理 `ValidationError`，可以很容易地在代码中添加另一个分支：

```ts twoslash collapse={3-17} {28-30}
import { Effect, Random, Either, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = Effect.gen(function* () {
  const failureOrSuccess = yield* Effect.either(program)
  if (Either.isLeft(failureOrSuccess)) {
    const error = failureOrSuccess.left
    // 同时处理 HttpError 和 ValidationError
    if (error._tag === "HttpError") {
      return "Recovering from HttpError"
    } else {
      return "Recovering from ValidationError"
    }
  } else {
    return failureOrSuccess.right
  }
})
```

我们可以观察到，错误通道中的类型已经变为了 `never`：

```ts showLineNumbers=false
const recovered: Effect<string, never, never>
```

这表明所有错误都已得到处理。
### catchSome

捕获并从特定类型的错误中恢复，允许你仅针对某些错误尝试恢复。

`Effect.catchSome` 允许你通过为特定错误提供恢复 Effect，从而选择性地捕获并处理某些类型的错误。如果错误符合条件，则尝试恢复；如果不符合，则不会影响程序。此函数不会改变错误类型，这意味着错误类型仍与原始 Effect 保持一致。

**示例**（使用 `Effect.catchSome` 处理特定错误）

```ts twoslash
import { Effect, Random, Option, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const recovered = program.pipe(
  Effect.catchSome((error) => {
    // 仅处理 HttpError 错误
    if (error._tag === "HttpError") {
      return Option.some(Effect.succeed("Recovering from HttpError"))
    } else {
      return Option.none()
    }
  })
)
```

在上面的代码中，`Effect.catchSome` 接受一个函数，该函数会检查错误并决定是否尝试恢复。如果错误匹配特定条件，可以通过返回 `Option.some(effect)` 来尝试恢复。如果无法恢复，只需返回 `Option.none()` 即可。

需要注意的是，虽然 `Effect.catchSome` 允许你捕获特定的错误，但它本身不会改变错误类型。因此，生成的 Effect 仍将具有与原始 Effect 相同的错误类型：

```ts "HttpError | ValidationError" showLineNumbers=false
const recovered: Effect<string, HttpError | ValidationError, never>
```

### catchIf

根据谓词（predicate）恢复特定错误。

`Effect.catchIf` 的工作方式类似于 [`Effect.catchSome`](#catchsome)，但它允许你通过提供一个谓词函数来从错误中恢复。如果谓词与错误匹配，则应用恢复 Effect。此函数不会改变错误类型，因此生成的 Effect 仍然携带原始错误类型，除非使用了用户定义的类型守卫（type guard）来收窄类型。

**示例**（使用谓词捕获特定错误）

```ts twoslash
import { Data, Effect, Random } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, ValidationError, never>
//      ▼
const recovered = program.pipe(
  Effect.catchIf(
    // 仅处理 HttpError 错误
    (error) => error._tag === "HttpError",
    () => Effect.succeed("Recovering from HttpError")
  )
)
```

需要注意的是，对于 TypeScript 5.5 以下的版本，虽然 `Effect.catchIf` 允许你捕获特定错误，但它**不会改变错误类型**本身。因此，生成的 Effect 仍将具有与原始 Effect 相同的错误类型：

```ts "HttpError | ValidationError" showLineNumbers=false
const recovered: Effect<string, HttpError | ValidationError, never>
```

在 TypeScript 5.5 及以上版本中，改进的类型收窄（type narrowing）会使生成的错误类型被推断为 `ValidationError`。

#### TypeScript 5.5 以下版本的替代方案

如果你提供一个 [用户定义的类型守卫](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#using-type-predicates) 而不是普通的谓词，生成的错误类型将被修剪（pruned），返回 `Effect<string, ValidationError, never>`：

```ts twoslash collapse={3-19} {25-26}
import { Data, Effect, Random } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, ValidationError, never>
//      ▼
const recovered = program.pipe(
  Effect.catchIf(
    // 用户定义的类型守卫
    (error): error is HttpError => error._tag === "HttpError",
    () => Effect.succeed("Recovering from HttpError")
  )
)
```
### catchTag

通过 `_tag` 字段（用作判别项）捕获并处理特定的错误。

当你的错误带有标识错误类型的 `_tag` 字段时，`Effect.catchTag` 非常有用。你可以通过匹配 `_tag` 的值来使用此函数处理特定的错误类型。这实现了精确的错误处理，确保只有特定的错误被捕获和处理。

要使用 `Effect.catchTag`，错误类型必须包含一个 `_tag` 字段。该字段用于识别和匹配错误。

**示例**（通过 Tag 处理错误）

```ts twoslash
import { Effect, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, ValidationError, never>
//      ▼
const recovered = program.pipe(
  // 仅处理 HttpError 错误
  Effect.catchTag("HttpError", (_HttpError) =>
    Effect.succeed("Recovering from HttpError")
  )
)
```

在上面的示例中，`Effect.catchTag` 函数允许我们专门处理 `HttpError`。如果在程序执行过程中发生了 `HttpError`，提供的错误处理函数将被调用，程序将按照处理程序中指定的恢复逻辑继续运行。

我们可以观察到，程序错误通道中的类型已经更改为仅显示 `ValidationError`：

```ts showLineNumbers=false
const recovered: Effect<string, ValidationError, never>
```

这表明 `HttpError` 已经得到了处理。

如果我们也想处理 `ValidationError`，只需简单地添加另一个 `catchTag` 即可：

**示例**（使用 `catchTag` 处理多种错误类型）

```ts twoslash collapse={3-19} {28-30}
import { Effect, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = program.pipe(
  // 同时处理 HttpError 和 ValidationError
  Effect.catchTag("HttpError", (_HttpError) =>
    Effect.succeed("Recovering from HttpError")
  ),
  Effect.catchTag("ValidationError", (_ValidationError) =>
    Effect.succeed("Recovering from ValidationError")
  )
)
```

我们可以观察到，程序错误通道中的类型已经变为了 `never`：

```ts showLineNumbers=false
const recovered: Effect<string, never, never>
```

这表明所有错误都已得到处理。

---
**错误类型要求**
>要使用 `catchTag`，错误类型必须包含一个只读的 `_tag` 字段。该字段用于识别和匹配错误。
---
有时，你可能需要用自定义实现替换默认服务。Effect 提供了内置工具，通过使用 `Effect.with<service>` 和 `Effect.with<service>Scoped` 来覆盖这些服务。

### catchTags

使用错误的 `_tag` 字段在单个代码块中处理多个错误。

`Effect.catchTags` 是一种一次性处理多种错误类型的便捷方式。无需多次使用 `Effect.catchTag`，你可以传递一个对象，其中每个键（key）是错误类型的 `_tag`，而对应的值（value）是该特定错误的处理程序。这使你能够通过单次调用捕获多种错误类型并从中恢复。

**示例**（同时处理多种带有标签的错误类型）

```ts twoslash
import { Effect, Random, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

class ValidationError extends Data.TaggedError("ValidationError")<{}> {}

//      ┌─── Effect<string, HttpError | ValidationError, never>
//      ▼
const program = Effect.gen(function* () {
  const n1 = yield* Random.next
  const n2 = yield* Random.next
  if (n1 < 0.5) {
    return yield* Effect.fail(new HttpError())
  }
  if (n2 < 0.5) {
    return yield* Effect.fail(new ValidationError())
  }
  return "some result"
})

//      ┌─── Effect<string, never, never>
//      ▼
const recovered = program.pipe(
  Effect.catchTags({
    HttpError: (_HttpError) =>
      Effect.succeed(`Recovering from HttpError`),
    ValidationError: (_ValidationError) =>
      Effect.succeed(`Recovering from ValidationError`)
  })
)
```

该函数接受一个对象，其中每个属性代表一个特定的错误 `_tag`（在本例中为 `"HttpError"` 和 `"ValidationError"`），对应的值是当该特定错误发生时要执行的错误处理函数。

---
**错误类型要求**
>错误类型必须具有一个只读的 `_tag` 字段才能使用 `catchTag`。该字段用于识别和匹配错误。

## Effect.fn

`Effect.fn` 函数允许你创建返回 Effect 的追踪函数（traced functions）。它提供了两个关键特性：

- 如果发生错误，提供包含位置详情的**堆栈追踪（Stack traces）**。
- 当提供了 span 名称时，为[追踪（tracing）](/docs/observability/tracing/)**自动创建 span**。

如果第一个参数传入了 span 名称，则会使用该名称跟踪函数的执行。如果没有提供名称，堆栈追踪仍然有效，但不会创建 span。

可以通过以下任一方式定义函数：

- 生成器函数（generator function），允许使用 `yield*` 进行 Effect 组合。
- 返回 `Effect` 的普通函数。

**示例**（创建带有 Span 名称的追踪函数）

```ts twoslash
import { Effect } from "effect"

const myfunc = Effect.fn("myspan")(function* <N extends number>(n: N) {
  yield* Effect.annotateCurrentSpan("n", n) // 为 span 附加元数据
  console.log(`got: ${n}`)
  yield* Effect.fail(new Error("Boom!")) // 模拟失败
})

Effect.runFork(myfunc(100).pipe(Effect.catchAllCause(Effect.logError)))
/*
输出：
got: 100
timestamp=... level=ERROR fiber=#0 cause="Error: Boom!
    at <anonymous> (/.../index.ts:6:22) <= 抛出位置 (Raise location)
    at myspan (/.../index.ts:3:23)  <= 定义位置 (Definition location)
    at myspan (/.../index.ts:9:16)" <= 调用位置 (Call location)
*/
```

### 导出追踪 Span

`Effect.fn` 会自动创建 [span](/docs/observability/tracing/)。这些 span 记录了关于函数执行的信息，包括元数据和错误详情。

**示例**（将 Span 导出到控制台）

```ts twoslash
import { Effect } from "effect"
import { NodeSdk } from "@effect/opentelemetry"
import {
  ConsoleSpanExporter,
  BatchSpanProcessor
} from "@opentelemetry/sdk-trace-base"

const myfunc = Effect.fn("myspan")(function* <N extends number>(n: N) {
  yield* Effect.annotateCurrentSpan("n", n)
  console.log(`got: ${n}`)
  yield* Effect.fail(new Error("Boom!"))
})

const program = myfunc(100)

const NodeSdkLive = NodeSdk.layer(() => ({
  resource: { serviceName: "example" },
  // 将 span 数据导出到控制台
  spanProcessor: new BatchSpanProcessor(new ConsoleSpanExporter())
}))

Effect.runFork(program.pipe(Effect.provide(NodeSdkLive)))
/*
输出：
got: 100
{
  ...
  name: 'myspan',
  ...
  attributes: {
    n: 100,
    'code.stacktrace': 'at <anonymous> (/.../index.ts:8:23)\n' +
      'at <anonymous> (/.../index.ts:14:17)'
  },
  status: { code: 2, message: 'Boom!' },
  ...
}
*/
```

### 将 Effect.fn 作为管道（pipe）函数使用

`Effect.fn` 还可以充当管道函数，允许你在函数定义之后，使用生成器函数返回的 Effect 作为管道的起始值来创建一个流水线。

**示例**（创建带有延迟的追踪函数）

```ts twoslash
import { Effect } from "effect"

const myfunc = Effect.fn(
  function* (n: number) {
    console.log(`got: ${n}`)
    yield* Effect.fail(new Error("Boom!"))
  },
  // 你可以同时访问创建出的 effect 和原始参数
  (effect, n) => Effect.delay(effect, `${n / 100} seconds`)
)

Effect.runFork(myfunc(100).pipe(Effect.catchAllCause(Effect.logError)))
/*
输出：
got: 100
timestamp=... level=ERROR fiber=#0 cause="Error: Boom! (<= 1 秒后)
*/
```
