本页介绍了在 Effect 库中处理失败和创建后备（fallback）机制的各种技术。

## orElse

`Effect.orElse` 允许你尝试运行一个 Effect，如果它失败了，你可以提供一个后备 Effect 来替代运行。

这对于优雅地处理失败非常有用，通过定义一个当第一个 Effect 遇到错误时执行的备选 Effect。

**示例**（使用 `Effect.orElse` 处理后备方案）

```ts
import { Effect } from "effect"

const success = Effect.succeed("success")
const failure = Effect.fail("failure")
const fallback = Effect.succeed("fallback")

// 首先尝试成功的 Effect，不使用后备方案
const program1 = Effect.orElse(success, () => fallback)
console.log(Effect.runSync(program1))
// 输出: "success"

// 首先尝试失败的 Effect，使用后备方案
const program2 = Effect.orElse(failure, () => fallback)
console.log(Effect.runSync(program2))
// 输出: "fallback"
```

## orElseFail

`Effect.orElseFail` 允许你将一个 Effect 的失败替换为自定义的失败值。如果该 Effect 失败，你可以提供一个新的失败值来代替原始值返回。

此函数仅适用于失败的 Effect。如果 Effect 成功，它将保持不变。

**示例**（使用 `Effect.orElseFail` 替换失败值）

```ts twoslash
import { Effect } from "effect"

const validate = (age: number): Effect.Effect<number, string> => {
  if (age < 0) {
    return Effect.fail("NegativeAgeError")
  } else if (age < 18) {
    return Effect.fail("IllegalAgeError")
  } else {
    return Effect.succeed(age)
  }
}

const program = Effect.orElseFail(validate(-1), () => "invalid age")

console.log(Effect.runSyncExit(program))
/*
输出:
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: { _id: 'Cause', _tag: 'Fail', failure: 'invalid age' }
}
*/
```

## orElseSucceed

`Effect.orElseSucceed` 允许你将 Effect 的失败替换为一个成功值。如果 Effect 失败，它将改为以提供的值成功运行，从而确保该 Effect 始终成功完成。

当你想要保证无论原始 Effect 是否失败都能得到一个成功结果时，这非常有用。

该函数确保任何失败都会被有效地“吞掉”并替换为一个成功值，这在需要为失败情况提供默认值时很有帮助。

此函数仅适用于失败的 Effect。如果 Effect 已经成功，它将保持不变。

**示例**（使用 `Effect.orElseSucceed` 将失败替换为成功）

```ts twoslash
import { Effect } from "effect"

const validate = (age: number): Effect.Effect<number, string> => {
  if (age < 0) {
    return Effect.fail("NegativeAgeError")
  } else if (age < 18) {
    return Effect.fail("IllegalAgeError")
  } else {
    return Effect.succeed(age)
  }
}

const program = Effect.orElseSucceed(validate(-1), () => 18)

console.log(Effect.runSyncExit(program))
/*
输出:
{ _id: 'Exit', _tag: 'Success', value: 18 }
*/
```

## firstSuccessOf

`Effect.firstSuccessOf` 允许你按顺序尝试多个 Effect，一旦其中一个成功，它就会返回该结果。如果所有 Effect 都失败，它将返回列表中最后一个 Effect 的错误。

当你拥有多个潜在的备选方案，并且想要使用第一个可行的方案时，这非常有用。

此函数是**顺序执行**的，这意味着可迭代对象（iterable）中的 Effect 值将按顺序执行，第一个成功的 Effect 将决定最终结果。

---
**空集合错误**
> 如果提供给 `Effect.firstSuccessOf` 函数的集合为空，它将抛出 `IllegalArgumentException` 错误。
---

**示例**（通过后备方案寻找配置）

在这个示例中，我们尝试从不同的节点获取配置。如果主节点失败，我们会回退到其他节点，直到找到成功的配置。

```ts twoslash
import { Effect, Console } from "effect"

interface Config {
  host: string
  port: number
  apiKey: string
}

// 创建一个带有示例值的配置对象
const makeConfig = (name: string): Config => ({
  host: `${name}.example.com`,
  port: 8080,
  apiKey: "12345-abcde"
})

// 模拟从远程节点检索配置
const remoteConfig = (name: string): Effect.Effect<Config, Error> =>
  Effect.gen(function* () {
    // 模拟只有 node3 拥有可用配置
    if (name === "node3") {
      yield* Console.log(`找到 ${name} 的配置`)
      return makeConfig(name)
    } else {
      yield* Console.log(`${name} 的配置不可用`)
      return yield* Effect.fail(new Error(`找不到 ${name} 的配置`))
    }
  })

// 定义主配置和潜在的后备节点
const masterConfig = remoteConfig("master")
const nodeConfigs = ["node1", "node2", "node3", "node4"].map(remoteConfig)

// 尝试寻找一个可用的配置，
// 从 master 开始，然后回退到其他节点
const config = Effect.firstSuccessOf([masterConfig, ...nodeConfigs])

// 运行 Effect 以检索配置
const result = Effect.runSync(config)

console.log(result)
/*
输出:
master 的配置不可用
node1 的配置不可用
node2 的配置不可用
找到 node3 的配置
{ host: 'node3.example.com', port: 8080, apiKey: '12345-abcde' }
*/
```
