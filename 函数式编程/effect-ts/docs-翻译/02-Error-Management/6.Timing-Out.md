在编程中，处理需要一段时间才能完成的任务是很常见的。通常，我们希望对等待这些任务的时间设定一个上限。`Effect.timeout` 函数可以为操作添加时间约束，确保它不会无限期地运行。

## 基本用法

### timeout

`Effect.timeout` 函数接收一个 [Duration](/docs/data-types/duration/) 参数来建立操作的时间限制。如果操作超过此限制，将触发一个 `TimeoutException`，表明发生了超时。

**示例**（设置超时）

在下例中，任务在超时时限内完成，因此结果被成功返回。

```ts twoslash
import { Effect } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds") // 模拟处理延迟
  console.log("处理完成。")
  return "结果"
})

// 为任务设置 3 秒超时
const timedEffect = task.pipe(Effect.timeout("3 seconds"))

// 输出将显示任务成功完成，因为它在超时时限内
Effect.runPromiseExit(timedEffect).then(console.log)
/*
输出:
开始处理...
处理完成。
{ _id: 'Exit', _tag: 'Success', value: 'Result' }
*/
```

如果操作超过了指定的时长，则会抛出 `TimeoutException`：

```ts twoslash
import { Effect } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds") // 模拟处理延迟
  console.log("处理完成。")
  return "结果"
})

// 输出将显示 TimeoutException，因为任务耗时超过了指定的超时时长
const timedEffect = task.pipe(Effect.timeout("1 second"))

Effect.runPromiseExit(timedEffect).then(console.log)
/*
输出:
开始处理...
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Fail',
    failure: { _tag: 'TimeoutException' }
  }
}
*/
```

### timeoutOption

如果你想更优雅地处理超时，可以考虑使用 `Effect.timeoutOption`。该函数将超时视为一种常规结果，将产出值包装在 [Option](/docs/data-types/option/) 中。

**示例**（将超时作为 Option 处理）

在此示例中，第一个任务成功完成，而第二个任务超时。超时任务的结果在 `Option` 类型中表示为 `None`。

```ts twoslash
import { Effect } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds") // 模拟处理延迟
  console.log("处理完成。")
  return "结果"
})

const timedOutEffect = Effect.all([
  task.pipe(Effect.timeoutOption("3 seconds")),
  task.pipe(Effect.timeoutOption("1 second"))
])

Effect.runPromise(timedOutEffect).then(console.log)
/*
输出:
开始处理...
处理完成。
开始处理...
[
  { _id: 'Option', _tag: 'Some', value: 'Result' },
  { _id: 'Option', _tag: 'None' }
]
*/
```

## 超时处理机制

当操作未在指定时长内完成时，`Effect.timeout` 的行为取决于该操作是否为“不可中断”（uninterruptible）状态。

<Aside type="note" title="不可中断的 Effect">
  不可中断的 Effect 是指一旦开始，超时机制就无法直接在中途将其停止的 Effect。这通常是因为该 Effect 内部的操作必须运行到结束，以避免系统进入不一致的状态。
</Aside>

1.  **可中断操作**：如果操作是可以中断的，一旦达到超时阈值，它会立即终止，并产生一个 `TimeoutException`。

2.  **不可中断操作**：如果操作是不可中断的，它会继续运行直到完成，之后才会评估（并抛出）`TimeoutException`。

   ```ts twoslash
   import { Effect } from "effect"

   const task = Effect.gen(function* () {
     console.log("开始处理...")
     yield* Effect.sleep("2 seconds") // 模拟处理延迟
     console.log("处理完成。")
     return "结果"
   })

   const timedEffect = task.pipe(
     Effect.uninterruptible,
     Effect.timeout("1 second")
   )

   // 在任务完成后输出 TimeoutException，因为任务是不可中断的
   Effect.runPromiseExit(timedEffect).then(console.log)
   /*
    输出:
    开始处理...
    处理完成。
    {
      _id: 'Exit',
      _tag: 'Failure',
      cause: {
        _id: 'Cause',
        _tag: 'Fail',
        failure: { _tag: 'TimeoutException' }
      }
    }
    */
   ```

## 超时断开连接 (Disconnection)

`Effect.disconnect` 函数提供了一种更灵活的方式来处理不可中断 Effect 的超时。它允许不可中断的 Effect 在后台继续完成，而主控制流则立即像发生超时一样继续执行。

以下是区别：

**不使用** `Effect.disconnect`：
- 不可中断的 Effect 会忽略超时并继续执行直到完成，之后才会评估超时错误。
- 这会导致识别超时状态出现延迟，因为系统必须等待该 Effect 执行完毕。

**使用** `Effect.disconnect`：
- 不可中断的 Effect 被允许在后台继续运行，独立于主控制流。
- 主控制流会**立即**识别到超时，并携带超时错误或执行后续逻辑，而无需等待后台 Effect 完成。
- 当 Effect 的操作虽然被标记为不可中断，但其结果不再阻塞程序后续执行时，此方法特别有用。

**示例**（运行超时并在后台完成的不可中断任务）

假设启动了一个耗时的数据处理任务，你希望即使处理时间过长，系统也能保持响应：

```ts twoslash
import { Effect } from "effect"

const longRunningTask = Effect.gen(function* () {
  console.log("开始繁重处理...")
  yield* Effect.sleep("5 seconds") // 模拟耗时过程
  console.log("繁重处理完成。")
  return "数据已处理"
})

const timedEffect = longRunningTask.pipe(
  Effect.uninterruptible,
  // 如果发生超时，允许任务在后台完成
  Effect.disconnect,
  Effect.timeout("1 second")
)

Effect.runPromiseExit(timedEffect).then(console.log)
/*
输出:
开始繁重处理...
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Fail',
    failure: { _tag: 'TimeoutException' }
  }
}
繁重处理完成。
*/
```

在此示例中，系统在 1 秒后检测到超时，但耗时任务仍在后台继续执行并最终完成，而不会阻塞主程序的流动。

## 自定义超时行为

除了基础的 `Effect.timeout` 函数外，还有一些变体允许你自定义超时发生时的行为。

### timeoutFail

`Effect.timeoutFail` 函数允许你在发生超时时产生一个特定的错误。

**示例**（自定义超时错误）

```ts twoslash
import { Effect, Data } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds") 
  console.log("处理完成。")
  return "结果"
})

class MyTimeoutError extends Data.TaggedError("MyTimeoutError")<{}> {}

const program = task.pipe(
  Effect.timeoutFail({
    duration: "1 second",
    onTimeout: () => new MyTimeoutError() // 自定义超时错误
  })
)

Effect.runPromiseExit(program).then(console.log)
```

### timeoutFailCause

`Effect.timeoutFailCause` 允许你定义超时时抛出的特定 Cause（例如 Defect）。这对于将超时视为代码中的异常情况（Exceptional cases）非常有用。

**示例**（超时抛出自定义 Defect）

```ts twoslash
import { Effect, Cause } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds")
  console.log("处理完成。")
  return "结果"
})

const program = task.pipe(
  Effect.timeoutFailCause({
    duration: "1 second",
    onTimeout: () => Cause.die("超时了！") // 超时时的自定义 defect
  })
)

Effect.runPromiseExit(program).then(console.log)
```

### timeoutTo

相比 `Effect.timeout`，`Effect.timeoutTo` 提供了更大的灵活性，允许你为“成功”和“超时”两种情况定义不同的输出。当你需要根据操作是否按时完成来统一返回类型时，这非常有用。

**示例**（使用 [Either](/docs/data-types/either/) 处理成功与超时）

```ts twoslash
import { Effect, Either } from "effect"

const task = Effect.gen(function* () {
  console.log("开始处理...")
  yield* Effect.sleep("2 seconds")
  console.log("处理完成。")
  return "结果"
})

const program = task.pipe(
  Effect.timeoutTo({
    duration: "1 second",
    onSuccess: (result): Either.Either<string, string> =>
      Either.right(result),
    onTimeout: (): Either.Either<string, string> =>
      Either.left("超时了！")
  })
)

Effect.runPromise(program).then(console.log)
/*
输出:
开始处理...
{
  _id: "Either",
  _tag: "Left",
  left: "超时了！"
}
*/
```
