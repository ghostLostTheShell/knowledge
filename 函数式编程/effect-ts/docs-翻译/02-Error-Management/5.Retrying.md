在软件开发中，经常会遇到操作因各种因素（如网络问题、资源不可用或外部依赖）而暂时失败的情况。在这种情况下，通常希望自动重试该操作，使其最终能够成功。

重试是处理瞬时故障并确保关键操作成功执行的强大机制。在 Effect 中，通过内置函数和调度策略，重试变得简单且灵活。

在本指南中，我们将探索 Effect 中的重试概念，并学习如何使用 `retry` 和 `retryOrElse` 函数来处理失败场景。我们将了解如何使用调度（Schedules）来定义重试策略，这些策略决定了何时以及重试操作多少次。

无论你是在处理网络请求、数据库交互，还是任何其他可能出错的操作，掌握 Effect 的重试功能都能显著增强应用程序的弹性和可靠性。

## retry

`Effect.retry` 函数接收一个 Effect 和一个[调度 (Schedule)](/docs/scheduling/introduction/) 策略，如果该 Effect 失败，它将根据策略规则自动进行重试。

如果 Effect 最终成功，则返回结果。

如果达到最大重试次数后 Effect 仍然失败，则会传播该失败。

这在处理间歇性故障（如网络问题或临时资源不可用）时非常有用。通过定义重试策略，你可以控制重试次数、重试之间的延迟以及何时停止重试。

**示例**（以固定延迟重试）

```ts twoslash
import { Effect, Schedule } from "effect"

let count = 0

// 模拟一个可能失败的 Effect
const task = Effect.async<string, Error>((resume) => {
  if (count <= 2) {
    count++
    console.log("failure")
    resume(Effect.fail(new Error()))
  } else {
    console.log("success")
    resume(Effect.succeed("yay!"))
  }
})

// 定义一个在重试之间使用固定延迟的重复策略
const policy = Schedule.fixed("100 millis")

const repeated = Effect.retry(task, policy)

Effect.runPromise(repeated).then(console.log)
/*
输出：
failure
failure
failure
success
yay!
*/
```

### 立即重试 n 次

你也可以使用一种更简单的策略，将失败的 Effect 立即重试指定的次数：

**示例**（重试任务最多 5 次）

```ts twoslash
import { Effect } from "effect"

let count = 0

// 模拟一个可能失败的 Effect
const task = Effect.async<string, Error>((resume) => {
  if (count <= 2) {
    count++
    console.log("failure")
    resume(Effect.fail(new Error()))
  } else {
    console.log("success")
    resume(Effect.succeed("yay!"))
  }
})

// 重试任务最多 5 次
Effect.runPromise(Effect.retry(task, { times: 5 }))
/*
输出：
failure
failure
failure
success
*/
```

### 基于条件重试

你可以通过指定条件来自定义如何管理重试。使用 `until` 或 `while` 选项来控制何时停止重试。

**示例**（重试直到满足特定条件）

```ts twoslash
import { Effect } from "effect"

let count = 0

// 定义一个模拟每次调用产生不同错误的 Effect
const action = Effect.failSync(() => {
  console.log(`Action called ${++count} time(s)`)
  return `Error ${count}`
})

// 重试该操作，直到满足特定条件
const program = Effect.retry(action, {
  until: (err) => err === "Error 3"
})

Effect.runPromiseExit(program).then(console.log)
/*
输出：
Action called 1 time(s)
Action called 2 time(s)
Action called 3 time(s)
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: { _id: 'Cause', _tag: 'Fail', failure: 'Error 3' }
}
*/
```

<Aside type="tip" title="替代方案">
  如果你的重试条件是基于成功结果而不是错误，你也可以使用 [Effect.repeat](/docs/scheduling/repetition/#repeating-based-on-a-condition)。
</Aside>

## retryOrElse

`Effect.retryOrElse` 函数尝试根据定义的 [调度 (Schedule)](/docs/scheduling/introduction/) 策略多次重试失败的 Effect。

如果重试次数用尽且 Effect 仍然失败，它将运行一个回退（fallback）Effect。

当你想通过在多次失败后指定备选操作来优雅地处理故障时，此函数非常有用。

**示例**（带有回退机制的重试）

```ts twoslash
import { Effect, Schedule, Console } from "effect"

let count = 0

// 模拟一个可能失败的 Effect
const task = Effect.async<string, Error>((resume) => {
  if (count <= 2) {
    count++
    console.log("failure")
    resume(Effect.fail(new Error()))
  } else {
    console.log("success")
    resume(Effect.succeed("yay!"))
  }
})

// 重试任务，重试之间有延迟，且最多重试 2 次
const policy = Schedule.addDelay(Schedule.recurs(2), () => "100 millis")

// 如果所有重试都失败，则运行回退 Effect
const repeated = Effect.retryOrElse(
  task,
  policy,
  // fallback (回退)
  () => Console.log("orElse").pipe(Effect.as("default value"))
)

Effect.runPromise(repeated).then(console.log)
/*
输出：
failure
failure
failure
orElse
default value
*/
```
