在某些情况下，你可能会遇到非预期的错误，并且需要决定如何处理它们。Effect 提供了相应的函数来帮助你应对这些场景，让你能够在 Effect 执行过程中发生错误时采取适当的行动。

## 创建不可恢复的错误

就像可以利用 [Effect.fail](/docs/getting-started/creating-effects/#fail) 等算子来创建类型为 `Effect<never, E, never>` 的值一样，Effect 库也提供了创建 **缺陷 (Defects)** 的工具。

当遇到从业务逻辑角度无法恢复的错误时（例如：在多次重试后仍然连接被拒绝），创建缺陷通常是必要的。

在这些情况下，终止 Effect 的执行并通过输出（如 stdout 或外部监控服务）进行报告可能是最佳解决方案。

以下函数和算子允许终止 Effect，它们通常用于将 `Effect<A, E, R>` 类型的值转换为 `Effect<A, never, R>` 类型的值，从而为程序员提供一个“逃生口”，无需处理和恢复那些没有合理恢复方式的错误。

### die

创建一个由于指定错误而导致纤程（Fiber）终止的 Effect。

当你的代码遇到不应作为普通错误处理、而是代表不可恢复缺陷的非预期情况时，请使用 `Effect.die`。

`Effect.die` 函数用于发出缺陷信号，代表代码中严重的、非预期的错误。当被调用时，它会产生一个不处理该错误而是直接终止纤程的 Effect。

结果 Effect 的错误通道类型为 `never`，表明它无法从该故障中恢复。

**示例**（发生除零错误时使用指定错误终止）

```ts twoslash
import { Effect } from "effect"

const divide = (a: number, b: number) =>
  b === 0
    ? Effect.die(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)

//      ┌─── Effect<number, never, never>
//      ▼
const program = divide(1, 0)

Effect.runPromise(program).catch(console.error)
/*
输出：
(FiberFailure) Error: Cannot divide by zero
  ...堆栈追踪...
*/
```

### dieMessage

创建一个 Effect，使纤程以包含指定消息的 `RuntimeException` 终止。

当你希望由于不可恢复的缺陷而终止纤程，并在消息中包含清晰的解释时，请使用 `Effect.dieMessage`。

`Effect.dieMessage` 函数用于发出缺陷信号。调用时，它会产生一个 Effect，使纤程以携带给定消息的 `RuntimeException` 终止。

结果 Effect 的错误通道类型为 `never`，表明它不会处理或从该错误中恢复。

**示例**（发生除零错误时使用指定消息终止）

```ts twoslash
import { Effect } from "effect"

const divide = (a: number, b: number) =>
  b === 0
    ? Effect.dieMessage("Cannot divide by zero")
    : Effect.succeed(a / b)

//      ┌─── Effect<number, never, never>
//      ▼
const program = divide(1, 0)

Effect.runPromise(program).catch(console.error)
/*
输出：
(FiberFailure) RuntimeException: Cannot divide by zero
  ...堆栈追踪...
*/
```

## 将失败转换为缺陷

### orDie

将 Effect 的失败（Failure）转换为纤程终止（Termination），从而从 Effect 的类型中移除该错误。

当失败应被视为不可恢复的缺陷且不需要错误处理时，请使用 `Effect.orDie`。

当你遇到不想处理或恢复的错误时，可以使用 `Effect.orDie` 函数。它会从 Effect 中移除错误类型，并确保任何失败都会终止纤程。这对于将失败作为缺陷传播非常有用，表明它们不应在 Effect 内部被处理。

**示例**（将错误作为缺陷传播）

```ts twoslash
import { Effect } from "effect"

const divide = (a: number, b: number) =>
  b === 0
    ? Effect.fail(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)

//      ┌─── Effect<number, never, never>
//      ▼
const program = Effect.orDie(divide(1, 0))

Effect.runPromise(program).catch(console.error)
/*
输出：
(FiberFailure) Error: Cannot divide by zero
  ...堆栈追踪...
*/
```

### orDieWith

将 Effect 的失败转换为带有自定义错误的纤程终止。

当失败应当作为缺陷终止纤程，并且你希望为了清晰起见或调试目的自定义错误时，请使用 `Effect.orDieWith`。

`Effect.orDieWith` 函数的行为类似于 [Effect.orDie](#ordie)，但它允许你提供一个映射函数，在终止纤程之前对错误进行转换。当你希望在失败作为缺陷传播时包含更详细或更友好的错误信息，这会非常有用。

**示例**（自定义缺陷内容）

```ts twoslash
import { Effect } from "effect"

const divide = (a: number, b: number) =>
  b === 0
    ? Effect.fail(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)

//      ┌─── Effect<number, never, never>
//      ▼
const program = Effect.orDieWith(
  divide(1, 0),
  (error) => new Error(`defect: ${error.message}`)
)

Effect.runPromise(program).catch(console.error)
/*
输出：
(FiberFailure) Error: defect: Cannot divide by zero
  ...堆栈追踪...
*/
```

## 捕获所有缺陷

通常没有合理的办法从缺陷中恢复。接下来我们要讨论的函数应当仅用于 Effect 与外部系统的边界处，以便传输有关缺陷的信息用于诊断或解释目的。

### exit

`Effect.exit` 函数将 `Effect<A, E, R>` 转换为一个将潜在失败和成功都封装在 [Exit](/docs/data-types/exit/) 数据类型中的 Effect：

```ts showLineNumbers=false
Effect<A, E, R> -> Effect<Exit<A, E>, never, R>
```

这意味着如果你有如下类型的 Effect：

```ts showLineNumbers=false
Effect<string, HttpError, never>
```

对其调用 `Effect.exit` 后，类型变为：

```ts showLineNumbers=false
Effect<Exit<string, HttpError>, never, never>
```

生成的 Effect 不会失败，因为潜在的失败现在由 `Exit` 的 `Failure` 类型表示。返回的 Effect 的错误类型被指定为 `never`，确认了该 Effect 的结构是不可能失败的。

通过 yield 一个 `Exit`，我们获得了在生成器函数内对该类型进行“模式匹配”的能力，从而同时处理失败和成功的情况。

**示例**（使用 `Effect.exit` 捕获缺陷）

```ts twoslash
import { Effect, Cause, Console, Exit } from "effect"

// 模拟一个运行时错误
const task = Effect.dieMessage("Boom!")

const program = Effect.gen(function* () {
  const exit = yield* Effect.exit(task)
  if (Exit.isFailure(exit)) {
    const cause = exit.cause
    if (
      Cause.isDieType(cause) &&
      Cause.isRuntimeException(cause.defect)
    ) {
      yield* Console.log(
        `捕获到 RuntimeException 缺陷: ${cause.defect.message}`
      )
    } else {
      yield* Console.log("捕获到未知失败。")
    }
  }
})

// 我们得到一个 Exit.Success，因为我们捕获了所有错误
Effect.runPromiseExit(program).then(console.log)
/*
输出：
捕获到 RuntimeException 缺陷: Boom!
{
  _id: "Exit",
  _tag: "Success",
  value: undefined
}
*/
```

### catchAllDefect

使用提供的恢复函数从所有缺陷中恢复。

`Effect.catchAllDefect` 允许你处理缺陷（即通常会导致程序终止的非预期错误）。该函数通过提供一个处理错误的函数来让你从这些缺陷中恢复。

但是，它**不会**处理预期的错误（例如来自 [Effect.fail](/docs/getting-started/creating-effects/#fail) 的错误）或执行中断（例如来自 [Effect.interrupt](/docs/concurrency/basic-concurrency/#interrupt) 的中断）。

**示例**（处理所有缺陷）

```ts twoslash
import { Effect, Cause, Console } from "effect"

// 模拟一个运行时错误
const task = Effect.dieMessage("Boom!")

const program = Effect.catchAllDefect(task, (defect) => {
  if (Cause.isRuntimeException(defect)) {
    return Console.log(
      `捕获到 RuntimeException 缺陷: ${defect.message}`
    )
  }
  return Console.log("捕获到未知缺陷。")
})

// 我们得到一个 Exit.Success，因为捕获了所有缺陷
Effect.runPromiseExit(program).then(console.log)
/*
输出：
捕获到 RuntimeException 缺陷: Boom!
{
  _id: "Exit",
  _tag: "Success",
  value: undefined
}
*/
```
---
**何时从缺陷中恢复**
> 缺陷是非预期的错误，通常不应该被恢复，因为它们往往表明了严重的问题。然而在某些情况下，例如动态加载的插件，可能需要受控的恢复。

## 捕获部分缺陷

### catchSomeDefect

使用提供的偏函数从特定缺陷中恢复。

`Effect.catchSomeDefect` 允许你处理特定的缺陷。它使用一个偏函数（partial function）来仅捕获某些缺陷并忽略其他缺陷。

同样，它**不会**处理预期的错误或执行中断。

提供给 `Effect.catchSomeDefect` 的函数充当了缺陷的过滤器和处理程序：

- 它接收缺陷作为输入。
- 如果缺陷匹配特定条件（例如某种错误类型），该函数返回包含恢复逻辑的 `Option.some`。
- 如果缺陷不匹配，该函数返回 `Option.none`，允许该缺陷继续传播。

**示例**（处理特定缺陷）

```ts twoslash
import { Effect, Cause, Option, Console } from "effect"

// 模拟一个运行时错误
const task = Effect.dieMessage("Boom!")

const program = Effect.catchSomeDefect(task, (defect) => {
  if (Cause.isIllegalArgumentException(defect)) {
    return Option.some(
      Console.log(
        `捕获到 IllegalArgumentException 缺陷: ${defect.message}`
      )
    )
  }
  return Option.none()
})

// 由于我们只捕获 IllegalArgumentException，
// 而模拟的是运行时错误，所以我们会得到一个 Exit.Failure。
Effect.runPromiseExit(program).then(console.log)
/*
输出：
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Die',
    defect: { _tag: 'RuntimeException' }
  }
}
*/
```

---
**何时从缺陷中恢复**
> 缺陷是非预期的错误，通常不应该被恢复，因为它们往往表明了严重的问题。然而在某些情况下，例如动态加载的插件，可能需要受控的恢复。
