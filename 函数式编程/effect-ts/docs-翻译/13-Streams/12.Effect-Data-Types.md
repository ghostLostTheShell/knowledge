## 与 Data 的互操作

Effect 生态系统中的 [Data](/docs/data-types/data/) 模块通过自动实现 [Equal](/docs/trait/equal/) 和 [Hash](/docs/trait/hash/) 特性来简化值比较。这消除了手动实现的需要，使相等性检查变得简单直接。

**示例**（使用 Data 比较结构体）

```ts twoslash
import { Data, Equal } from "effect"

const person1 = Data.struct({ name: "Alice", age: 30 })
const person2 = Data.struct({ name: "Alice", age: 30 })

console.log(Equal.equals(person1, person2))
// 输出: true
```

默认情况下，像 `Schema.Struct` 这样的模式不实现 `Equal` 和 `Hash` 特性。这意味着两个具有相同值的解码对象不会被视作相等。

**示例**（没有 `Equal` 和 `Hash` 时的默认行为）

```ts twoslash
import { Schema } from "effect"
import { Equal } from "effect"

const schema = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

const decode = Schema.decode(schema)

const person1 = decode({ name: "Alice", age: 30 })
const person2 = decode({ name: "Alice", age: 30 })

console.log(Equal.equals(person1, person2))
// 输出: false
```

`Schema.Data` 函数可用于增强模式，使其包含 `Equal` 和 `Hash` 特性。这使结果对象能够支持基于值的相等性。

**示例**（使用 `Schema.Data` 添加相等性）

```ts twoslash
import { Schema } from "effect"
import { Equal } from "effect"

const schema = Schema.Data(
  Schema.Struct({
    name: Schema.String,
    age: Schema.Number
  })
)

const decode = Schema.decode(schema)

const person1 = decode({ name: "Alice", age: 30 })
const person2 = decode({ name: "Alice", age: 30 })

console.log(Equal.equals(person1, person2))
// 输出: true
```

## Config

`Schema.Config` 函数允许您使用结构化模式解码和管理应用程序配置设置。它确保配置数据的一致性，并为解码错误提供详细的反馈。

**语法**

```ts showLineNumbers=false
Config: <A, I extends string>(name: string, schema: Schema<A, I>) =>
  Config<A>
```

此函数接受两个参数：

- `name`：配置设置的标识符。
- `schema`：描述预期数据类型和结构的模式。

它返回一个与应用程序配置系统集成的 [Config](/docs/configuration/) 对象。

编码类型 `I` 必须扩展 `string`，因此模式必须能够从字符串解码，这包括像 `Schema.String`、`Schema.Literal("...")` 或 `Schema.NumberFromString` 这样的模式，可能还应用了精炼。

在幕后，`Schema.Config` 遵循以下步骤：

1.  **使用提供的名称获取值**（例如从环境变量中获取）。
2.  **使用给定的模式解码该值**。如果值无效，解码失败。
3.  **使用 [TreeFormatter.formatErrorSync](/docs/schema/error-formatters/#treeformatter-default) 格式化任何错误**，这有助于生成可读且详细的错误消息。

**示例**（解码配置值）

```ts twoslash filename="config.ts"
import { Effect, Schema } from "effect"

// 定义一个期望至少包含 4 个字符的字符串的配置
const myConfig = Schema.Config(
  "Foo",
  Schema.String.pipe(Schema.minLength(4))
)

const program = Effect.gen(function* () {
  const foo = yield* myConfig
  console.log(`ok: ${foo}`)
})

Effect.runSync(program)
```

要测试配置，请执行以下命令：

**测试**（缺少配置数据）

```sh showLineNumbers=false
npx tsx config.ts
# 输出:
# [(Missing data at Foo: "Expected Foo to exist in the process context")]
```

**测试**（数据无效）

```sh showLineNumbers=false
Foo=bar npx tsx config.ts
# 输出:
# [(Invalid data at Foo: "a string at least 4 character(s) long
# └─ Predicate refinement failure
#    └─ Expected a string at least 4 character(s) long, actual "bar"")]
```

**测试**（数据有效）

```sh showLineNumbers=false
Foo=foobar npx tsx config.ts
# 输出:
# ok: foobar
```

## Option

### Option

`Schema.Option` 函数对于将 `Option` 转换为 JSON 可序列化格式非常有用。

**语法**

```ts showLineNumbers=false
Schema.Option(schema: Schema<A, I, R>)
```

##### 解码

| 输入                        | 输出                                                                              |
| --------------------------- | --------------------------------------------------------------------------------- |
| `{ _tag: "None" }`          | 转换为 `Option.none()`                                                            |
| `{ _tag: "Some", value: I }` | 转换为 `Option.some(a)`，其中 `I` 使用内部模式解码为 `A`                           |

##### 编码

| 输入            | 输出                                                                                          |
| --------------- | --------------------------------------------------------------------------------------------- |
| `Option.none()` | 转换为 `{ _tag: "None" }`                                                                     |
| `Option.some(A)` | 转换为 `{ _tag: "Some", value: I }`，其中 `A` 使用内部模式编码为 `I`                           |

**示例**

```ts twoslash
import { Schema } from "effect"
import { Option } from "effect"

const schema = Schema.Option(Schema.NumberFromString)

//     ┌─── OptionEncoded<string>
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── Option<number>
//     ▼
type Type = typeof schema.Type

const decode = Schema.decodeUnknownSync(schema)
const encode = Schema.encodeSync(schema)

// 解码示例

console.log(decode({ _tag: "None" }))
// 输出: { _id: 'Option', _tag: 'None' }

console.log(decode({ _tag: "Some", value: "1" }))
// 输出: { _id: 'Option', _tag: 'Some', value: 1 }

// 编码示例

console.log(encode(Option.none()))
// 输出: { _tag: 'None' }

console.log(encode(Option.some(1)))
// 输出: { _tag: 'Some', value: '1' }
```

### OptionFromNullishOr

`Schema.OptionFromNullishOr` 函数处理 `null` 或 `undefined` 被视为 `Option.none()` 的情况，而所有其他值根据提供的模式被解释为 `Option.some()`。此外，它允许自定义 `Option.none()` 的编码方式（`null` 或 `undefined`）。

**语法**

```ts showLineNumbers=false
Schema.OptionFromNullishOr(
  schema: Schema<A, I, R>,
  onNoneEncoding: null | undefined
)
```

#### 解码

| 输入       | 输出                                                                              |
| ---------- | --------------------------------------------------------------------------------- |
| `undefined` | 转换为 `Option.none()`                                                            |
| `null`     | 转换为 `Option.none()`                                                            |
| `I`        | 转换为 `Option.some(A)`，其中 `I` 使用内部模式解码为 `A`                           |

#### 编码

| 输入            | 输出                                                                     |
| --------------- | ------------------------------------------------------------------------ |
| `Option.none()` | 根据用户选择（`onNoneEncoding`）转换为 `undefined` 或 `null`              |
| `Option.some(A)` | 转换为 `I`，其中 `A` 使用内部模式编码为 `I`                               |

**示例**

```ts twoslash
import { Schema } from "effect"
import { Option } from "effect"

const schema = Schema.OptionFromNullishOr(
  Schema.NumberFromString,
  undefined // 将 Option.none() 编码为 undefined
)

//     ┌─── string | null | undefined
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── Option<number>
//     ▼
type Type = typeof schema.Type

const decode = Schema.decodeUnknownSync(schema)
const encode = Schema.encodeSync(schema)

// 解码示例

console.log(decode(null))
// 输出: { _id: 'Option', _tag: 'None' }

console.log(decode(undefined))
// 输出: { _id: 'Option', _tag: 'None' }

console.log(decode("1"))
// 输出: { _id: 'Option', _tag: 'Some', value: 1 }

// 编码示例

console.log(encode(Option.none()))
// 输出: undefined

console.log(encode(Option.some(1)))
// 输出: "1"
```

### OptionFromNonEmptyTrimmedString

`Schema.OptionFromNonEmptyTrimmedString` 模式旨在处理字符串，其中修剪后的空字符串被视为 `Option.none()`，所有其他字符串被转换为 `Option.some()`。

#### 解码

| 输入       | 输出                                                  |
| ---------- | ----------------------------------------------------- |
| `s: string` | 如果 `s.trim().length > 0`，则转换为 `Option.some(s)` |
|            | 否则转换为 `Option.none()`                            |

#### 编码

| 输入                    | 输出            |
| ----------------------- | --------------- |
| `Option.none()`         | 转换为 `""`     |
| `Option.some(s: string)` | 转换为 `s`      |

**示例**

```ts twoslash
import { Schema, Option } from "effect"

//     ┌─── string
//     ▼
type Encoded = typeof Schema.OptionFromNonEmptyTrimmedString

//     ┌─── Option<string>
//     ▼
type Type = typeof Schema.OptionFromNonEmptyTrimmedString

const decode = Schema.decodeUnknownSync(
  Schema.OptionFromNonEmptyTrimmedString
)
const encode = Schema.encodeSync(Schema.OptionFromNonEmptyTrimmedString)

// 解码示例

console.log(decode(""))
// 输出: { _id: 'Option', _tag: 'None' }

console.log(decode(" a "))
// 输出: { _id: 'Option', _tag: 'Some', value: 'a' }

console.log(decode("a"))
// 输出: { _id: 'Option', _tag: 'Some', value: 'a' }

// 编码示例

console.log(encode(Option.none()))
// 输出: ""

console.log(encode(Option.some("example")))
// 输出: "example"
```

## Either

### Either

`Schema.Either` 函数对于将 `Either` 转换为 JSON 可序列化格式非常有用。

**语法**

```ts showLineNumbers=false
Schema.Either(options: {
  left: Schema<LA, LI, LR>,
  right: Schema<RA, RI, RR>
})
```

##### 解码

| 输入                          | 输出                                                                                          |
| ----------------------------- | --------------------------------------------------------------------------------------------- |
| `{ _tag: "Left", left: LI }`   | 转换为 `Either.left(LA)`，其中 `LI` 使用内部 `left` 模式解码为 `LA`                           |
| `{ _tag: "Right", right: RI }` | 转换为 `Either.right(RA)`，其中 `RI` 使用内部 `right` 模式解码为 `RA`                         |

##### 编码

| 输入              | 输出                                                                                                      |
| ----------------- | --------------------------------------------------------------------------------------------------------- |
| `Either.left(LA)`  | 转换为 `{ _tag: "Left", left: LI }`，其中 `LA` 使用内部 `left` 模式编码为 `LI`                            |
| `Either.right(RA)` | 转换为 `{ _tag: "Right", right: RI }`，其中 `RA` 使用内部 `right` 模式编码为 `RI`                         |

**示例**

```ts twoslash
import { Schema, Either } from "effect"

const schema = Schema.Either({
  left: Schema.Trim,
  right: Schema.NumberFromString
})

//     ┌─── EitherEncoded<string, string>
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── Either<number, string>
//     ▼
type Type = typeof schema.Type

const decode = Schema.decodeUnknownSync(schema)
const encode = Schema.encodeSync(schema)

// 解码示例

console.log(decode({ _tag: "Left", left: " a " }))
// 输出: { _id: 'Either', _tag: 'Left', left: 'a' }

console.log(decode({ _tag: "Right", right: "1" }))
// 输出: { _id: 'Either', _tag: 'Right', right: 1 }

// 编码示例

console.log(encode(Either.left("a")))
// 输出: { _tag: 'Left', left: 'a' }

console.log(encode(Either.right(1)))
// 输出: { _tag: 'Right', right: '1' }
```

## Exit

### Exit

`Schema.Exit` 函数对于将 `Exit` 转换为 JSON 可序列化格式非常有用。

**语法**

```ts showLineNumbers=false
Schema.Exit(options: {
  failure: Schema<FA, FI, FR>,
  success: Schema<SA, SI, SR>,
  defect: Schema<DA, DI, DR>
})
```

##### 解码

| 输入                                              | 输出                                                                                                                                            |
| ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `{ _tag: "Failure", cause: CauseEncoded<FI, DI> }` | 转换为 `Exit.failCause(Cause<FA>)`，其中 `CauseEncoded<FI, DI>` 使用内部 `failure` 和 `defect` 模式解码为 `Cause<FA>`                           |
| `{ _tag: "Success", value: SI }`                   | 转换为 `Exit.succeed(SA)`，其中 `SI` 使用内部 `success` 模式解码为 `SA`                                                                         |

##### 编码

| 输入                       | 输出                                                                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `Exit.failCause(Cause<FA>)` | 转换为 `{ _tag: "Failure", cause: CauseEncoded<FI, DI> }`，其中 `Cause<FA>` 使用内部 `failure` 和 `defect` 模式编码为 `CauseEncoded<FI, DI>`                           |
| `Exit.succeed(SA)`          | 转换为 `{ _tag: "Success", value: SI }`，其中 `SA` 使用内部 `success` 模式编码为 `SI`                                                                                  |

**示例**

```ts twoslash
import { Schema, Exit } from "effect"

const schema = Schema.Exit({
  failure: Schema.String,
  success: Schema.NumberFromString,
  defect: Schema.String
})

//     ┌─── ExitEncoded<string, string, string>
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── Exit<number, string>
//     ▼
type Type = typeof schema.Type

const decode = Schema.decodeUnknownSync(schema)
const encode = Schema.encodeSync(schema)

// 解码示例

console.log(
  decode({ _tag: "Failure", cause: { _tag: "Fail", error: "a" } })
)
/*
输出:
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: { _id: 'Cause', _tag: 'Fail', failure: 'a' }
}
*/

console.log(decode({ _tag: "Success", value: "1" }))
/*
输出:
{ _id: 'Exit', _tag: 'Success', value: 1 }
*/

// 编码示例

console.log(encode(Exit.fail("a")))
/*
输出:
```

### 处理序列化中的缺陷

Effect 提供了一个内置的 `Defect` 模式，用于处理 JavaScript 错误（`Error` 实例）和其他类型的不可恢复缺陷。

- 解码时，如果输入具有 `message` 以及可选的 `name` 和 `stack`，它会重构 `Error` 实例。
- 编码时，它将 `Error` 实例转换为仅保留基本属性的普通对象。

这在通过网络请求传输错误或通过日志系统传输错误时非常有用，因为 `Error` 对象默认不会序列化。

**示例**（编码和解码缺陷）

```ts twoslash
import { Schema, Exit } from "effect"

const schema = Schema.Exit({
  failure: Schema.String,
  success: Schema.NumberFromString,
  defect: Schema.Defect
})

const decode = Schema.decodeSync(schema)
const encode = Schema.encodeSync(schema)

console.log(encode(Exit.die(new Error("Message"))))
/*
输出:
{
  _tag: 'Failure',
  cause: { _tag: 'Die', defect: { name: 'Error', message: 'Message' } }
}
*/

console.log(encode(Exit.fail("a")))

console.log(
  decode({
    _tag: "Failure",
    cause: { _tag: "Die", defect: { name: "Error", message: "Message" } }
  })
)
/*
输出:
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Die',
    defect: [Error: Message] { [cause]: [Object] }
  }
}
*/
```

## Redacted

### Redacted

`Schema.Redacted` 函数专门设计用于通过将 `string` 转换为 [Redacted](/docs/data-types/redacted/) 对象来处理敏感信息。这种转换确保敏感数据不会暴露在应用程序的输出中。

**示例**（基本 Redacted 模式）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Redacted(Schema.String)

//     ┌─── string
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── Redacted<string>
//     ▼
type Type = typeof schema.Type

const decode = Schema.decodeUnknownSync(schema)

// 解码示例

console.log(decode("keep it secret, keep it safe"))
// 输出: <redacted>
```

需要注意的是，当成功解码 `Redacted` 时，输出会故意被遮蔽（`<redacted>`），以防止实际的秘密在日志或控制台输出中被暴露。

<Aside type="caution" title="潜在风险">
  当将 `Redacted` 模式与其他模式组合时，必须小心，因为解码或编码错误可能会潜在地暴露敏感信息。
</Aside>

**示例**（错误期间的暴露风险）

在下面的示例中，如果输入字符串不符合标准（例如，包含空格），生成的错误消息可能会无意中暴露输入中包含的敏感信息。

```ts twoslash
import { Schema } from "effect"
import { Redacted } from "effect"

const schema = Schema.Trimmed.pipe(
  Schema.compose(Schema.Redacted(Schema.String))
)

console.log(Schema.decodeUnknownEither(schema)(" SECRET"))
/*
{
  _id: 'Either',
  _tag: 'Left',
  left: {
    _id: 'ParseError',
    message: '(Trimmed <-> (string <-> Redacted(<redacted>)))\n' +
      '└─ Encoded side transformation failure\n' +
      '   └─ Trimmed\n' +
      '      └─ Predicate refinement failure\n' +
      '         └─ Expected Trimmed (a string with no leading or trailing whitespace), actual " SECRET"'
  }
}
*/

console.log(Schema.encodeEither(schema)(Redacted.make(" SECRET")))
/*
{
  _id: 'Either',
  _tag: 'Left',
  left: {
    _id: 'ParseError',
    message: '(Trimmed <-> (string <-> Redacted(<redacted>)))\n' +
      '└─ Encoded side transformation failure\n' +
      '   └─ Trimmed\n' +
      '      └─ Predicate refinement failure\n' +
      '         └─ Expected Trimmed (a string with no leading or trailing whitespace), actual " SECRET"'
  }
}
*/
```

#### 降低暴露风险

为了降低错误消息中敏感信息泄露的风险，您可以自定义错误消息以遮蔽敏感细节：

**示例**（自定义错误消息）

```ts twoslash
import { Schema } from "effect"
import { Redacted } from "effect"

const schema = Schema.Trimmed.annotations({
  message: () => "Expected Trimmed, actual <redacted>"
}).pipe(Schema.compose(Schema.Redacted(Schema.String)))

console.log(Schema.decodeUnknownEither(schema)(" SECRET"))
/*
{
  _id: 'Either',
  _tag: 'Left',
  left: {
    _id: 'ParseError',
    message: '(Trimmed <-> (string <-> Redacted(<redacted>)))\n' +
      '└─ Encoded side transformation failure\n' +
      '   └─ Expected Trimmed, actual <redacted>'
  }
}
*/

console.log(Schema.encodeEither(schema)(Redacted.make(" SECRET")))
/*
{
  _id: 'Either',
  _tag: 'Left',
  left: {
    _id: 'ParseError',
    message: '(Trimmed <-> (string <-> Redacted(<redacted>)))\n' +
      '└─ Encoded side transformation failure\n' +
      '   └─ Expected Trimmed, actual <redacted>'
  }
}
*/
```
