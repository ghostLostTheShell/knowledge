转换在处理模式时非常重要。它们允许你将数据从一种类型更改为另一种类型。例如，你可能需要将字符串解析为数字，或将日期字符串转换为 `Date` 对象。

[Schema.transform](#transform) 和 [Schema.transformOrFail](#transformorfail) 函数帮助你将两个模式连接起来，以便在它们之间转换数据。

## transform

`Schema.transform` 通过将一个模式（"源"）的输出作为另一个模式（"目标"）的输入来创建一个新的模式。当你确信转换总是成功时使用此函数。如果转换可能失败，应使用 [Schema.transformOrFail](#transformorfail)。

### 理解输入和输出

"输出"和"输入"取决于你在做什么（解码或编码）：

**解码时：**

- 源模式 `Schema<SourceType, SourceEncoded>` 产生一个 `SourceType`。
- 目标模式 `Schema<TargetType, TargetEncoded>` 期望一个 `TargetEncoded`。
- 解码路径如下：`SourceEncoded` → `TargetType`。

如果 `SourceType` 和 `TargetEncoded` 不同，你可以提供一个 `decode` 函数来将源模式的输出转换为目标模式的输入。

**编码时：**

- 目标模式 `Schema<TargetType, TargetEncoded>` 产生一个 `TargetEncoded`。
- 源模式 `Schema<SourceType, SourceEncoded>` 期望一个 `SourceType`。
- 编码路径如下：`TargetType` → `SourceEncoded`。

如果 `TargetEncoded` 和 `SourceType` 不同，你可以提供一个 `encode` 函数来将目标模式的输出转换为源模式的输入。

### 组合两个原始模式

在此示例中，我们从接受 `"on"` 或 `"off"` 的模式开始，并将其转换为布尔模式。`decode` 函数将 `"on"` 转换为 `true`，将 `"off"` 转换为 `false`。`encode` 函数执行相反的操作。这为我们提供了一个 `Schema<boolean, "on" | "off">`。

**示例**（将字符串转换为布尔值）

```ts twoslash
import { Schema } from "effect"

// 将 "on"/"off" 转换为布尔值并反向转换
const BooleanFromString = Schema.transform(
  // 源模式："on" 或 "off"
  Schema.Literal("on", "off"),
  // 目标模式：布尔值
  Schema.Boolean,
  {
    // 可选，但可以从 TypeScript 获得更好的错误消息
    strict: true,
    // 转换：将源模式的输出 ("on" | "off") 转换为目标模式的输入（布尔值）
    decode: (literal) => literal === "on", // 这里总是成功
    // 反向转换
    encode: (bool) => (bool ? "on" : "off")
  }
)

//     ┌─── "on" | "off"
//     ▼
type Encoded = typeof BooleanFromString.Encoded

//     ┌─── boolean
//     ▼
type Type = typeof BooleanFromString.Type

console.log(Schema.decodeUnknownSync(BooleanFromString)("on"))
// 输出: true
```

上面的 `decode` 函数本身永远不会失败。然而，如果输入不符合源模式，完整的解码过程仍然可能失败。例如，如果你提供 `"wrong"` 而不是 `"on"` 或 `"off"`，源模式将在调用 `decode` 之前失败。

**示例**（处理无效输入）

```ts twoslash collapse={4-12}
import { Schema } from "effect"

// 将 "on"/"off" 转换为布尔值并反向转换
const BooleanFromString = Schema.transform(
  Schema.Literal("on", "off"),
  Schema.Boolean,
  {
    strict: true,
    decode: (s) => s === "on",
    encode: (bool) => (bool ? "on" : "off")
  }
)

// 提供源模式不允许的输入
Schema.decodeUnknownSync(BooleanFromString)("wrong")
/*
抛出:
ParseError: ("on" | "off" <-> boolean)
└─ Encoded side transformation failure
   └─ "on" | "off"
      ├─ Expected "on", actual "wrong"
      └─ Expected "off", actual "wrong"
*/
```

### 组合两个转换模式

下面是一个源模式和目标模式都转换其数据的示例：

- 源模式是 `Schema.NumberFromString`，即 `Schema<number, string>`。
- 目标模式是上面定义的 `BooleanFromString`，即 `Schema<boolean, "on" | "off">`。

此示例涉及四种类型，需要两个转换：

- 解码时，将 `number` 转换为 `"on" | "off"`。例如，将任何正数视为 `"on"`。
- 编码时，将 `"on" | "off"` 转换回 `number`。例如，将 `"on"` 视为 `1`，将 `"off"` 视为 `-1`。

通过组合这些转换，我们获得了一个将字符串解码为布尔值并将布尔值编码回字符串的模式。结果模式是 `Schema<boolean, string>`。

**示例**（组合两个转换模式）

```ts twoslash collapse={4-12}
import { Schema } from "effect"

// 将 "on"/"off" 转换为布尔值并反向转换
const BooleanFromString = Schema.transform(
  Schema.Literal("on", "off"),
  Schema.Boolean,
  {
    strict: true,
    decode: (s) => s === "on",
    encode: (bool) => (bool ? "on" : "off")
  }
)

const BooleanFromNumericString = Schema.transform(
  // 源模式：将字符串转换为数字
  Schema.NumberFromString,
  // 目标模式：将 "on"/"off" 转换为布尔值
  BooleanFromString,
  {
    strict: true,
    // 如果数字为正数，使用 "on"，否则使用 "off"
    decode: (n) => (n > 0 ? "on" : "off"),
    // 如果布尔值为 "on"，使用 1，否则使用 -1
    encode: (bool) => (bool === "on" ? 1 : -1)
  }
)

//     ┌─── string
//     ▼
type Encoded = typeof BooleanFromNumericString.Encoded

//     ┌─── boolean
//     ▼
type Type = typeof BooleanFromNumericString.Type

console.log(Schema.decodeUnknownSync(BooleanFromNumericString)("100"))
// 输出: true
```

**示例**（将数组转换为 ReadonlySet）

在此示例中，我们将数组转换为 `ReadonlySet`。`decode` 函数接受一个数组并创建一个新的 `ReadonlySet`。`encode` 函数将集合转换回数组。我们还提供了数组项的模式，以便它们被正确验证。

```ts twoslash
import { Schema } from "effect"

// 此函数构建一个在只读数组和只读集合之间转换的模式
const ReadonlySetFromArray = <A, I, R>(
  itemSchema: Schema.Schema<A, I, R>
): Schema.Schema<ReadonlySet<A>, ReadonlyArray<I>, R> =>
  Schema.transform(
    // 源模式：数组项
    Schema.Array(itemSchema),
    // 目标模式：只读集合
    // **重要** 我们在此使用 `Schema.typeSchema` 来获取项的模式，
    // 以避免对元素进行双重解码
    Schema.ReadonlySetFromSelf(Schema.typeSchema(itemSchema)),
    {
      strict: true,
      decode: (items) => new Set(items),
      encode: (set) => Array.from(set.values())
    }
  )

const schema = ReadonlySetFromArray(Schema.String)

//     ┌─── readonly string[]
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── ReadonlySet<string>
//     ▼
type Type = typeof schema.Type

console.log(Schema.decodeUnknownSync(schema)(["a", "b", "c"]))
// 输出: Set(3) { 'a', 'b', 'c' }

console.log(Schema.encodeSync(schema)(new Set(["a", "b", "c"])))
// 输出: [ 'a', 'b', 'c' ]
```

<Aside type="note" title="为什么使用 Schema.typeSchema">
  请注意，为了定义目标模式，我们使用了 [Schema.typeSchema](/docs/schema/projections/#typeschema)。这是因为元素的解码/编码已经由 `from` 模式 `Schema.Array(itemSchema)` 处理，从而避免了双重解码。
</Aside>

### Non-strict 选项

在某些情况下，严格的类型检查可能会在数据转换期间造成问题，特别是当类型在特定转换中略有差异时。为了应对这些情况，`Schema.transform` 提供了 `strict: false` 选项，它放宽了类型约束，允许更灵活的转换。

**示例**（创建钳位构造函数）

考虑需要定义一个构造函数 `clamp` 来确保数字落在特定范围内的场景。此函数返回一个将数字"钳位"到指定最小和最大范围的模式：

```ts twoslash
import { Schema, Number } from "effect"

const clamp =
  (minimum: number, maximum: number) =>
  <A extends number, I, R>(self: Schema.Schema<A, I, R>) =>
    Schema.transform(
      // 源模式
      self,
      // 目标模式：基于最小/最大范围进行过滤
      self.pipe(
        Schema.typeSchema,
        Schema.filter((a) => a <= minimum || a >= maximum)
      ),
// @errors: 2345
      {
        strict: true,
        // 将数字钳位在指定范围内
        decode: (a) => Number.clamp(a, { minimum, maximum }),
        encode: (a) => a
      }
    )
```

在此示例中，`Number.clamp` 返回一个 `number`，但可能不被识别为特定的 `A` 类型，这在严格检查下导致类型不匹配。

有两种方法可以解决此问题：

1. **使用类型断言**：
   添加类型转换可以强制将返回类型视为 `A` 类型：

   ```ts showLineNumbers=false
   decode: (a) => Number.clamp(a, { minimum, maximum }) as A
   ```

2. **使用 Non-strict 选项**：
   在转换选项中设置 `strict: false` 允许模式绕过 TypeScript 的某些类型检查规则，以适应类型差异：

   ```ts twoslash
   import { Schema, Number } from "effect"

   const clamp =
     (minimum: number, maximum: number) =>
     <A extends number, I, R>(self: Schema.Schema<A, I, R>) =>
       Schema.transform(
         self,
         self.pipe(
           Schema.typeSchema,
           Schema.filter((a) => a >= minimum && a <= maximum)
         ),
         {
           strict: false,
           decode: (a) => Number.clamp(a, { minimum, maximum }),
           encode: (a) => a
         }
       )
   ```

## transformOrFail

虽然 [Schema.transform](#transform) 函数适用于无错误的转换，但 `Schema.transformOrFail` 函数专为更复杂的场景设计，在这些场景中，**转换在解码或编码阶段可能失败**。

此函数使解码/编码函数能够返回成功结果或错误，特别适用于验证和处理可能并不总是符合预期格式的数据。

### 错误处理

`Schema.transformOrFail` 函数使用 ParseResult 模块来管理潜在错误：

| 构造函数           | 描述                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| `ParseResult.succeed` | 表示转换成功，没有发生错误。                                         |
| `ParseResult.fail`    | 表示转换失败，根据提供的 `ParseIssue` 创建一个新的 `ParseError`。 |

此外，ParseResult 模块提供了用于处理各种类型解析问题的构造函数，例如：

| 解析问题类型     | 描述                                                   |
| ---------------- | ------------------------------------------------------ |
| `Type`           | 指示类型不匹配错误。                                   |
| `Missing`        | 当必需字段缺失时使用。                                 |
| `Unexpected`     | 用于模式中不允许的意外字段。                           |
| `Forbidden`      | 标记解码或编码操作被模式禁止。                         |
| `Pointer`        | 指向数据中发生问题的特定位置。                         |
| `Refinement`     | 当值不满足特定的精炼或约束时使用。                     |
| `Transformation` | 标记在一种类型到另一种类型的转换过程中发生的问题。     |
| `Composite`      | 表示复合错误，将多个问题组合为一个，有助于分组错误。   |

这些工具允许进行详细和具体的错误处理，提高了数据处理操作的可靠性。

**示例**（将字符串转换为数字）

`Schema.transformOrFail` 的一个常见用例是将数字的字符串表示形式转换为实际的数字类型。这种场景在处理用户输入或来自外部源的数据时很典型。

```ts twoslash
import { ParseResult, Schema } from "effect"

export const NumberFromString = Schema.transformOrFail(
  // 源模式：接受任何字符串
  Schema.String,
  // 目标模式：期望一个数字
  Schema.Number,
  {
    // 可选，但可以从 TypeScript 获得更好的错误消息
    strict: true,
    decode: (input, options, ast) => {
      const parsed = parseFloat(input)
      // 如果解析失败（NaN），返回一个带有自定义错误的 ParseError
      if (isNaN(parsed)) {
        return ParseResult.fail(
          // 创建一个类型不匹配错误
          new ParseResult.Type(
            // 提供模式的抽象语法树以获取上下文
            ast,
            // 包含有问题的输入
            input,
            // 可选的自定义错误消息
            "Failed to convert string to number"
          )
        )
      }
      return ParseResult.succeed(parsed)
    },
    encode: (input, options, ast) => ParseResult.succeed(input.toString())
  }
)

//     ┌─── string
//     ▼
type Encoded = typeof NumberFromString.Encoded

//     ┌─── number
//     ▼
type Type = typeof NumberFromString.Type

console.log(Schema.decodeUnknownSync(NumberFromString)("123"))
// 输出: 123

console.log(Schema.decodeUnknownSync(NumberFromString)("-"))
/*
抛出:
ParseError: (string <-> number)
└─ Transformation process failure
   └─ Failed to convert string to number
*/
```

`decode` 和 `encode` 函数不仅接收要转换的值（`input`），还接收用户在结果模式上设置的[解析选项](/docs/schema/getting-started/#parse-options)，以及 `ast`，它表示正在转换的模式的底层定义。

### 异步转换

在现代应用程序中，特别是那些与外部 API 交互的应用程序，你可能需要异步转换数据。`Schema.transformOrFail` 通过允许你返回 `Effect` 来支持异步转换。

**示例**（通过 API 调用验证数据）

考虑需要通过对 API 的调用来验证人员 ID 的场景。以下是实现方法：

```ts twoslash
import { Effect, Schema, ParseResult } from "effect"

// 定义发起 API 请求的函数
const get = (url: string): Effect.Effect<unknown, Error> =>
  Effect.tryPromise({
    try: () =>
      fetch(url).then((res) => {
        if (res.ok) {
          return res.json() as Promise<unknown>
        }
        throw new Error(String(res.status))
      }),
    catch: (e) => new Error(String(e))
  })

// 为人员 ID 创建一个品牌模式
const PeopleId = Schema.String.pipe(Schema.brand("PeopleId"))

// 定义带有异步转换的模式
const PeopleIdFromString = Schema.transformOrFail(
  Schema.String,
  PeopleId,
  {
    strict: true,
    decode: (s, _, ast) =>
      // 发起 API 调用以验证 ID
      Effect.mapBoth(get(`https://swapi.dev/api/people/${s}`), {
        // API 调用失败的错误处理
        onFailure: (e) => new ParseResult.Type(ast, s, e.message),
        // 如果 API 调用成功，返回 ID
        onSuccess: () => s
      }),
    encode: ParseResult.succeed
  }
)

//     ┌─── string
//     ▼
type Encoded = typeof PeopleIdFromString.Encoded

//     ┌─── string & Brand<"PeopleId">
//     ▼
type Type = typeof PeopleIdFromString.Type

//     ┌─── never
//     ▼
type Context = typeof PeopleIdFromString.Context

// 运行成功的解码操作
Effect.runPromiseExit(Schema.decodeUnknown(PeopleIdFromString)("1")).then(
  console.log
)
/*
输出:
{ _id: 'Exit', _tag: 'Success', value: '1' }
*/

// 运行一个将失败的解码操作
Effect.runPromiseExit(
  Schema.decodeUnknown(PeopleIdFromString)("fail")
).then(console.log)
/*
输出:
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Fail',
    failure: {
      _id: 'ParseError',
      message: '(string <-> string & Brand<"PeopleId">)\n' +
        '└─ Transformation process failure\n' +
        '   └─ Error: 404'
    }
  }
}
*/
```

### 声明依赖

在你的转换依赖于外部服务的情况下，你可以在 `decode` 或 `encode` 函数中注入这些服务。然后这些依赖会被追踪在模式的 `Requirements` 通道中：

```text showLineNumbers=false "Requirements"
Schema<Type, Encoded, Requirements>
```

**示例**（使用服务验证数据）

```ts twoslash {46}
import { Context, Effect, Schema, ParseResult, Layer } from "effect"

// 定义一个验证服务，用于依赖注入
class Validation extends Context.Tag("Validation")<
  Validation,
  {
    readonly validatePeopleid: (s: string) => Effect.Effect<void, Error>
  }
>() {}

// 为人员 ID 创建一个品牌模式
const PeopleId = Schema.String.pipe(Schema.brand("PeopleId"))

// 将字符串转换为经过验证的 PeopleId，
// 使用外部验证服务
const PeopleIdFromString = Schema.transformOrFail(
  Schema.String,
  PeopleId,
  {
    strict: true,
    decode: (s, _, ast) =>
      // 使用注入的服务异步验证 ID
      Effect.gen(function* () {
        // 访问验证服务
        const validator = yield* Validation
        // 使用服务验证 ID
        yield* validator.validatePeopleid(s)
        return s
      }).pipe(
        Effect.mapError((e) => new ParseResult.Type(ast, s, e.message))
      ),
    encode: ParseResult.succeed // 编码时直接返回字符串
  }
)

//     ┌─── string
//     ▼
type Encoded = typeof PeopleIdFromString.Encoded

//     ┌─── string & Brand<"PeopleId">
//     ▼
type Type = typeof PeopleIdFromString.Type

//     ┌─── Validation
//     ▼
type Context = typeof PeopleIdFromString.Context

// 提供一个成功验证服务的 Layer
const SuccessTest = Layer.succeed(Validation, {
  validatePeopleid: (_) => Effect.void
})

// 运行成功的解码操作
Effect.runPromiseExit(
  Schema.decodeUnknown(PeopleIdFromString)("1").pipe(
    Effect.provide(SuccessTest)
  )
).then(console.log)
/*
输出:
{ _id: 'Exit', _tag: 'Success', value: '1' }
*/

// 提供一个失败验证服务的 Layer
const FailureTest = Layer.succeed(Validation, {
  validatePeopleid: (_) => Effect.fail(new Error("404"))
})

// 运行一个将失败的解码操作
Effect.runPromiseExit(
  Schema.decodeUnknown(PeopleIdFromString)("fail").pipe(
    Effect.provide(FailureTest)
  )
).then(console.log)
/*
输出:
{
  _id: 'Exit',
  _tag: 'Failure',
  cause: {
    _id: 'Cause',
    _tag: 'Fail',
    failure: {
      _id: 'ParseError',
      message: '(string <-> string & Brand<"PeopleId">)\n' +
        '└─ Transformation process failure\n' +
        '   └─ Error: 404'
    }
  }
}
*/
```

## 禁止编码的单向转换

在某些情况下，将值编码回其原始形式可能没有意义或不可取。你可以使用 `Schema.transformOrFail` 定义一个单向转换，并在编码过程中显式返回一个 `Forbidden` 解析错误。这确保了值一旦被转换，就无法恢复为其原始形式。

**示例**（带有禁止编码的密码哈希）

考虑需要对用户的明文密码进行哈希处理以便安全存储的场景。重要的是，哈希后的密码不能反向恢复为明文。通过使用 `Schema.transformOrFail`，你可以强制执行此限制，确保从明文到哈希密码的单向转换。

```ts twoslash
import { Schema, ParseResult, Redacted } from "effect"
import { createHash } from "node:crypto"

// 为明文密码定义模式
// 带有最小长度要求
const PlainPassword = Schema.String.pipe(
  Schema.minLength(6),
  Schema.brand("PlainPassword", { identifier: "PlainPassword" })
)

// 为哈希密码定义一个单独的品牌类型
const HashedPassword = Schema.String.pipe(
  Schema.brand("HashedPassword", { identifier: "HashedPassword" })
)

// 定义从明文密码到哈希密码的单向转换
export const PasswordHashing = Schema.transformOrFail(
  PlainPassword,
  // 将输出包装在 Redacted 中以增加安全性
  Schema.RedactedFromSelf(HashedPassword),
  {
    strict: true,
    // 解码：将明文密码转换为哈希密码
    decode: (plainPassword) => {
      const hash = createHash("sha256")
        .update(plainPassword)
        .digest("hex")
      // 将哈希包装在 Redacted 中
      return ParseResult.succeed(Redacted.make(hash))
    },
    // 编码：禁止将哈希密码反向恢复为明文
    encode: (hashedPassword, _, ast) =>
      ParseResult.fail(
        new ParseResult.Forbidden(
          ast,
          hashedPassword,
          "Encoding hashed passwords back to plain text is forbidden."
        )
      )
  }
)

//     ┌─── string
//     ▼
type Encoded = typeof PasswordHashing.Encoded

//     ┌─── Redacted<string & Brand<"HashedPassword">>
//     ▼
type Type = typeof PasswordHashing.Type

// 示例：将明文密码解码为哈希密码
console.log(
  Schema.decodeUnknownSync(PasswordHashing)("myPlainPassword123")
)
// 输出: <redacted>

// 示例：尝试将哈希密码编码回明文
console.log(
  Schema.encodeUnknownSync(PasswordHashing)(Redacted.make("2ef2b7..."))
)
/*
抛出:
ParseError: (PlainPassword <-> Redacted(<redacted>))
└─ Transformation process failure
   └─ (PlainPassword <-> Redacted(<redacted>))
      └─ Encoding hashed passwords back to plain text is forbidden.
*/
```

## 组合

在复杂应用中，经常需要组合和重用模式，而 `Schema.compose` 组合子提供了一种高效的方式来实现这一点。使用 `Schema.compose`，你可以将两个模式 `Schema<B, A, R1>` 和 `Schema<C, B, R2>` 链式组合成一个单一模式 `Schema<C, A, R1 | R2>`：

**示例**（组合模式以将分隔字符串解析为数字）

```ts twoslash
import { Schema } from "effect"

// 按逗号将字符串拆分为字符串数组的模式
//
//     ┌─── Schema<readonly string[], string, never>
//     ▼
const schema1 = Schema.asSchema(Schema.split(","))

// 将字符串数组转换为数字数组的模式
//
//     ┌─── Schema<readonly number[], readonly string[], never>
//     ▼
const schema2 = Schema.asSchema(Schema.Array(Schema.NumberFromString))

// 组合后的模式，接受一个字符串，按逗号拆分，
// 并将结果转换为数字数组
//
//     ┌─── Schema<readonly number[], string, never>
//     ▼
const ComposedSchema = Schema.asSchema(Schema.compose(schema1, schema2))
```

### Non-strict 选项

组合模式时，你可能会遇到一个模式的输出与下一个模式的输入不完全匹配的情况，例如，如果你有 `Schema<R1, A, B>` 和 `Schema<R2, C, D>`，其中 `C` 与 `B` 不同。为了处理这些情况，你可以使用 `{ strict: false }` 选项来放宽类型约束。

**示例**（在组合中使用 Non-strict 选项）

```ts twoslash
import { Schema } from "effect"

// 如果没有 `strict: false` 选项，
// 此组合会引发 TypeScript 错误
Schema.compose(
// @errors: 2769
  Schema.Union(Schema.Null, Schema.Literal("0")),
  Schema.NumberFromString
)

// 使用 `strict: false` 以允许类型灵活性
Schema.compose(
  Schema.Union(Schema.Null, Schema.Literal("0")),
  Schema.NumberFromString,
  { strict: false }
)
```

## Effectful 过滤器

`Schema.filterEffect` 函数支持需要异步或动态场景的验证，使其适用于涉及副作用（如网络请求或数据库查询）的验证。对于简单的同步验证，请参阅 [`Schema.filter`](/docs/schema/filters/#declaring-filters)。

**示例**（异步用户名验证）

```ts twoslash
import { Effect, Schema } from "effect"

// 模拟验证用户名的异步函数
async function validateUsername(username: string) {
  return Promise.resolve(username === "gcanti")
}

// 定义一个带有 effectful 过滤器的模式
const ValidUsername = Schema.String.pipe(
  Schema.filterEffect((username) =>
    Effect.promise(() =>
      // 异步验证用户名，
      // 如果无效则返回错误消息
      validateUsername(username).then(
        (valid) => valid || "Invalid username"
      )
    )
  )
).annotations({ identifier: "ValidUsername" })

Effect.runPromise(Schema.decodeUnknown(ValidUsername)("xxx")).then(
  console.log
)
/*
ParseError: ValidUsername
└─ Transformation process failure
   └─ Invalid username
*/
```

### parseJson

`Schema.parseJson` 构造函数提供了一种使用 `JSON.parse` 的底层功能将 JSON 字符串转换为 `unknown` 类型的方法。它还在编码时使用 `JSON.stringify`。
