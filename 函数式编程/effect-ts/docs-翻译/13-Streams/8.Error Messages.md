## 默认错误消息

默认情况下，当解析错误发生时，系统会根据模式的结构和错误的性质自动生成信息丰富的消息（更多信息请参阅 [TreeFormatter](/docs/schema/error-formatters/#treeformatter-default)）。例如，如果缺少必需属性或数据类型不匹配，错误消息将清楚地说明期望值与实际输入。

**示例**（类型不匹配）

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

Schema.decodeUnknownSync(Person)(null)
// 输出: ParseError: Expected { readonly name: string; readonly age: number }, actual null
```

**示例**（缺少属性）

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

Schema.decodeUnknownSync(Person)({}, { errors: "all" })
/*
抛出:
ParseError: { readonly name: string; readonly age: number }
├─ ["name"]
│  └─ is missing
└─ ["age"]
   └─ is missing
*/
```

**示例**（属性类型错误）

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

Schema.decodeUnknownSync(Person)(
  { name: null, age: "age" },
  { errors: "all" }
)
/*
抛出:
ParseError: { readonly name: string; readonly age: number }
├─ ["name"]
│  └─ Expected string, actual null
└─ ["age"]
   └─ Expected number, actual "age"
*/
```

### 使用标识符增强错误消息的清晰度

在模式具有多个字段或嵌套结构的场景中，默认错误消息可能会变得过于复杂和冗长。为了解决这个问题，您可以通过使用 `identifier`、`title` 和 `description` 等注解来增强这些消息的清晰度和简洁性。

**示例**（使用标识符提高清晰度）

```ts twoslash
import { Schema } from "effect"

const Name = Schema.String.annotations({ identifier: "Name" })

const Age = Schema.Number.annotations({ identifier: "Age" })

const Person = Schema.Struct({
  name: Name,
  age: Age
}).annotations({ identifier: "Person" })

Schema.decodeUnknownSync(Person)(null)
/*
抛出:
ParseError: Expected Person, actual null
*/

Schema.decodeUnknownSync(Person)({}, { errors: "all" })
/*
抛出:
ParseError: Person
├─ ["name"]
│  └─ is missing
└─ ["age"]
   └─ is missing
*/

Schema.decodeUnknownSync(Person)(
  { name: null, age: null },
  { errors: "all" }
)
/*
抛出:
ParseError: Person
├─ ["name"]
│  └─ Expected Name, actual null
└─ ["age"]
   └─ Expected Age, actual null
*/
```

### 精炼

当精炼失败时，默认错误消息会指示失败是发生在"源"部分还是定义精炼的谓词内部：

**示例**（精炼错误）

```ts twoslash
import { Schema } from "effect"

const Name = Schema.NonEmptyString.annotations({ identifier: "Name" })

const Age = Schema.Positive.pipe(Schema.int({ identifier: "Age" }))

const Person = Schema.Struct({
  name: Name,
  age: Age
}).annotations({ identifier: "Person" })

// 源侧失败
Schema.decodeUnknownSync(Person)({ name: null, age: 18 })
/*
抛出:
ParseError: Person
└─ ["name"]
   └─ Name
      └─ From side refinement failure
         └─ Expected string, actual null
*/

// 谓词精炼失败
Schema.decodeUnknownSync(Person)({ name: "", age: 18 })
/*
抛出:
ParseError: Person
└─ ["name"]
   └─ Name
      └─ Predicate refinement failure
         └─ Expected a non empty string, actual ""
*/
```

在第一个示例中，错误消息指示 `name` 属性发生了"源侧"精炼失败，说明期望的是字符串但收到了 `null`。
在第二个示例中，报告了"谓词"精炼失败，说明 `name` 期望非空字符串但提供了空字符串。

### 转换

不同类型或格式之间的转换偶尔会导致错误。系统提供结构化的错误消息来指定错误发生的位置：

- **编码侧失败**：此侧的错误通常表明转换的输入与预期的初始类型或格式不匹配。例如，当期望 `string` 时收到 `null`。
- **转换过程失败**：此类错误发生在转换逻辑本身失败时，例如当输入不满足转换函数中指定的标准时。
- **类型侧失败**：当转换的输出不满足解码侧的模式要求时发生。如果转换后的值未能通过后续验证或条件，就可能发生这种情况。

**示例**（转换错误）

```ts twoslash
import { ParseResult, Schema } from "effect"

const schema = Schema.transformOrFail(
  Schema.String,
  Schema.String.pipe(Schema.minLength(2)),
  {
    strict: true,
    decode: (s, _, ast) =>
      s.length > 0
        ? ParseResult.succeed(s)
        : ParseResult.fail(new ParseResult.Type(ast, s)),
    encode: ParseResult.succeed
  }
)

// 编码侧失败
Schema.decodeUnknownSync(schema)(null)
/*
抛出:
ParseError: (string <-> minLength(2))
└─ Encoded side transformation failure
   └─ Expected string, actual null
*/

// 转换失败
Schema.decodeUnknownSync(schema)("")
/*
抛出:
ParseError: (string <-> minLength(2))
└─ Transformation process failure
   └─ Expected (string <-> minLength(2)), actual ""
*/

// 类型侧失败
Schema.decodeUnknownSync(schema)("a")
/*
抛出:
ParseError: (string <-> minLength(2))
└─ Type side transformation failure
   └─ minLength(2)
      └─ Predicate refinement failure
         └─ Expected a string at least 2 character(s) long, actual "a"
*/
```

## 自定义错误消息

您可以使用 `message` 注解为模式的不同部分定义专门的自定义错误消息。这允许开发人员提供更多上下文相关的反馈，从而改善调试和验证过程。

以下是 `MessageAnnotation` 类型的概述，您可以使用它来构建这些消息：

```ts showLineNumbers=false
type MessageAnnotation = (issue: ParseIssue) =>
  | string
  | Effect<string>
  | {
      readonly message: string | Effect<string>
      readonly override: boolean
    }
```

| 返回类型                            | 描述                                                                                                                                                                                                                                 |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `string`                            | 提供直接描述错误的静态消息。                                                                                                                                                                                                         |
| `Effect<string>`                    | 使用动态消息，这些消息可以结合**同步**过程的结果或依赖**可选**的依赖项。                                                                                                                                                            |
| 对象（包含 `message` 和 `override`） | 允许您定义一个特定的错误消息以及一个布尔标志（`override`）。此标志决定自定义消息是否应覆盖任何默认或嵌套的自定义消息，从而精确控制向用户显示的错误输出。                                                                           |

**示例**（向字符串模式添加自定义错误消息）

```ts twoslash
import { Schema } from "effect"

// 定义一个没有自定义消息的字符串模式
const MyString = Schema.String

// 尝试解码 `null`，结果出现默认错误消息
Schema.decodeUnknownSync(MyString)(null)
/*
抛出:
ParseError: Expected string, actual null
*/

// 定义一个带有自定义错误消息的字符串模式
const MyStringWithMessage = Schema.String.annotations({
  message: () => "not a string"
})

// 使用自定义模式解码，显示新的错误消息
Schema.decodeUnknownSync(MyStringWithMessage)(null)
/*
抛出:
ParseError: not a string
*/
```

**示例**（为联合模式添加带有覆盖选项的自定义错误消息）

```ts twoslash "override: true"
import { Schema } from "effect"

// 定义一个没有自定义消息的联合模式
const MyUnion = Schema.Union(Schema.String, Schema.Number)

// 解码 `null`，结果出现默认的联合错误消息
Schema.decodeUnknownSync(MyUnion)(null)
/*
抛出:
ParseError: string | number
├─ Expected string, actual null
└─ Expected number, actual null
*/

// 定义一个带有自定义消息和覆盖标志的联合模式
const MyUnionWithMessage = Schema.Union(
  Schema.String,
  Schema.Number
).annotations({
  message: () => ({
    message: "Please provide a string or a number",
    // 确保此消息替换所有嵌套消息
    override: true
  })
})

// 使用自定义模式解码，显示新的错误消息
Schema.decodeUnknownSync(MyUnionWithMessage)(null)
/*
抛出:
ParseError: Please provide a string or a number
*/
```

### 消息的通用指南

确定消息的一般逻辑如下：

1.  如果没有设置自定义消息，则使用操作（即解码或编码）失败的最内层模式相关的默认消息。

2.  如果设置了自定义消息，则使用从最内层模式到最外层模式中**第一个**失败模式对应的消息。但是，如果失败的模式没有自定义消息，则**使用默认消息**。

3.  作为一个可选功能，**您可以覆盖指南 2**，通过将 `override` 标志设置为 `true`。这允许自定义消息优先于来自内部模式的所有其他自定义消息。这是为了解决用户想要定义一个单一的累积自定义消息来描述有效值必须具有的属性，并且不希望看到默认消息的场景。

让我们看一些实际的例子。

### 标量模式

**示例**（为标量模式设置简单的自定义消息）

```ts twoslash
import { Schema } from "effect"

const MyString = Schema.String.annotations({
  message: () => "my custom message"
})

const decode = Schema.decodeUnknownSync(MyString)

try {
  decode(null)
} catch (e: any) {
  console.log(e.message) // "my custom message"
}
```

### 精炼

此示例演示了在精炼链中的最后一个精炼上设置自定义消息。如您所见，只有在与 `maxLength` 相关的精炼失败时，才会使用自定义消息；否则，使用默认消息。

**示例**（在链中的最后一个精炼上设置自定义消息）

```ts twoslash
import { Schema } from "effect"

const MyString = Schema.String.pipe(
  Schema.minLength(1),
  Schema.maxLength(2)
).annotations({
  // 仅当最后一个过滤器（`maxLength`）失败时才会显示此消息
  message: () => "my custom message"
})

const decode = Schema.decodeUnknownSync(MyString)

try {
  decode(null)
} catch (e: any) {
  console.log(e.message)
  /*
   minLength(1) & maxLength(2)
   └─ From side refinement failure
      └─ minLength(1)
         └─ From side refinement failure
            └─ Expected string, actual null
  */
}

try {
  decode("")
} catch (e: any) {
  console.log(e.message)
  /*
   minLength(1) & maxLength(2)
   └─ From side refinement failure
      └─ minLength(1)
         └─ Predicate refinement failure
            └─ Expected a string at least 1 character(s) long, actual ""
  */
}

try {
  decode("abc")
} catch (e: any) {
  console.log(e.message)
  // "my custom message"
}
```

当设置多个自定义消息时，使用从最内层精炼到最外层精炼中**第一个**失败谓词对应的消息：

**示例**（为多个精炼设置自定义消息）

```ts twoslash
import { Schema } from "effect"

const MyString = Schema.String
  // 仅当输入非字符串时显示此消息
  .annotations({ message: () => "String custom message" })
  .pipe(
    // 仅当过滤器 `minLength` 失败时显示此消息
    Schema.minLength(1, { message: () => "minLength custom message" }),
    // 仅当过滤器 `maxLength` 失败时显示此消息
    Schema.maxLength(2, { message: () => "maxLength custom message" })
  )

const decode = Schema.decodeUnknownSync(MyString)

try {
  decode(null)
} catch (e: any) {
  console.log(e.message) // String custom message
}

try {
  decode("")
} catch (e: any) {
  console.log(e.message) // minLength custom message
}

try {
  decode("abc")
} catch (e: any) {
  console.log(e.message) // maxLength custom message
}
```

您可以通过将 `override` 标志设置为 `true` 来更改默认行为。当您想要创建一个单一的全面自定义消息来描述有效值的所需属性而不显示默认消息时，这很有用。

**示例**（覆盖默认消息）

```ts twoslash
import { Schema } from "effect"

const MyString = Schema.String.pipe(
  Schema.minLength(1),
  Schema.maxLength(2)
).annotations({
  // 通过将 `override` 标志设置为 `true`，此消息将始终显示任何错误
  message: () => ({ message: "my custom message", override: true })
})

const decode = Schema.decodeUnknownSync(MyString)

try {
  decode(null)
} catch (e: any) {
  console.log(e.message) // my custom message
}

try {
  decode("")
} catch (e: any) {
  console.log(e.message) // my custom message
}

try {
  decode("abc")
} catch (e: any) {
  console.log(e.message) // my custom message
}
```

### 转换

在此示例中，`IntFromString` 是一个将字符串转换为整数的转换模式。它根据不同的场景应用特定的验证消息。

**示例**（为字符串到整数转换设置自定义错误消息）

```ts twoslash
import { ParseResult, Schema } from "effect"

const IntFromString = Schema.transformOrFail(
  // 仅当输入不是字符串时显示此消息
  Schema.String.annotations({ message: () => "please enter a string" }),
  // 仅当输入可以转换为数字但不是整数时显示此消息
  Schema.Int.annotations({ message: () => "please enter an integer" }),
  {
    strict: true,
    decode: (s, _, ast) => {
      const n = Number(s)
      return Number.isNaN(n)
        ? ParseResult.fail(new ParseResult.Type(ast, s))
        : ParseResult.succeed(n)
    },
    encode: (n) => ParseResult.succeed(String(n))
  }
)
  // 仅当输入无法转换为数字时显示此消息
  .annotations({ message: () => "please enter a parseable string" })

const decode = Schema.decodeUnknownSync(IntFromString)

try {
  decode(null)
} catch (e: any) {
  console.log(e.message) // please enter a string
}

try {
  decode("1.2")
} catch (e: any) {
  console.log(e.message) // please enter an integer
}

try {
  decode("not a number")
} catch (e: any) {
  console.log(e.message) // please enter a parseable string
}
```

### 复合模式

与简单的标量值（如 `string` 或 `number`）不同，自定义消息系统在处理复杂模式时特别有用。例如，考虑一个包含嵌套结构的模式，比如一个包含其他结构体数组的结构体。让我们看一个例子，展示默认消息在处理此类嵌套结构中的解码错误时的优势：

**示例**（嵌套模式中的自定义错误消息）

```ts twoslash
import { Schema, pipe } from "effect"

const schema = Schema.Struct({
  outcomes: pipe(
    Schema.Array(
      Schema.Struct({
        id: Schema.String,
        text: pipe(
          Schema.String.annotations({
            message: () => "error_invalid_outcome_type"
          }),
          Schema.minLength(1, { message: () => "error_required_field" }),
          Schema.maxLength(50, {
            message: () => "error_max_length_field"
          })
        )
      })
    ),
    Schema.minItems(1, { message: () => "error_min_length_field" })
  )
})

Schema.decodeUnknownSync(schema, { errors: "all" })({
  outcomes: []
})
/*
抛出
ParseError: { readonly outcomes: minItems(1) }
└─ ["outcomes"]
   └─ error_min_length_field
*/

Schema.decodeUnknownSync(schema, { errors: "all" })({
  outcomes: [
    { id: "1", text: "" },
    { id: "2", text: "this one is valid" },
    { id: "3", text: "1234567890".repeat(6) }
  ]
})
/*
抛出
ParseError: { readonly outcomes: minItems(1) }
└─ ["outcomes"]
   └─ minItems(1)
      └─ From side refinement failure
         └─ ReadonlyArray<{ readonly id: string; readonly text: minLength(1) & maxLength(50) }>
            ├─ [0]
            │  └─ { readonly id: string; readonly text: minLength(1) & maxLength(50) }
            │     └─ ["text"]
            │        └─ error_required_field
            └─ [2]
               └─ { readonly id: string; readonly text: minLength(1) & maxLength(50) }
                  └─ ["text"]
                     └─ error_max_length_field
*/
```

### Effectful 消息

错误消息可以超越简单的字符串，通过返回一个 `Effect`，允许它们访问依赖项，例如国际化服务。这种方法使消息能够根据外部上下文或服务动态调整。下面是一个示例，说明如何创建基于 Effect 的消息。

**示例**（带有国际化服务的基于 Effect 的消息）

```ts twoslash
import {
  Context,
  Effect,
  Either,
  Option,
  Schema,
  ParseResult
} from "effect"

// 定义一个用于自定义消息的国际化服务
class Messages extends Context.Tag("Messages")<
  Messages,
  {
    NonEmpty: string
  }
>() {}

// 定义一个带有基于 Effect 的消息的模式
// 该消息依赖于 Messages 服务
const Name = Schema.NonEmptyString.annotations({
  message: () =>
    Effect.gen(function* () {
      // 尝试检索 Messages 服务
      const service = yield* Effect.serviceOption(Messages)
      // 如果服务不可用，则使用回退消息
      return Option.match(service, {
        onNone: () => "Invalid string",
        onSome: (messages) => messages.NonEmpty
      })
    })
})

// 尝试在未提供 Messages 服务的情况下解码空字符串
Schema.decodeUnknownEither(Name)("").pipe(
  Either.mapLeft((error) =>
    ParseResult.TreeFormatter.formatError(error).pipe(
      Effect.runSync,
      console.log
    )
  )
)
// 输出: Invalid string

// 提供 Messages 服务以自定义错误消息
Schema.decodeUnknownEither(Name)("").pipe(
  Either.mapLeft((error) =>
    ParseResult.TreeFormatter.formatError(error).pipe(
      Effect.provideService(Messages, {
        NonEmpty: "should be non empty"
      }),
      Effect.runSync,
      console.log
    )
  )
)
// 输出: should be non empty
```

### 缺失消息

您可以使用 `missingMessage` 注解为缺失的字段或元组元素提供自定义消息。

**示例**（为缺失属性提供自定义消息）

在此示例中，为 `Person` 模式中缺失的 `name` 属性定义了一个自定义消息。

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.propertySignature(Schema.String).annotations({
    // 如果 "name" 缺失时的自定义消息
    missingMessage: () => "Name is required"
  })
})

Schema.decodeUnknownSync(Person)({})
/*
抛出:
ParseError: { readonly name: string }
└─ ["name"]
   └─ Name is required
*/
```

**示例**（为缺失的元组元素提供自定义消息）

在这里，`Point` 元组模式中的每个元素都有一个特定的自定义消息，如果该元素缺失。

```ts twoslash
import { Schema } from "effect"

const Point = Schema.Tuple(
  Schema.element(Schema.Number).annotations({
    // 如果 X 缺失时的消息
    missingMessage: () => "X coordinate is required"
  }),
  Schema.element(Schema.Number).annotations({
    // 如果 Y 缺失时的消息
    missingMessage: () => "Y coordinate is required"
  })
)

Schema.decodeUnknownSync(Point)([], { errors: "all" })
/*
抛出:
ParseError: readonly [number, number]
├─ [0]
│  └─ X coordinate is required
└─ [1]
   └─ Y coordinate is required
*/
```
