Schema 设计的关键特性之一是其灵活性和可定制性。这通过"注解"来实现。模式 `ast` 字段中的每个节点都有一个 `annotations: Record<string | symbol, unknown>` 字段，允许你向模式附加额外的信息。你可以使用 `annotations` 方法或 `Schema.annotations` API 来管理这些注解。

**示例**（使用注解自定义模式）

```ts twoslash
import { Schema } from "effect"

// 定义一个 Password 模式，从字符串类型开始
const Password = Schema.String
  // 为非字符串值添加自定义错误消息
  .annotations({ message: () => "not a string" })
  .pipe(
    // 强制非空字符串并提供自定义错误消息
    Schema.nonEmptyString({ message: () => "required" }),
    // 将字符串长度限制为 10 个字符或更少
    // 并为超出长度提供自定义错误消息
    Schema.maxLength(10, {
      message: (issue) => `${issue.actual} is too long`
    })
  )
  .annotations({
    // 为模式添加唯一标识符
    identifier: "Password",
    // 为模式提供标题
    title: "password",
    // 包含解释此模式含义的描述
    description:
      "A password is a secret string used to authenticate a user",
    // 添加示例以提高清晰度
    examples: ["1Ki77y", "jelly22fi$h"],
    // 包含任何额外的文档
    documentation: `...technical information on Password schema...`
  })
```

## 内置注解

下表概述了常见的内置注解及其用途：

| 注解                | 描述                                                                                                                                                                                                                                                             |
| ------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `identifier`        | 为模式分配一个唯一标识符，适用于 TypeScript 标识符和代码生成目的。常用于工具如 [TreeFormatter](/docs/schema/error-formatters/#customizing-the-output) 以明确输出。示例包括 `"Person"`、`"Product"`。                                                              |
| `title`             | 为模式设置一个简短的描述性标题，类似于 JSON Schema 标题。对于文档或 UI 标题很有用。它也被 [TreeFormatter](/docs/schema/error-formatters/#customizing-the-output) 用于增强错误消息的可读性。                                                                      |
| `description`       | 提供关于模式目的的详细解释，类似于 JSON Schema 描述。被 [TreeFormatter](/docs/schema/error-formatters/#customizing-the-output) 用于提供更详细的错误消息。                                                                                                        |
| `documentation`     | 扩展模式的详细文档，对开发者或自动文档生成有益。                                                                                                                                                                                                                 |
| `examples`          | 列出模式有效值的示例，类似于 JSON Schema 中的 examples 属性，对于文档和验证测试很有用。                                                                                                                                                                          |
| `default`           | 定义模式的默认值，类似于 JSON Schema 中的 default 属性，以确保模式在适用时被预填充。                                                                                                                                                                             |
| `message`           | 自定义验证失败时的错误消息，提高解码或验证错误期间来自 [TreeFormatter](/docs/schema/error-formatters/#customizing-the-output) 和 [ArrayFormatter](/docs/schema/error-formatters/#arrayformatter) 等工具输出的清晰度。                                            |
| `jsonSchema`        | 指定影响 [JSON Schema](/docs/schema/json-schema/) 文档生成的注解，自定义模式的表现形式。                                                                                                                                                                         |
| `arbitrary`         | 配置生成 [Arbitrary](/docs/schema/arbitrary/) 测试数据的设置。                                                                                                                                                                                                   |
| `pretty`            | 配置生成 [Pretty](/docs/schema/pretty/) 输出的设置。                                                                                                                                                                                                             |
| `equivalence`       | 配置评估数据 [Equivalence](/docs/schema/equivalence/) 的设置。                                                                                                                                                                                                   |
| `concurrency`       | 控制并发行为，确保模式在并发操作下最佳运行。有关详细用法，请参考[并发注解](#concurrency-annotation)。                                                                                                                                                           |
| `batching`          | 管理批处理操作的设置，以在操作可以分组时提高性能。                                                                                                                                                                                                               |
| `parseIssueTitle`   | 为解析问题提供自定义标题，增强 [TreeFormatter](/docs/schema/error-formatters/#treeformatter-default) 输出的错误描述。更多信息请参见 [ParseIssueTitle 注解](/docs/schema/error-formatters/#parseissuetitle-annotation)。                                         |
| `parseOptions`      | 允许在模式级别覆盖解析选项，对解析行为提供精细控制。有关应用细节，请参见[在模式级别自定义解析行为](/docs/schema/getting-started/#customizing-parsing-behavior-at-the-schema-level)。                                                                             |
| `decodingFallback`  | 提供一种方式，用于定义在解码操作失败时触发的自定义回退行为。有关详细用法，请参考[使用回退处理解码错误](#handling-decoding-errors-with-fallbacks)。                                                                                                              |

## 并发注解

对于包含多个嵌套模式的更复杂模式（如 `Struct`、`Array` 或 `Union`），`concurrency` 注解提供了一种控制验证如何并发执行的方式。

```ts showLineNumbers=false
type ConcurrencyAnnotation = number | "unbounded" | "inherit" | undefined
```

以下是表格形式的简短版本：

| 值             | 描述                                     |
| -------------- | ---------------------------------------- |
| `number`       | 限制最大并发任务数。                     |
| `"unbounded"`  | 所有任务无限制地并发运行。               |
| `"inherit"`    | 从父上下文继承并发设置。                 |
| `undefined`    | 任务按顺序运行，一个接一个（默认行为）。 |

**示例**（顺序执行）

在此示例中，我们定义了三个模拟具有不同持续时间的异步操作的任务。由于没有指定并发性，任务按顺序执行，一个接一个。

```ts twoslash
import { Schema } from "effect"
import type { Duration } from "effect"
import { Effect } from "effect"

// 模拟一个异步任务
const item = (id: number, duration: Duration.DurationInput) =>
  Schema.String.pipe(
    Schema.filterEffect(() =>
      Effect.gen(function* () {
        yield* Effect.sleep(duration)
        console.log(`Task ${id} done`)
        return true
      })
    )
  )

const Sequential = Schema.Tuple(
  item(1, "30 millis"),
  item(2, "10 millis"),
  item(3, "20 millis")
)

Effect.runPromise(Schema.decode(Sequential)(["a", "b", "c"]))
/*
输出:
Task 1 done
Task 2 done
Task 3 done
*/
```

**示例**（并发执行）

通过添加设置为 `"unbounded"` 的 `concurrency` 注解，任务现在可以并发运行，这意味着它们不需要等待彼此完成即可开始。这在涉及多个任务时可以实现更快的执行。

```ts twoslash
import { Schema } from "effect"
import type { Duration } from "effect"
import { Effect } from "effect"

// 模拟一个异步任务
const item = (id: number, duration: Duration.DurationInput) =>
  Schema.String.pipe(
    Schema.filterEffect(() =>
      Effect.gen(function* () {
        yield* Effect.sleep(duration)
        console.log(`Task ${id} done`)
        return true
      })
    )
  )

const Concurrent = Schema.Tuple(
  item(1, "30 millis"),
  item(2, "10 millis"),
  item(3, "20 millis")
).annotations({ concurrency: "unbounded" })

Effect.runPromise(Schema.decode(Concurrent)(["a", "b", "c"]))
/*
输出:
Task 2 done
Task 3 done
Task 1 done
*/
```

## 使用回退处理解码错误

`DecodingFallbackAnnotation` 允许你通过提供自定义回退逻辑来处理解码错误。

```ts showLineNumbers=false
type DecodingFallbackAnnotation<A> = (
  issue: ParseIssue
) => Effect<A, ParseIssue>
```

此注解使您能够在解码失败时指定回退行为，从而能够优雅地从错误中恢复。

**示例**（基本回退）

在这个基本示例中，当解码失败时（例如输入为 `null`），会返回回退值而不是错误。

```ts twoslash
import { Schema } from "effect"
import { Either } from "effect"

// 带有回退值的模式
const schema = Schema.String.annotations({
  decodingFallback: () => Either.right("<fallback>")
})

console.log(Schema.decodeUnknownSync(schema)("valid input"))
// 输出: valid input

console.log(Schema.decodeUnknownSync(schema)(null))
// 输出: <fallback>
```

**示例**（带日志记录的高级回退）

在这个高级示例中，当解码错误发生时，模式会记录问题，然后返回一个回退值。这演示了如何在错误处理期间结合日志记录和其他副作用。

```ts twoslash
import { Schema } from "effect"
import { Effect } from "effect"

// 带有日志记录和回退的模式
const schemaWithLog = Schema.String.annotations({
  decodingFallback: (issue) =>
    Effect.gen(function* () {
      // 记录错误问题
      yield* Effect.log(issue._tag)
      // 模拟延迟
      yield* Effect.sleep(10)
      // 返回一个回退值
      return yield* Effect.succeed("<fallback>")
    })
})

// 运行 effectful 回退逻辑
Effect.runPromise(Schema.decodeUnknown(schemaWithLog)(null)).then(
  console.log
)
/*
输出:
timestamp=2024-07-25T13:22:37.706Z level=INFO fiber=#0 message=Type
<fallback>
*/
```

## 自定义注解

除了内置注解，您还可以定义自定义注解以满足特定需求。例如，下面是如何创建一个 `deprecated` 注解：

**示例**（定义自定义注解）

```ts twoslash
import { Schema } from "effect"

// 为您的自定义注解定义一个唯一标识符
const DeprecatedId = Symbol.for(
  "some/unique/identifier/for/your/custom/annotation"
)

// 将自定义注解应用到模式
const MyString = Schema.String.annotations({ [DeprecatedId]: true })

console.log(MyString)
/*
输出:
[class SchemaClass] {
  ast: StringKeyword {
    annotations: {
      [Symbol(@effect/docs/schema/annotation/Title)]: 'string',
      [Symbol(@effect/docs/schema/annotation/Description)]: 'a string',
      [Symbol(some/unique/identifier/for/your/custom/annotation)]: true
    },
    _tag: 'StringKeyword'
  },
  ...
}
*/
```

为了使您的新自定义注解具有类型安全性，您可以使用模块增强。在下一个示例中，我们希望我们的自定义注解是布尔类型。

**示例**（为自定义注解添加类型安全性）

```ts twoslash
import { Schema } from "effect"

const DeprecatedId = Symbol.for(
  "some/unique/identifier/for/your/custom/annotation"
)

// 模块增强
declare module "effect/Schema" {
  namespace Annotations {
    interface GenericSchema<A> extends Schema<A> {
      [DeprecatedId]?: boolean
    }
  }
}

const MyString = Schema.String.annotations({
// @errors: 2418
  [DeprecatedId]: "bad value"
})
```

您可以使用 `SchemaAST.getAnnotation` 辅助函数检索自定义注解。

**示例**（检索自定义注解）

```ts twoslash collapse={4-16}
import { SchemaAST, Schema } from "effect"
import { Option } from "effect"

const DeprecatedId = Symbol.for(
  "some/unique/identifier/for/your/custom/annotation"
)

declare module "effect/Schema" {
  namespace Annotations {
    interface GenericSchema<A> extends Schema<A> {
      [DeprecatedId]?: boolean
    }
  }
}

const MyString = Schema.String.annotations({ [DeprecatedId]: true })

// 辅助函数，用于检查模式是否被标记为已弃用
const isDeprecated = <A, I, R>(schema: Schema.Schema<A, I, R>): boolean =>
  SchemaAST.getAnnotation<boolean>(DeprecatedId)(schema.ast).pipe(
    Option.getOrElse(() => false)
  )

console.log(isDeprecated(Schema.String))
// 输出: false

console.log(isDeprecated(MyString))
// 输出: true
```
