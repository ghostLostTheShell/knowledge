在处理模式时，除了使用 [Schema.Struct](/docs/schema/basic-usage/#structs) 构造函数之外，您还有另一种选择。您可以通过 `Schema.Class` 工具利用类的强大功能，它针对常见用例提供了一系列优势：

类提供了几个简化模式创建过程的功能：

- **一体化定义**：使用类，您可以同时定义模式和其对应的不透明类型。
- **共享功能**：您可以使用类方法或 getter 来整合共享功能。
- **值的哈希与相等性**：利用内置的功能进行值的相等性检查和应用哈希（这得益于 `Class` 实现了 [Data.Class](/docs/data-types/data/#class)）。

<Aside type="caution" title="类模式是转换">
  使用 `Schema.Class` 定义的类充当 [转换](/docs/schema/transformations/)。详情请参见 [类模式是转换](#class-schemas-are-transformations)。
</Aside>

## 定义

要使用 `Schema.Class` 定义一个类，您需要指定：

- 正在创建的类的**类型**。
- 类的唯一**标识符**。
- 所需的**字段**。

**示例**（定义一个 Schema 类）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}
```

在此示例中，`Person` 既是一个模式，也是一个 TypeScript 类。`Person` 的实例使用定义的模式创建，确保符合指定的字段。

**示例**（创建实例）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

console.log(new Person({ id: 1, name: "John" }))
/*
输出:
Person { id: 1, name: 'John' }
*/

// 使用工厂函数
console.log(Person.make({ id: 1, name: "John" }))
/*
输出:
Person { id: 1, name: 'John' }
*/
```

<Aside type="note" title="为什么要使用标识符？">
  您需要指定一个标识符以使类成为全局的。这确保了具有相同标识符的两个类引用同一个实例，从而避免依赖 `instanceof` 检查。

  这种行为类似于我们处理其他基于类的 API（如 [Context.Tag](/docs/requirements-management/services/#creating-a-service)）的方式。

  使用唯一标识符在可能发生热重载的场景中特别有用，因为它有助于在重载时保持实例。它确保实例不会重复（尽管不应该发生，但某些打包工具和框架的行为可能无法预测）。

</Aside>

### 类模式是转换

类模式将结构体模式[转换](/docs/schema/transformations/)为一个表示类类型的[声明](/docs/schema/advanced-usage/#declaring-new-data-types)模式。

- 解码时，普通对象被转换为类的实例。
- 编码时，类实例被转换回普通对象。

**示例**（解码和编码一个类）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

const person = Person.make({ id: 1, name: "John" })

// 从普通对象解码为类实例
const decoded = Schema.decodeUnknownSync(Person)({ id: 1, name: "John" })
console.log(decoded)
// 输出: Person { id: 1, name: 'John' }

// 将类实例编码回普通对象
const encoded = Schema.encodeUnknownSync(Person)(person)
console.log(encoded)
// 输出: { id: 1, name: 'John' }
```

### 定义无字段的类

当您的模式不需要任何字段时，您可以使用空对象定义一个类。

**示例**（定义和使用无参类）

```ts twoslash
import { Schema } from "effect"

// 定义一个没有字段的类
class NoArgs extends Schema.Class<NoArgs>("NoArgs")({}) {}

// 使用默认构造函数创建实例
const noargs1 = new NoArgs()

// 或者，通过显式传递空对象创建实例
const noargs2 = new NoArgs({})
```

### 定义带过滤器的类

过滤器允许您在解码、编码或创建实例时验证输入。您可以传递一个应用了过滤器的 `Schema.Struct`，而不是指定原始字段。

**示例**（对 Schema 类应用过滤器）

```ts twoslash
import { Schema } from "effect"

class WithFilter extends Schema.Class<WithFilter>("WithFilter")(
  Schema.Struct({
    a: Schema.NumberFromString,
    b: Schema.NumberFromString
  }).pipe(
    Schema.filter(({ a, b }) => a >= b || "a must be greater than b")
  )
) {}

// 构造函数
console.log(new WithFilter({ a: 1, b: 2 }))
/*
抛出:
ParseError: WithFilter (Constructor)
└─ Predicate refinement failure
   └─ a must be greater than b
*/

// 解码
console.log(Schema.decodeUnknownSync(WithFilter)({ a: "1", b: "2" }))
/*
抛出:
ParseError: (WithFilter (Encoded side) <-> WithFilter)
└─ Encoded side transformation failure
   └─ WithFilter (Encoded side)
      └─ Predicate refinement failure
         └─ a must be greater than b
*/
```

## 通过类构造函数验证属性

当您使用 `Schema.Class` 定义一个类时，构造函数会自动检查所提供的属性是否符合模式的规则。

### 定义和实例化有效的类实例

构造函数确保每个属性（如 `id` 和 `name`）都符合模式。例如，`id` 必须是数字，`name` 必须是非空字符串。

**示例**（创建有效实例）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

// 使用有效属性创建实例
const john = new Person({ id: 1, name: "John" })
```

### 处理无效属性

如果在实例化期间提供了无效属性，构造函数会抛出一个错误，说明验证失败的原因。

**示例**（使用无效属性创建实例）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

// 尝试使用无效的 `name` 创建实例
new Person({ id: 1, name: "" })
/*
抛出:
ParseError: Person (Constructor)
└─ ["name"]
   └─ NonEmptyString
      └─ Predicate refinement failure
         └─ Expected NonEmptyString, actual ""
*/
```

错误清楚地指出 `name` 字段未能满足 `NonEmptyString` 的要求。

### 绕过验证

在某些情况下，您可能希望绕过验证逻辑。虽然通常不推荐，但该库提供了一个选项来实现这一点。

**示例**（绕过验证）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

// 实例化时绕过验证
const john = new Person({ id: 1, name: "" }, true)

// 或显式使用 `disableValidation` 选项
new Person({ id: 1, name: "" }, { disableValidation: true })
```

## 类中的自动哈希与相等性

使用 `Schema.Class` 创建的类实例通过它们与 [Data.Class](/docs/data-types/data/#class) 的集成支持 [Equal](/docs/trait/equal/) 特性。这使得即使在不同的实例之间也能进行直接的值比较。

### 基本相等性检查

如果两个类实例的属性具有相同的值，则它们被认为是相等的。

**示例**（比较具有相同属性的实例）

```ts twoslash
import { Schema } from "effect"
import { Equal } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

const john1 = new Person({ id: 1, name: "John" })
const john2 = new Person({ id: 1, name: "John" })

// 比较实例
console.log(Equal.equals(john1, john2))
// 输出: true
```

### 嵌套或复杂属性

`Equal` 特性执行浅层比较。如果属性是更复杂的结构（如数组），即使数组本身具有相同的值，实例也可能不被认为是相等的。

**示例**（数组的浅层相等性）

```ts twoslash
import { Schema } from "effect"
import { Equal } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString,
  hobbies: Schema.Array(Schema.String) // 标准数组模式
}) {}

const john1 = new Person({
  id: 1,
  name: "John",
  hobbies: ["reading", "coding"]
})
const john2 = new Person({
  id: 1,
  name: "John",
  hobbies: ["reading", "coding"]
})

// 相等性失败，因为 `hobbies` 没有被深度比较
console.log(Equal.equals(john1, john2))
// 输出: false
```

为了实现嵌套结构（如数组）的深度相等，请结合使用 `Schema.Data` 和 `Data.array`。这使库能够比较数组的每个元素，而不是将其视为单个实体。

**示例**（使用 `Schema.Data` 实现深度相等）

```ts twoslash
import { Schema } from "effect"
import { Data, Equal } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString,
  hobbies: Schema.Data(Schema.Array(Schema.String)) // 启用深度相等
}) {}

const john1 = new Person({
  id: 1,
  name: "John",
  hobbies: Data.array(["reading", "coding"])
})
const john2 = new Person({
  id: 1,
  name: "John",
  hobbies: Data.array(["reading", "coding"])
})

// 相等性成功，因为 `hobbies` 被深度比较
console.log(Equal.equals(john1, john2))
// 输出: true
```

## 使用自定义逻辑扩展类

Schema 类提供了包含自定义 getter 和方法的灵活性，允许您扩展它们超出定义字段的功能。

### 添加自定义 Getter

Getter 可用于从类的字段派生计算值。例如，`Person` 类可以包含一个 getter 来返回大写的 `name` 属性。

**示例**（为大写名称添加 Getter）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {
  // 自定义 getter，以大写形式返回名称
  get upperName() {
    return this.name.toUpperCase()
  }
}

const john = new Person({ id: 1, name: "John" })

// 使用自定义 getter
console.log(john.upperName)
// 输出: "JOHN"
```

### 添加自定义方法

除了 getter，您还可以定义方法来封装更复杂的逻辑或涉及类字段的操作。

**示例**（添加方法）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {
  // 返回问候语的自定义方法
  greet() {
    return `Hello, my name is ${this.name}.`
  }
}

const john = new Person({ id: 1, name: "John" })

// 使用自定义方法
console.log(john.greet())
// 输出: "Hello, my name is John."
```

## 利用类作为模式定义

当您使用 `Schema.Class` 定义一个类时，它既充当模式，也充当类。这种双重功能允许在需要模式的任何地方使用该类。

**示例**（在数组模式中使用类）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

// 在数组模式中使用 Person 类
const Persons = Schema.Array(Person)

//     ┌─── readonly Person[]
//     ▼
type Type = typeof Persons.Type
```

### 暴露的值

该类还包含一个 `fields` 静态属性，概述了在类创建期间定义的字段。

**示例**（访问 `fields` 属性）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

//       ┌─── {
//       |      readonly id: typeof Schema.Number;
//       |      readonly name: typeof Schema.NonEmptyString;
//       |    }
//       ▼
Person.fields
```

## 添加注解

使用 `Schema.Class` 定义一个类类似于创建一个[转换](/docs/schema/transformations/)模式，该模式将结构体模式转换为表示类类型的[声明](/docs/schema/advanced-usage/#declaring-new-data-types)模式。

例如，考虑以下类定义：

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}
```

在底层，这个定义创建了一个转换模式，将：

```ts showLineNumbers=false
Schema.Struct({
  id: Schema.Number,
  name: Schema.NonEmptyString
})
```

映射到一个表示 `Person` 类的模式：

```ts showLineNumbers=false
Schema.declare((input) => input instanceof Person)
```

因此，使用 `Schema.Class` 定义一个模式涉及三个模式：

- "源"模式（结构体）
- "目标"模式（类）
- "转换"模式（结构体 -> 类）

您可以通过向 `Schema.Class` API 传递一个元组作为第二个参数来为这些模式中的每一个添加注解。

**示例**（注解类模式的不同部分）

```ts twoslash
import { Schema, SchemaAST } from "effect"

class Person extends Schema.Class<Person>("Person")(
  {
    id: Schema.Number,
    name: Schema.NonEmptyString
  },
  [
    // "目标"模式的注解
    { description: `"to" description` },

    // "转换"模式的注解
    { description: `"transformation" description` },

    // "源"模式的注解
    { description: `"from" description` }
  ]
) {}

console.log(SchemaAST.getDescriptionAnnotation(Person.ast.to))
// 输出: { _id: 'Option', _tag: 'Some', value: '"to" description' }

console.log(SchemaAST.getDescriptionAnnotation(Person.ast))
// 输出: { _id: 'Option', _tag: 'Some', value: '"transformation" description' }

console.log(SchemaAST.getDescriptionAnnotation(Person.ast.from))
// 输出: { _id: 'Option', _tag: 'Some', value: '"from" description' }
```

如果您不想注解所有三个模式，可以为想要跳过的模式传递 `undefined`。

**示例**（跳过注解）

```ts twoslash
import { Schema, SchemaAST } from "effect"

class Person extends Schema.Class<Person>("Person")(
  {
    id: Schema.Number,
    name: Schema.NonEmptyString
  },
  [
    // "目标"模式没有注解
    undefined,

    // "转换"模式的注解
    { description: `"transformation" description` }
  ]
) {}

console.log(SchemaAST.getDescriptionAnnotation(Person.ast.to))
// 输出: { _id: 'Option', _tag: 'None' }

console.log(SchemaAST.getDescriptionAnnotation(Person.ast))
// 输出: { _id: 'Option', _tag: 'Some', value: '"transformation" description' }

console.log(SchemaAST.getDescriptionAnnotation(Person.ast.from))
// 输出: { _id: 'Option', _tag: 'None' }
```

默认情况下，用于定义类的唯一标识符也会作为类模式的默认 `identifier` 注解应用。

**示例**（默认标识符注解）

```ts twoslash
import { Schema, SchemaAST } from "effect"

// 用作默认标识符注解 ────┐
//                           |
//                           ▼
class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {}

console.log(SchemaAST.getIdentifierAnnotation(Person.ast.to))
// 输出: { _id: 'Option', _tag: 'Some', value: 'Person' }
```

## 递归模式

当您需要定义一个依赖于自身的模式时，`Schema.suspend` 组合子非常有用，例如在递归数据结构的情况下。在此示例中，`Category` 模式依赖于自身，因为它有一个 `subcategories` 字段，该字段是 `Category` 对象的数组。

**示例**（自引用模式）

```ts twoslash
import { Schema } from "effect"

// 定义一个带有递归子类别字段的 Category 模式
class Category extends Schema.Class<Category>("Category")({
  name: Schema.String,
  subcategories: Schema.Array(
    Schema.suspend((): Schema.Schema<Category> => Category)
  )
}) {}
```

<Aside type="note" title="正确推断">
  有必要添加显式类型注解，否则 TypeScript 将难以正确推断类型。如果没有此注解，您可能会遇到以下错误消息：
</Aside>

**示例**（缺少类型注解错误）

```ts twoslash
import { Schema } from "effect"

// @errors: 2506 7024
class Category extends Schema.Class<Category>("Category")({
  name: Schema.String,
  subcategories: Schema.Array(Schema.suspend(() => Category))
}) {}
```

### 互递归模式

有时，模式会以相互递归的方式相互依赖。例如，一个算术表达式树可能包含 `Expression` 节点，这些节点可以是数字或 `Operation` 节点，而 `Operation` 节点又引用 `Expression` 节点。

**示例**（算术表达式树）

```ts twoslash
import { Schema } from "effect"

class Expression extends Schema.Class<Expression>("Expression")({
  type: Schema.Literal("expression"),
  value: Schema.Union(
    Schema.Number,
    Schema.suspend((): Schema.Schema<Operation> => Operation)
  )
}) {}

class Operation extends Schema.Class<Operation>("Operation")({
  type: Schema.Literal("operation"),
  operator: Schema.Literal("+", "-"),
  left: Expression,
  right: Expression
}) {}
```

### 具有不同 Encoded 和 Type 的递归类型

定义 `Encoded` 类型与 `Type` 类型不同的递归模式会引入额外的复杂性。例如，如果某个模式包含转换数据的字段（例如 `NumberFromString`），`Encoded` 和 `Type` 类型可能不对齐。

在这种情况下，我们需要为 `Encoded` 类型定义一个接口。

让我们考虑一个示例：假设我们想向 `Category` 模式添加一个 `id` 字段，其中 `id` 的模式是 `NumberFromString`。需要注意的是，`NumberFromString` 是一个将字符串转换为数字的模式，因此 `NumberFromString` 的 `Type` 和 `Encoded` 类型不同，分别是 `number` 和 `string`。当我们将此字段添加到 `Category` 模式时，TypeScript 会引发错误：

```ts twoslash
import { Schema } from "effect"

class Category extends Schema.Class<Category>("Category")({
  id: Schema.NumberFromString,
  name: Schema.String,
  subcategories: Schema.Array(
// @errors: 2322
    Schema.suspend((): Schema.Schema<Category> => Category)
  )
}) {}
```

此错误发生是因为显式注解 `S.suspend((): S.Schema<Category> => Category` 已不再足够，需要通过显式添加 `Encoded` 类型进行调整：

**示例**（使用显式 `Encoded` 类型调整模式）

```ts twoslash
import { Schema } from "effect"

interface CategoryEncoded {
  readonly id: string
  readonly name: string
  readonly subcategories: ReadonlyArray<CategoryEncoded>
}

class Category extends Schema.Class<Category>("Category")({
  id: Schema.NumberFromString,
  name: Schema.String,
  subcategories: Schema.Array(
    Schema.suspend(
      (): Schema.Schema<Category, CategoryEncoded> => Category
    )
  )
}) {}
```

正如我们所见，有必要为模式的 `Encoded` 定义一个接口以启用递归模式定义，这可能会使事情复杂化并且相当繁琐。一种缓解这种情况的模式是**将负责递归的字段**与所有其他字段**分开**。

**示例**（分离递归字段）

```ts twoslash
import { Schema } from "effect"

const fields = {
  id: Schema.NumberFromString,
  name: Schema.String
  // ...可能还有其他字段
}

interface CategoryEncoded extends Schema.Struct.Encoded<typeof fields> {
  // 使用递归定义 `subcategories`
  readonly subcategories: ReadonlyArray<CategoryEncoded>
}

class Category extends Schema.Class<Category>("Category")({
  ...fields, // 包含字段
  subcategories: Schema.Array(
    // 使用递归定义 `subcategories`
    Schema.suspend(
      (): Schema.Schema<Category, CategoryEncoded> => Category
    )
  )
}) {}
```

## 标记类变体

您还可以创建扩展自 `effect/Data` 模块的 [TaggedClass](/docs/data-types/data/#taggedclass) 和 [TaggedError](/docs/data-types/data/#taggederror) 的类。

**示例**（创建标记类和错误）

```ts twoslash
import { Schema } from "effect"

// 定义一个带有 "name" 字段的标记类
class TaggedPerson extends Schema.TaggedClass<TaggedPerson>()(
  "TaggedPerson",
  {
    name: Schema.String
  }
) {}

// 定义一个带有 "status" 字段的标记错误
class HttpError extends Schema.TaggedError<HttpError>()("HttpError", {
  status: Schema.Number
}) {}

const joe = new TaggedPerson({ name: "Joe" })
console.log(joe._tag)
// 输出: "TaggedPerson"

const error = new HttpError({ status: 404 })
console.log(error._tag)
// 输出: "HttpError"

console.log(error.stack) // 访问堆栈跟踪
```

## 扩展现有类

`extend` 静态工具允许您通过添加**额外**的字段和功能来增强现有的 Schema 类。这种方法有助于在不从头重新定义的情况下，在现有模式的基础上进行构建。

**示例**（扩展 Schema 类）

```ts twoslash
import { Schema } from "effect"

// 定义基类
class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {
  // 将名称转换为大写的自定义 getter
  get upperName() {
    return this.name.toUpperCase()
  }
}

// 扩展基类以包含 "age" 字段
class PersonWithAge extends Person.extend<PersonWithAge>("PersonWithAge")(
  {
    age: Schema.Number
  }
) {
  // 检查该人是否成年人的自定义 getter
  get isAdult() {
    return this.age >= 18
  }
}

// 使用
const john = new PersonWithAge({ id: 1, name: "John", age: 25 })
console.log(john.upperName) // 输出: "JOHN"
console.log(john.isAdult) // 输出: true
```

请注意，扩展类时只能添加额外的字段。

**示例**（尝试覆盖现有字段）

```ts twoslash
import { Schema } from "effect"

class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.NonEmptyString
}) {
  get upperName() {
    return this.name.toUpperCase()
  }
}

class BadExtension extends Person.extend<BadExtension>("BadExtension")({
  name: Schema.Number
}) {}
/*
抛出:
Error: Duplicate property signature
details: Duplicate key "name"
*/
```

此错误发生是因为允许覆盖字段是不安全的。这可能会干扰类上依赖原始定义的任何 getter 或方法。例如，在这种情况下，如果 `name` 字段被更改为数字，`upperName` getter 将失效。

## 转换

您可以使用 effectful 转换来增强 Schema 类，以丰富或验证实体，特别是在处理来自外部系统（如数据库或 API）的数据时。

**示例**（Effectful 转换）

以下示例演示了向 `Person` 类添加 `age` 字段。`age` 值是基于 `id` 字段异步派生的。

```ts twoslash
import { Effect, Option, Schema, ParseResult } from "effect"

// 基类定义
class Person extends Schema.Class<Person>("Person")({
  id: Schema.Number,
  name: Schema.String
}) {}

console.log(Schema.decodeUnknownSync(Person)({ id: 1, name: "name" }))
/*
输出:
Person { id: 1, name: 'name' }
*/

// 模拟基于 id 异步获取年龄
function getAge(id: number): Effect.Effect<number, Error> {
  return Effect.succeed(id + 2)
}

// 带有转换的扩展类
class PersonWithTransform extends Person.transformOrFail<PersonWithTransform>(
  "PersonWithTransform"
)(
  {
    age: Schema.optionalWith(Schema.Number, { exact: true, as: "Option" })
  },
  {
    // 新字段的解码逻辑
    decode: (input) =>
      Effect.mapBoth(getAge(input.id), {
        onFailure: (e) =>
          new ParseResult.Type(Schema.String.ast, input.id, e.message),
        // 必须返回 { age: Option<number> }
        onSuccess: (age) => ({ ...input, age: Option.some(age) })
      }),
    encode: ParseResult.succeed
  }
) {}

Schema.decodeUnknownPromise(PersonWithTransform)({
  id: 1,
  name: "name"
}).then(console.log)
/*
输出:
PersonWithTransform {
  id: 1,
  name: 'name',
  age: { _id: 'Option', _tag: 'Some', value: 3 }
}
*/

// 带有条件转换的扩展类
class PersonWithTransformFrom extends Person.transformOrFailFrom<PersonWithTransformFrom>(
  "PersonWithTransformFrom"
)(
  {
    age: Schema.optionalWith(Schema.Number, { exact: true, as: "Option" })
  },
  {
    decode: (input) =>
      Effect.mapBoth(getAge(input.id), {
        onFailure: (e) =>
          new ParseResult.Type(Schema.String.ast, input, e.message),
        // 必须返回 { age?: number }
        onSuccess: (age) => (age > 18 ? { ...input, age } : { ...input })
      }),
    encode: ParseResult.succeed
  }
) {}

Schema.decodeUnknownPromise(PersonWithTransformFrom)({
  id: 1,
  name: "name"
}).then(console.log)
/*
输出:
PersonWithTransformFrom {
  id: 1,
  name: 'name',
  age: { _id: 'Option', _tag: 'None' }
}
*/
```

选择使用哪种 API（`transformOrFail` 或 `transformOrFailFrom`）取决于您希望何时执行转换：

1. 使用 `transformOrFail`：
   - 转换在过程结束时发生。
   - 它期望您提供一个类型为 `{ age: Option<number> }` 的值。
   - 在处理完初始输入后，新的转换开始生效，您需要确保最终输出符合指定的结构。

2. 使用 `transformOrFailFrom`：
   - 新的转换在处理初始输入后立即开始。
   - 您应该提供一个值 `{ age?: number }`。
   - 基于这个新输入，执行后续的转换 `Schema.optionalWith(Schema.Number, { exact: true, as: "Option" })`。
   - 这种方法允许立即处理输入，可能影响后续的转换。
