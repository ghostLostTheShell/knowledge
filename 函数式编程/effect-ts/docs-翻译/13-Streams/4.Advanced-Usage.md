**高级用法**

学习定义和扩展数据模式的高级技术，包括递归和互递归类型、可选字段、品牌类型和模式转换。

## 声明新的数据类型

### 原始数据类型

要为原始数据类型（如 `File`）声明模式，你可以使用 `Schema.declare` 函数以及一个类型守卫。

**示例**（为 `File` 声明模式）

```ts twoslash
import { Schema } from "effect"

// 使用类型守卫为 File 类型声明模式
const FileFromSelf = Schema.declare(
  (input: unknown): input is File => input instanceof File
)

const decode = Schema.decodeUnknownSync(FileFromSelf)

// 解码一个有效的 File 对象
console.log(decode(new File([], "")))
/*
输出:
File { size: 0, type: '', name: '', lastModified: 1724774163056 }
*/

// 解码无效输入
decode(null)
/*
抛出
ParseError: Expected <declaration schema>, actual null
*/
```

<Aside type="tip" title="添加注解">
  像 `identifier` 和 `description` 这样的注解对于改进错误消息和使模式具有自文档化非常有用。
</Aside>

为了增强默认错误消息，你可以添加注解，特别是 `identifier`、`title` 和 `description` 注解（这些注解都不是必需的，但为了良好的实践和使模式"自文档化"，建议使用）。这些注解将被消息系统用来返回更有意义的消息。

- **Identifier**：模式的唯一名称
- **Title**：一个简短、描述性的标题
- **Description**：对模式目的的详细解释

**示例**（使用注解声明模式）

```ts twoslash
import { Schema } from "effect"

// 为 File 类型声明模式并添加额外的注解
const FileFromSelf = Schema.declare(
  (input: unknown): input is File => input instanceof File,
  {
    // 模式的唯一标识符
    identifier: "FileFromSelf",
    // 模式的详细描述
    description: "The `File` type in JavaScript"
  }
)

const decode = Schema.decodeUnknownSync(FileFromSelf)

// 解码一个有效的 File 对象
console.log(decode(new File([], "")))
/*
输出:
File { size: 0, type: '', name: '', lastModified: 1724774163056 }
*/

// 解码无效输入
decode(null)
/*
抛出
ParseError: Expected FileFromSelf, actual null
*/
```

### 类型构造函数

类型构造函数是以一个或多个类型作为参数并返回一个新类型的泛型类型。要为类型构造函数定义模式，你可以使用 `Schema.declare` 函数。

**示例**（为 `ReadonlySet<A>` 声明模式）

```ts twoslash
import { ParseResult, Schema } from "effect"

export const MyReadonlySet = <A, I, R>(
  // Set 元素的模式
  item: Schema.Schema<A, I, R>
): Schema.Schema<ReadonlySet<A>, ReadonlySet<I>, R> =>
  Schema.declare(
    // 存储 Set 元素的模式
    [item],
    {
      // 解码函数
      decode: (item) => (input, parseOptions, ast) => {
        if (input instanceof Set) {
          // 解码 Set 中的每个元素
          const elements = ParseResult.decodeUnknown(Schema.Array(item))(
            Array.from(input.values()),
            parseOptions
          )
          // 返回包含解码后元素的 ReadonlySet
          return ParseResult.map(
            elements,
            (as): ReadonlySet<A> => new Set(as)
          )
        }
        // 处理无效输入
        return ParseResult.fail(new ParseResult.Type(ast, input))
      },
      // 编码函数
      encode: (item) => (input, parseOptions, ast) => {
        if (input instanceof Set) {
          // 编码 Set 中的每个元素
          const elements = ParseResult.encodeUnknown(Schema.Array(item))(
            Array.from(input.values()),
            parseOptions
          )
          // 返回包含编码后元素的 ReadonlySet
          return ParseResult.map(
            elements,
            (is): ReadonlySet<I> => new Set(is)
          )
        }
        // 处理无效输入
        return ParseResult.fail(new ParseResult.Type(ast, input))
      }
    },
    {
      description: `ReadonlySet<${Schema.format(item)}>`
    }
  )

// 为数字的 ReadonlySet 定义模式
const setOfNumbers = MyReadonlySet(Schema.NumberFromString)

const decode = Schema.decodeUnknownSync(setOfNumbers)

console.log(decode(new Set(["1", "2", "3"]))) // Set(3) { 1, 2, 3 }

// 解码无效输入
decode(null)
/*
抛出
ParseError: Expected ReadonlySet<NumberFromString>, actual null
*/

// 解码包含无效元素的 Set
decode(new Set(["1", null, "3"]))
/*
抛出
ParseError: ReadonlyArray<NumberFromString>
└─ [1]
   └─ NumberFromString
      └─ Encoded side transformation failure
         └─ Expected string, actual null
*/
```

<Aside type="caution" title="解码/编码限制">
  解码和编码函数不能依赖上下文（`Requirements` 类型参数），也不能处理异步效果。这意味着在这些函数中只支持同步操作。
</Aside>

### 添加编译器注解

在定义新的数据类型时，一些编译器如 [Arbitrary](/docs/schema/arbitrary/) 或 [Pretty](/docs/schema/pretty/) 可能不知道如何处理新类型。这可能导致错误，因为编译器可能缺乏生成实例或产生可读输出所需的信息：

**示例**（尝试在未添加所需注解的情况下生成 Arbitrary 值）

```ts twoslash
import { Arbitrary, Schema } from "effect"

// 为 File 类型定义模式
const FileFromSelf = Schema.declare(
  (input: unknown): input is File => input instanceof File,
  {
    identifier: "FileFromSelf"
  }
)

// 尝试为模式创建 Arbitrary 实例
const arb = Arbitrary.make(FileFromSelf)
/*
抛出:
Error: Missing annotation
details: Generating an Arbitrary for this schema requires an "arbitrary" annotation
schema (Declaration): FileFromSelf
*/
```

在上面的示例中，尝试为 `FileFromSelf` 模式生成任意值失败，因为编译器缺乏必要的注解。要解决这个问题，你需要为生成任意数据提供注解：

**示例**（为自定义 `File` 模式添加 Arbitrary 注解）

```ts twoslash
import { Arbitrary, FastCheck, Pretty, Schema } from "effect"

const FileFromSelf = Schema.declare(
  (input: unknown): input is File => input instanceof File,
  {
    identifier: "FileFromSelf",
    // 提供一个生成随机 File 实例的函数
    arbitrary: () => (fc) =>
      fc
        .tuple(fc.string(), fc.string())
        .map(([content, path]) => new File([content], path))
  }
)

// 为模式创建 Arbitrary 实例
const arb = Arbitrary.make(FileFromSelf)

// 使用 Arbitrary 实例生成示例文件
const files = FastCheck.sample(arb, 2)
console.log(files)
/*
示例输出:
[
  File { size: 5, type: '', name: 'C', lastModified: 1706435571176 },
  File { size: 1, type: '', name: '98Ggmc', lastModified: 1706435571176 }
]
*/
```

有关如何为 Arbitrary 编译器添加注解的更多详细信息，请参阅 [Arbitrary](/docs/schema/arbitrary/) 文档。

## 品牌类型

TypeScript 的类型系统是结构化的，这意味着任何在结构上等价的类型都被认为是相同的。当语义上不同的类型被视为相同时，这可能会导致问题。

**示例**（结构化类型问题）

```ts twoslash
type UserId = string
type Username = string

declare const getUser: (id: UserId) => object

const myUsername: Username = "gcanti"

getUser(myUsername) // 这错误地工作了
```

在上面的例子中，`UserId` 和 `Username` 都是同一类型 `string` 的别名。这意味着 `getUser` 函数可能错误地将 `Username` 接受为有效的 `UserId`，从而导致错误和 bug。

为了防止这种情况，Effect 引入了**品牌类型**。这些类型向类型附加一个唯一的标识符（或"品牌"），允许你区分结构相似但语义不同的类型。

**示例**（定义品牌类型）

```ts twoslash
import { Brand } from "effect"

type UserId = string & Brand.Brand<"UserId">
type Username = string

declare const getUser: (id: UserId) => object

const myUsername: Username = "gcanti"

// @errors: 2345
getUser(myUsername)
```

通过将 `UserId` 定义为品牌类型，`getUser` 函数只能接受 `UserId` 类型的值，而不能接受普通字符串或其他与字符串兼容的类型。这有助于防止因意外向函数传递错误类型的值而导致的错误。

有两种方式为品牌类型定义模式，具体取决于你是：

- 想要从头开始定义模式
- 已经通过 [`effect/Brand`](/docs/code-style/branded-types/) 定义了品牌类型，并希望重用它来定义模式

### 从头开始定义品牌模式

要从头开始为品牌类型定义模式，请使用 `Schema.brand` 函数。

**示例**（为品牌类型创建模式）

```ts twoslash
import { Schema } from "effect"

const UserId = Schema.String.pipe(Schema.brand("UserId"))

// string & Brand<"UserId">
type UserId = typeof UserId.Type
```

请注意，你可以使用 `unique symbol` 作为品牌，以确保跨模块/包的唯一性。

**示例**（使用唯一符号作为品牌）

```ts twoslash
import { Schema } from "effect"

const UserIdBrand: unique symbol = Symbol.for("UserId")

const UserId = Schema.String.pipe(Schema.brand(UserIdBrand))

// string & Brand<typeof UserIdBrand>
type UserId = typeof UserId.Type
```

### 重用现有的品牌构造函数

如果你已经使用 [`effect/Brand`](/docs/code-style/branded-types/) 模块定义了品牌类型，你可以使用 `Schema.fromBrand` 函数重用它来定义模式。

**示例**（重用现有的品牌类型）

```ts twoslash
import { Schema } from "effect"
import { Brand } from "effect"

// 现有的品牌类型
type UserId = string & Brand.Brand<"UserId">

const UserId = Brand.nominal<UserId>()

// 为品牌类型定义模式
const UserIdSchema = Schema.String.pipe(Schema.fromBrand(UserId))
```

### 使用默认构造函数

`Schema.brand` 函数包含一个默认构造函数，以方便创建品牌值。

```ts twoslash
import { Schema } from "effect"

const UserId = Schema.String.pipe(Schema.brand("UserId"))

const userId = UserId.make("123") // 创建一个品牌的 UserId
```

## 属性签名

`PropertySignature` 表示从"源"字段到"目标"字段的转换。这允许你定义传入数据字段与内部模型之间的映射。

### 基本用法

属性签名可以使用注解来定义，以提供关于字段的额外上下文。

**示例**（向属性签名添加注解）

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.propertySignature(Schema.NumberFromString).annotations({
    title: "Age" // 用于标记年龄字段的注解
  })
})
```

`PropertySignature` 类型包含几个参数，每个参数提供了关于源字段（From）和目标字段（To）之间转换的详细信息。让我们看看每个参数代表什么：

```ts showLineNumbers=false
age: PropertySignature<
  ToToken,
  ToType,
  FromKey,
  FromToken,
  FromType,
  HasDefault,
  Context
>
```

| 参数         | 描述                                                                                          |
| ------------ | --------------------------------------------------------------------------------------------- |
| `age`        | "目标"字段的键                                                                                |
| `ToToken`    | 表示字段要求：`"?:"` 表示可选，`":"` 表示必需                                                |
| `ToType`     | "目标"字段的类型                                                                              |
| `FromKey`    | （可选，默认 = `never`）表示源字段的键，通常与"目标"字段键相同，除非另有指定                |
| `FromToken`  | 表示源字段的要求：`"?:"` 表示可选，`":"` 表示必需                                             |
| `FromType`   | "源"字段的类型                                                                                |
| `HasDefault` | 表示是否有构造函数默认值（布尔值）                                                            |

在上面的例子中，`age` 的 `PropertySignature` 类型是：

```ts showLineNumbers=false
PropertySignature<":", number, never, ":", string, false, never>
```

这意味着：

| 参数         | 描述                                                  |
| ------------ | ----------------------------------------------------- |
| `age`        | "目标"字段的键                                        |
| `ToToken`    | `":"` 表示 `age` 字段是必需的                         |
| `ToType`     | `age` 字段的类型是 `number`                           |
| `FromKey`    | `never` 表示解码发生在同名的 `age` 字段               |
| `FromToken`  | `":"` 表示解码发生在一个必需的 `age` 字段             |
| `FromType`   | "源"字段的类型是 `string`                             |
| `HasDefault` | `false`：表示没有默认值                               |

有时，源字段（"源"字段）可能与内部模型中的字段名称不同。你可以使用 `Schema.fromKey` 函数在这些字段之间进行映射。

**示例**（从不同的键映射）

```ts twoslash
import { Schema } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.propertySignature(Schema.NumberFromString).pipe(
    Schema.fromKey("AGE") // 从 "AGE" 映射到 "age"
  )
})

console.log(Schema.decodeUnknownSync(Person)({ name: "name", AGE: "18" }))
// 输出: { name: 'name', age: 18 }
```

当你从 `"AGE"` 映射到 `"age"` 时，`PropertySignature` 类型会变为：

```ts showLineNumbers=false ""AGE"" del={1} ins={2}
PropertySignature<":", number, never, ":", string, false, never>
PropertySignature<":", number, "AGE", ":", string, false, never>
```

### 可选字段

#### 基本可选属性

语法：

```ts showLineNumbers=false
Schema.optional(schema: Schema<A, I, R>)
```

在模式中创建一个可选属性，允许字段被省略或设置为 `undefined`。

##### 解码

| 输入                 | 输出                      |
| -------------------- | ------------------------- |
| `<missing value>`    | 保持 `<missing value>`    |
| `undefined`          | 保持 `undefined`          |
| `i: I`               | 转换为 `a: A`             |

##### 编码

| 输入                 | 输出                      |
| -------------------- | ------------------------- |
| `<missing value>`    | 保持 `<missing value>`    |
| `undefined`          | 保持 `undefined`          |
| `a: A`               | 转换回 `i: I`             |

**示例**（定义可选数字字段）

```ts twoslash
import { Schema } from "effect"

const Product = Schema.Struct({
  quantity: Schema.optional(Schema.NumberFromString)
})

//     ┌─── { readonly quantity?: string | undefined; }
//     ▼
type Encoded = typeof Product.Encoded

//     ┌─── { readonly quantity?: number | undefined; }
//     ▼
type Type = typeof Product.Type

// 解码示例

console.log(Schema.decodeUnknownSync(Product)({ quantity: "1" }))
// 输出: { quantity: 1 }
console.log(Schema.decodeUnknownSync(Product)({}))
// 输出: {}
console.log(Schema.decodeUnknownSync(Product)({ quantity: undefined }))
// 输出: { quantity: undefined }

// 编码示例

console.log(Schema.encodeSync(Product)({ quantity: 1 }))
// 输出: { quantity: "1" }
console.log(Schema.encodeSync(Product)({}))
// 输出: {}
console.log(Schema.encodeSync(Product)({ quantity: undefined }))
// 输出: { quantity: undefined }
```

#### 可选与精确性

语法：


| 输入                 | 输出                      |

### 默认值

`Schema.optionalWith` 中的 `default` 选项允许你设置在解码和对象构造阶段应用的默认值。此功能确保即使用户没有提供某些属性，系统也会自动使用指定的默认值。

## 可选字段原语

### optionalToOptional

`Schema.optionalToOptional` API 允许你管理从输入中的可选字段到输出中的可选字段的转换。这对于控制输出类型以及根据特定标准判断字段是否存在非常有用。

`optionalToOptional` 的一个常见用例是处理输入中的特定值（如空字符串）应被视为输出中的缺失字段的情况。

**语法**

```ts showLineNumbers=false
const optionalToOptional = <FA, FI, FR, TA, TI, TR>(
  from: Schema<FA, FI, FR>,
  to: Schema<TA, TI, TR>,
  options: {
    readonly decode: (o: Option.Option<FA>) => Option.Option<TI>,
    readonly encode: (o: Option.Option<TI>) => Option.Option<FA>
  }
): PropertySignature<"?:", TA, never, "?:", FI, false, FR | TR>
```

在此函数中：

- `from` 参数指定输入模式，`to` 指定输出模式。
- `decode` 和 `encode` 函数定义了如何解释两侧的字段：
  - 作为输入参数的 `Option.none()` 表示输入中缺失的字段。
  - 从任一函数返回 `Option.none()` 将省略输出中的字段。

**示例**（从输出中省略空字符串）

考虑一个类型为 `string` 的可选字段，其中输入中的空字符串应从输出中移除。

```ts twoslash
import { Option, Schema } from "effect"

const schema = Schema.Struct({
  nonEmpty: Schema.optionalToOptional(Schema.String, Schema.String, {
    //         ┌─── Option<string>
    //         ▼
    decode: (maybeString) => {
      if (Option.isNone(maybeString)) {
        // 如果 `maybeString` 是 `None`，则输入中字段缺失。
        // 返回 Option.none() 以在输出中省略它。
        return Option.none()
      }
      // 从 `Some` 实例中提取值
      const value = maybeString.value
      if (value === "") {
        // 将空字符串视为输出中缺失
        // 通过返回 Option.none()。
        return Option.none()
      }
      // 在输出中包含非空字符串。
      return Option.some(value)
    },
    // 在编码阶段，你可以决定以类似于解码阶段的方式处理字段，
    // 或使用不同的逻辑。
    // 这里，逻辑保持不变。
    //
    //         ┌─── Option<string>
    //         ▼
    encode: (maybeString) => maybeString
  })
})

// 解码示例

const decode = Schema.decodeUnknownSync(schema)

console.log(decode({}))
// 输出: {}
console.log(decode({ nonEmpty: "" }))
// 输出: {}
console.log(decode({ nonEmpty: "a non-empty string" }))
// 输出: { nonEmpty: 'a non-empty string' }

// 编码示例

const encode = Schema.encodeSync(schema)

console.log(encode({}))
// 输出: {}
console.log(encode({ nonEmpty: "" }))
// 输出: { nonEmpty: '' }
console.log(encode({ nonEmpty: "a non-empty string" }))
// 输出: { nonEmpty: 'a non-empty string' }
```

你可以使用 `Option.filter` 简化解码逻辑，它以简洁的方式过滤掉不需要的值。

**示例**（使用 `Option.filter` 进行解码）

```ts twoslash
import { identity, Option, Schema } from "effect"

const schema = Schema.Struct({
  nonEmpty: Schema.optionalToOptional(Schema.String, Schema.String, {
    decode: Option.filter((s) => s !== ""),
    encode: identity
  })
})
```

```ts showLineNumbers=false
  options: {
    readonly decode: (o: Option.Option<FA>) => TI,
    readonly encode: (ti: TI) => Option.Option<FA>
  }
): PropertySignature<":", TA, never, "?:", FI, false, FR | TR>
```

在此函数中：

- `from` 指定输入模式，`to` 指定输出模式。
- `decode` 和 `encode` 函数定义了转换行为：
  - 向 `decode` 传递 `Option.none()` 表示输入中字段缺失。然后该函数可以为输出返回一个默认值。
  - 在 `encode` 中返回 `Option.none()` 将省略输出中的字段。

**示例**（为缺失字段设置 `null` 作为默认值）

此示例演示了如何使用 `optionalToRequired` 在输入中缺少 `nullable` 字段时提供 `null` 默认值。在编码期间，值为 `null` 的字段将从输出中省略。

```ts twoslash
import { Option, Schema } from "effect"

const schema = Schema.Struct({
  nullable: Schema.optionalToRequired(
    // 可选字符串的输入模式
    Schema.String,
    // 允许 null 或字符串的输出模式
    Schema.NullOr(Schema.String),
    {
      //         ┌─── Option<string>
      //         ▼
      decode: (maybeString) => {
        if (Option.isNone(maybeString)) {
          // 如果 `maybeString` 是 `None`，则输入中字段缺失。
          // 为输出返回 `null` 作为默认值。
          return null
        }
        // 从 `Some` 实例中提取值
        // 并将其用作输出。
        return maybeString.value
      },
      // 在编码期间，将 `null` 视为缺失字段
      //
      //         ┌─── string | null
      //         ▼
      encode: (stringOrNull) =>
        stringOrNull === null
          ? // 通过返回 `None` 省略字段
            Option.none()
          : // 通过返回 `Some` 包含字段
            Option.some(stringOrNull)
    }
  )
})

// 解码示例

const decode = Schema.decodeUnknownSync(schema)

console.log(decode({}))
// 输出: { nullable: null }
console.log(decode({ nullable: "a value" }))
// 输出: { nullable: 'a value' }

// 编码示例

const encode = Schema.encodeSync(schema)

console.log(encode({ nullable: "a value" }))
// 输出: { nullable: 'a value' }
console.log(encode({ nullable: null }))
// 输出: {}
```

你可以使用 `Option.getOrElse` 和 `Option.liftPredicate` 简化编解码逻辑，实现简洁且可读的转换。

**示例**（使用 `Option.getOrElse` 和 `Option.liftPredicate`）

```ts twoslash
import { Option, Schema } from "effect"

const schema = Schema.Struct({
  nullable: Schema.optionalToRequired(
    Schema.String,
    Schema.NullOr(Schema.String),
    {
      decode: Option.getOrElse(() => null),
      encode: Option.liftPredicate((value) => value !== null)
    }
  )
})
```

### requiredToOptional

`requiredToOptional` API 允许你将一个必需字段转换为可选字段，应用自定义逻辑来确定何时可以省略该字段。

**语法**

```ts showLineNumbers=false
const requiredToOptional = <FA, FI, FR, TA, TI, TR>(
  from: Schema<FA, FI, FR>,
  to: Schema<TA, TI, TR>,
  options: {
    readonly decode: (fa: FA) => Option.Option<TI>
    readonly encode: (o: Option.Option<TI>) => FA
  }
): PropertySignature<"?:", TA, never, ":", FI, false, FR | TR>
```

通过 `decode` 和 `encode` 函数，你可以控制字段的存在或缺失：

- `decode` 中的 `Option.none()` 作为参数表示输入中字段缺失。
- `encode` 中返回 `Option.none()` 表示输出中将省略该字段。

**示例**（将空字符串视为缺失值）

在此示例中，`name` 字段是必需的，但如果它是空字符串，则被视为可选。在解码期间，`name` 中的空字符串被视为缺失，而编码确保有一个值（如果 `name` 缺失，则使用空字符串作为默认值）。

```ts twoslash
import { Option, Schema } from "effect"

const schema = Schema.Struct({
  name: Schema.requiredToOptional(Schema.String, Schema.String, {
    //         ┌─── string
    //         ▼
    decode: (string) => {
      // 将空字符串视为缺失值
      if (string === "") {
        // 通过返回 `None` 省略字段
        return Option.none()
      }
      // 否则，按原样返回字符串
      return Option.some(string)
    },
    //         ┌─── Option<string>
    //         ▼
    encode: (maybeString) => {
      // 检查字段是否缺失
      if (Option.isNone(maybeString)) {
        // 提供空字符串作为默认值
        return ""
      }
      // 否则，按原样返回字符串
      return maybeString.value
    }
  })
})

// 解码示例

const decode = Schema.decodeUnknownSync(schema)

console.log(decode({ name: "John" }))
// 输出: { name: 'John' }
console.log(decode({ name: "" }))
// 输出: {}

// 编码示例

const encode = Schema.encodeSync(schema)

console.log(encode({ name: "John" }))
// 输出: { name: 'John' }
console.log(encode({}))
// 输出: { name: '' }
```

你可以使用 `Option.liftPredicate` 和 `Option.getOrElse` 简化编解码逻辑，实现简洁且可读的转换。

**示例**（使用 `Option.liftPredicate` 和 `Option.getOrElse`）

```ts twoslash
import { Option, Schema } from "effect"

const schema = Schema.Struct({
  name: Schema.requiredToOptional(Schema.String, Schema.String, {
    decode: Option.liftPredicate((s) => s !== ""),
    encode: Option.getOrElse(() => "")
  })
})
```

## 扩展模式

`effect` 中的模式可以通过多种方式进行扩展，允许你通过添加额外字段或功能来组合或增强现有类型。一种常见的方法是使用 `Struct` 模式中可用的 `fields` 属性。此属性提供了一种便捷的方式来添加字段或合并来自不同结构体的字段，同时保留原始的 `Struct` 类型。这种方法也使得访问和修改字段更加容易。

对于更复杂的情况，例如用联合类型扩展结构体，你可能希望使用 `Schema.extend` 函数，它在直接字段扩展可能不足的情况下提供了灵活性。

<Aside type="tip" title="通过字段扩展保留 Struct 类型">
  通过使用 `...Struct.fields` 进行字段扩展，你可以保持模式的 `Struct` 类型，从而允许继续访问 `fields` 属性以进行进一步修改。
</Aside>

### 扩展 Struct 字段

结构体通过 `fields` 属性提供对其字段的访问，这允许你通过添加额外字段或合并多个结构体的字段来扩展现有结构体。

**示例**（添加新字段）

```ts twoslash
import { Schema } from "effect"

const Original = Schema.Struct({
  a: Schema.String,
  b: Schema.String
})

const Extended = Schema.Struct({
  ...Original.fields,
  // 添加新字段
  c: Schema.String,
  d: Schema.String
})

//     ┌─── {
//     |      readonly a: string;
//     |      readonly b: string;
//     |      readonly c: string;
//     |      readonly d: string;
//     |    }
//     ▼
type Type = typeof Extended.Type
```

**示例**（添加额外的索引签名）

```ts twoslash
import { Schema } from "effect"

const Original = Schema.Struct({
  a: Schema.String,
  b: Schema.String
})

const Extended = Schema.Struct(
  Original.fields,
  // 添加索引签名
  Schema.Record({ key: Schema.String, value: Schema.String })
)

//     ┌─── {
//     │      readonly [x: string]: string;
//     |      readonly a: string;
//     |      readonly b: string;
//     |    }
//     ▼
type Type = typeof Extended.Type
```

**示例**（合并多个结构体的字段）

```ts twoslash
import { Schema } from "effect"

const Struct1 = Schema.Struct({
  a: Schema.String,
  b: Schema.String
})

const Struct2 = Schema.Struct({
  c: Schema.String,
  d: Schema.String
})

const Extended = Schema.Struct({
  ...Struct1.fields,
  ...Struct2.fields
})

//     ┌─── {
//     |      readonly a: string;
//     |      readonly b: string;
//     |      readonly c: string;
//     |      readonly d: string;
//     |    }
//     ▼
type Type = typeof Extended.Type
```

### extend 函数

`Schema.extend` 函数提供了一种结构化的方法来扩展模式，当直接的[字段扩展](#spreading-struct-fields)不够用时特别有用——例如当你需要用其他结构体的联合来扩展一个结构体时。

<Aside type="caution" title="扩展支持限制">
  并非所有扩展都受支持，兼容性取决于扩展中涉及的模式类型。
</Aside>

支持的扩展包括：

- `Schema.String` 与另一个 `Schema.String` 的精炼或字符串字面量
- `Schema.Number` 与另一个 `Schema.Number` 的精炼或数字字面量
- `Schema.Boolean` 与另一个 `Schema.Boolean` 的精炼或布尔字面量
- 一个结构体与另一个字段重叠支持扩展的结构体
- 一个带有索引签名的结构体
- 一个带有受支持模式联合的结构体
- 一个结构体的精炼与受支持的模式
- 一个结构体的 `suspend` 与受支持的模式
- 结构体之间的转换，其中"源"和"目标"方与目标结构体没有重叠字段

**示例**（用结构体的联合扩展结构体）

```ts twoslash
import { Schema } from "effect"

const Struct = Schema.Struct({
  a: Schema.String
})

const UnionOfStructs = Schema.Union(
  Schema.Struct({ b: Schema.String }),
  Schema.Struct({ c: Schema.String })
)

const Extended = Schema.extend(Struct, UnionOfStructs)

//     ┌─── {
//     |        readonly a: string;
//     |    } & ({
//     |        readonly b: string;
//     |    } | {
//     |        readonly c: string;
//     |    })
//     ▼
type Type = typeof Extended.Type
```

**示例**（尝试用冲突字段扩展结构体）

此示例演示了尝试用另一个包含重叠字段名称的结构体扩展结构体，由于类型冲突而导致错误。

```ts twoslash
import { Schema } from "effect"

const Struct = Schema.Struct({
  a: Schema.String
})

const OverlappingUnion = Schema.Union(
  Schema.Struct({ a: Schema.Number }), // 键 "a" 的类型冲突
  Schema.Struct({ d: Schema.String })
)

const Extended = Schema.extend(Struct, OverlappingUnion)
/*
抛出:
Error: Unsupported schema or overlapping types
at path: ["a"]
details: cannot extend string with number
*/
```

**示例**（用另一个精炼扩展一个精炼）

在此示例中，我们扩展了两个精炼 `Integer` 和 `Positive`，创建了一个同时强制整数和正数约束的模式。

```ts twoslash
import { Schema } from "effect"

const Integer = Schema.Int.pipe(Schema.brand("Int"))
const Positive = Schema.Positive.pipe(Schema.brand("Positive"))

//      ┌─── Schema<number & Brand<"Positive"> & Brand<"Int">, number, never>
//      ▼
const PositiveInteger = Schema.asSchema(Schema.extend(Positive, Integer))

Schema.decodeUnknownSync(PositiveInteger)(-1)
/*
抛出
ParseError: positive & Brand<"Positive"> & int & Brand<"Int">
└─ From side refinement failure
   └─ positive & Brand<"Positive">
      └─ Predicate refinement failure
         └─ Expected a positive number, actual -1
*/

Schema.decodeUnknownSync(PositiveInteger)(1.1)
/*
抛出
ParseError: positive & Brand<"Positive"> & int & Brand<"Int">
└─ Predicate refinement failure
   └─ Expected an integer, actual 1.1
*/
```

## 重命名属性

### 在定义期间重命名属性

要在模式创建期间直接重命名属性，你可以使用 `Schema.fromKey` 函数。

**示例**（重命名必需属性）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Struct({
  a: Schema.propertySignature(Schema.String).pipe(Schema.fromKey("c")),
  b: Schema.Number
})

//     ┌─── { readonly c: string; readonly b: number; }
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── { readonly a: string; readonly b: number; }
//     ▼
type Type = typeof schema.Type

console.log(Schema.decodeUnknownSync(schema)({ c: "c", b: 1 }))
// 输出: { a: "c", b: 1 }
```

**示例**（重命名可选属性）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Struct({
  a: Schema.optional(Schema.String).pipe(Schema.fromKey("c")),
  b: Schema.Number
})

//     ┌─── { readonly b: number; readonly c?: string | undefined; }
//     ▼
type Encoded = typeof schema.Encoded

//     ┌─── { readonly a?: string | undefined; readonly b: number; }
//     ▼
type Type = typeof schema.Type

console.log(Schema.decodeUnknownSync(schema)({ c: "c", b: 1 }))
// 输出: { a: 'c', b: 1 }

console.log(Schema.decodeUnknownSync(schema)({ b: 1 }))
// 输出: { b: 1 }
```

使用 `Schema.optional` 会自动返回一个 `PropertySignature`，因此不需要像上一个示例中重命名必需字段那样显式使用 `Schema.propertySignature`。

### 重命名现有模式的属性

对于现有模式，`Schema.rename` API 提供了一种系统性地更改模式中属性名称的方法，即使在像联合这样的复杂结构中也是如此，尽管对于结构体，你会失去原始字段类型。

**示例**（在结构体模式中重命名属性）

```ts twoslash
import { Schema } from "effect"

const Original = Schema.Struct({
  c: Schema.String,
  b: Schema.Number
})

// 将 "c" 属性重命名为 "a"
//
//
//      ┌─── SchemaClass<{
//      |      readonly a: string;
//      |      readonly b: number;
//      |    }>
//      ▼
const Renamed = Schema.rename(Original, { c: "a" })

console.log(Schema.decodeUnknownSync(Renamed)({ c: "c", b: 1 }))
// 输出: { a: "c", b: 1 }
```

**示例**（在联合模式中重命名属性）

```ts twoslash
import { Schema } from "effect"

const Original = Schema.Union(
  Schema.Struct({
    c: Schema.String,
    b: Schema.Number
  }),
  Schema.Struct({
    c: Schema.String,
    d: Schema.Boolean
  })
)

// 为所有成员将 "c" 属性重命名为 "a"
//
//      ┌─── SchemaClass<{
//      |      readonly a: string;
//      |      readonly b: number;
//      |    } | {
//      |      readonly a: string;
//      |      readonly d: number;
//      |    }>
//      ▼
const Renamed = Schema.rename(Original, { c: "a" })

console.log(Schema.decodeUnknownSync(Renamed)({ c: "c", b: 1 }))
// 输出: { a: "c", b: 1 }

console.log(Schema.decodeUnknownSync(Renamed)({ c: "c", d: false }))
// 输出: { a: 'c', d: false }
```

## 递归模式

`Schema.suspend` 函数旨在定义引用自身的模式，例如在递归数据结构中。

**示例**（自引用模式）

在此示例中，`Category` 模式通过 `subcategories` 字段引用自身，该字段是 `Category` 对象的数组。

```ts twoslash
import { Schema } from "effect"

interface Category {
  readonly name: string
  readonly subcategories: ReadonlyArray<Category>
}

const Category = Schema.Struct({
  name: Schema.String,
  subcategories: Schema.Array(
    Schema.suspend((): Schema.Schema<Category> => Category)
  )
})
```

<Aside type="note" title="正确推断">
  有必要定义 `Category` 类型并添加显式类型注解，否则 TypeScript 将难以正确推断类型。如果没有此注解，你可能会遇到错误消息：
</Aside>

**示例**（类型推断错误）

```ts twoslash
import { Schema } from "effect"

// @errors: 7022
const Category = Schema.Struct({
  name: Schema.String,
// @errors: 7022 7024
  subcategories: Schema.Array(Schema.suspend(() => Category))
})
```

### 简化模式定义的有用模式

正如我们所见，有必要为模式的 `Type` 定义一个接口以启用递归模式定义，这可能会使事情复杂化并且相当繁琐。
一种缓解这种情况的模式是**将负责递归的字段**与所有其他字段**分开**。

**示例**（分离递归字段）

```ts twoslash
import { Schema } from "effect"

const fields = {
  name: Schema.String
  // ...根据需要添加其他字段
}

// 为 Category 模式定义一个接口，
// 扩展已定义字段的 Type
interface Category extends Schema.Struct.Type<typeof fields> {
  // 使用递归定义 `subcategories`
  readonly subcategories: ReadonlyArray<Category>
}

const Category = Schema.Struct({
  ...fields, // 展开基础字段
  subcategories: Schema.Array(
    // 使用递归定义 `subcategories`
    Schema.suspend((): Schema.Schema<Category> => Category)
  )
})
```

### 互递归模式

你也可以使用 `Schema.suspend` 来创建互递归模式，其中两个模式相互引用。在以下示例中，`Expression` 和 `Operation` 通过相互引用形成了一个简单的算术表达式树。

**示例**（定义互递归模式）

```ts twoslash
import { Schema } from "effect"

interface Expression {
  readonly type: "expression"
  readonly value: number | Operation
}

interface Operation {
  readonly type: "operation"
  readonly operator: "+" | "-"
  readonly left: Expression
  readonly right: Expression
}

const Expression = Schema.Struct({
  type: Schema.Literal("expression"),
  value: Schema.Union(
    Schema.Number,
    Schema.suspend((): Schema.Schema<Operation> => Operation)
  )
})

const Operation = Schema.Struct({
  type: Schema.Literal("operation"),
  operator: Schema.Literal("+", "-"),
  left: Expression,
  right: Expression
})
```

### 具有不同 Encoded 和 Type 的递归类型

定义一个递归模式，其中 `Encoded` 类型与 `Type` 类型不同，会增加另一层复杂性。在这种情况下，我们需要定义两个接口：一个用于 `Type` 类型（如前所述），另一个用于 `Encoded` 类型。

**示例**（具有不同 Encoded 和 Type 定义的递归模式）

让我们考虑一个示例：假设我们想向 `Category` 模式添加一个 `id` 字段，其中 `id` 的模式是 `NumberFromString`。需要注意的是，`NumberFromString` 是一个将字符串转换为数字的模式，因此 `NumberFromString` 的 `Type` 和 `Encoded` 类型不同，分别是 `number` 和 `string`。当我们将此字段添加到 `Category` 模式时，TypeScript 会引发错误：

```ts twoslash
import { Schema } from "effect"

const fields = {
  id: Schema.NumberFromString,
  name: Schema.String
}

interface Category extends Schema.Struct.Type<typeof fields> {
  readonly subcategories: ReadonlyArray<Category>
}

const Category = Schema.Struct({
  ...fields,
  subcategories: Schema.Array(
// @errors: 2322
    Schema.suspend((): Schema.Schema<Category> => Category)
  )
})
```

此错误发生是因为显式注解 `Schema.Schema<Category>` 已不再足够，需要通过显式添加 `Encoded` 类型进行调整：

```ts twoslash
import { Schema } from "effect"

const fields = {
  id: Schema.NumberFromString,
  name: Schema.String
}

interface Category extends Schema.Struct.Type<typeof fields> {
  readonly subcategories: ReadonlyArray<Category>
}

interface CategoryEncoded extends Schema.Struct.Encoded<typeof fields> {
  readonly subcategories: ReadonlyArray<CategoryEncoded>
}

const Category = Schema.Struct({
  ...fields,
  subcategories: Schema.Array(
    Schema.suspend(
      (): Schema.Schema<Category, CategoryEncoded> => Category
    )
  )
})
```
