在处理 Effect Schema 时，解码或编码操作期间遇到的错误可以使用两种内置方法进行格式化：`TreeFormatter` 和 `ArrayFormatter`。这些格式化器有助于以可读且可操作的方式组织和呈现错误。

## TreeFormatter（默认）

`TreeFormatter` 是格式化错误的默认方法。它以树形结构组织错误，提供清晰的问题层次结构。

**示例**（解码时缺少属性）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

const decode = Schema.decodeUnknownEither(Person)

const result = decode({})
if (Either.isLeft(result)) {
  console.error("解码失败:")
  console.error(ParseResult.TreeFormatter.formatErrorSync(result.left))
}
/*
解码失败:
{ readonly name: string; readonly age: number }
└─ ["name"]
   └─ is missing
*/
```

在此示例中：

- `{ readonly name: string; readonly age: number }` 描述了模式期望的结构。
- `["name"]` 标识了导致错误的具体字段。
- `is missing` 解释了 `"name"` 字段的问题。

### 自定义输出

您可以通过使用 `identifier`、`title` 或 `description` 等注解来注解模式，使错误输出更简洁、更有意义。这些注解会替换错误消息中默认的类似 TypeScript 的表示形式。

**示例**（使用 `title` 注解提高清晰度）

添加 `title` 注解会将错误消息中的模式结构替换为更易读的 "Person"，使其更易于理解。

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
}).annotations({ title: "Person" }) // 添加标题注解

const result = Schema.decodeUnknownEither(Person)({})
if (Either.isLeft(result)) {
  console.error(ParseResult.TreeFormatter.formatErrorSync(result.left))
}
/*
Person
└─ ["name"]
   └─ is missing
*/
```

### 处理多个错误

默认情况下，像 `Schema.decodeUnknownEither` 这样的解码函数只报告第一个错误。要列出所有错误，请使用 `{ errors: "all" }` 选项。

**示例**（列出所有错误）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

const decode = Schema.decodeUnknownEither(Person, { errors: "all" })

const result = decode({})
if (Either.isLeft(result)) {
  console.error("解码失败:")
  console.error(ParseResult.TreeFormatter.formatErrorSync(result.left))
}
/*
解码失败:
{ readonly name: string; readonly age: number }
├─ ["name"]
│  └─ is missing
└─ ["age"]
   └─ is missing
*/
```

### ParseIssueTitle 注解

`parseIssueTitle` 注解允许您通过根据正在验证的值生成标题来向错误消息添加上下文。例如，它可以包含已验证对象的 ID，从而更容易识别复杂或嵌套数据结构中的特定问题。

**注解类型**

```ts
export type ParseIssueTitleAnnotation = (
  issue: ParseIssue
) => string | undefined
```

**返回值**：

- 如果函数返回一个 `string`，`TreeFormatter` 会将其用作标题，除非存在 `message` 注解（后者优先）。
- 如果函数返回 `undefined`，`TreeFormatter` 根据以下优先级确定标题：
  1. `identifier` 注解
  2. `title` 注解
  3. `description` 注解
  4. 默认的类似 TypeScript 的模式表示形式

**示例**（使用 `parseIssueTitle` 生成动态标题）

```ts twoslash
import type { ParseResult } from "effect"
import { Schema } from "effect"

// 为 OrderItem 问题生成标题的函数
const getOrderItemId = ({ actual }: ParseResult.ParseIssue) => {
  if (Schema.is(Schema.Struct({ id: Schema.String }))(actual)) {
    return `OrderItem with id: ${actual.id}`
  }
}

const OrderItem = Schema.Struct({
  id: Schema.String,
  name: Schema.String,
  price: Schema.Number
}).annotations({
  identifier: "OrderItem",
  parseIssueTitle: getOrderItemId
})

// 为 Order 问题生成标题的函数
const getOrderId = ({ actual }: ParseResult.ParseIssue) => {
  if (Schema.is(Schema.Struct({ id: Schema.Number }))(actual)) {
    return `Order with id: ${actual.id}`
  }
}

const Order = Schema.Struct({
  id: Schema.Number,
  name: Schema.String,
  items: Schema.Array(OrderItem)
}).annotations({
  identifier: "Order",
  parseIssueTitle: getOrderId
})

const decode = Schema.decodeUnknownSync(Order, { errors: "all" })

// 情况 1：没有可用的 id，使用 `identifier` 注解
decode({})
/*
抛出
ParseError: Order
├─ ["id"]
│  └─ is missing
├─ ["name"]
│  └─ is missing
└─ ["items"]
   └─ is missing
*/

// 情况 2：存在 ID，使用动态的 `parseIssueTitle` 注解
decode({ id: 1 })
/*
抛出
ParseError: Order with id: 1
├─ ["name"]
│  └─ is missing
└─ ["items"]
   └─ is missing
*/

// 情况 3：嵌套问题，Order 和 OrderItem 都有 ID
decode({ id: 1, items: [{ id: "22b", price: "100" }] })
/*
抛出
ParseError: Order with id: 1
├─ ["name"]
│  └─ is missing
└─ ["items"]
   └─ ReadonlyArray<OrderItem>
      └─ [0]
         └─ OrderItem with id: 22b
            ├─ ["name"]
            │  └─ is missing
            └─ ["price"]
               └─ Expected a number, actual "100"
*/
```

## ArrayFormatter

`ArrayFormatter` 提供了一种结构化的、基于数组的方法来格式化错误。它将每个错误表示为一个对象，使得在数据解码或编码期间分析和处理多个问题更加容易。每个错误对象都包含 `_tag`、`path` 和 `message` 等属性，以提高清晰度。

**示例**（数组格式的单个错误）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

const decode = Schema.decodeUnknownEither(Person)

const result = decode({})
if (Either.isLeft(result)) {
  console.error("解码失败:")
  console.error(ParseResult.ArrayFormatter.formatErrorSync(result.left))
}
/*
解码失败:
[ { _tag: 'Missing', path: [ 'name' ], message: 'is missing' } ]
*/
```

在此示例中：

- `_tag`：指示错误的类型（`Missing`）。
- `path`：指定数据中错误的位置（`['name']`）。
- `message`：描述问题（`'is missing'`）。

### 处理多个错误

默认情况下，像 `Schema.decodeUnknownEither` 这样的解码函数只报告第一个错误。要列出所有错误，请使用 `{ errors: "all" }` 选项。

**示例**（列出所有错误）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Person = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

const decode = Schema.decodeUnknownEither(Person, { errors: "all" })

const result = decode({})
if (Either.isLeft(result)) {
  console.error("解码失败:")
  console.error(ParseResult.ArrayFormatter.formatErrorSync(result.left))
}
/*
解码失败:
[
  { _tag: 'Missing', path: [ 'name' ], message: 'is missing' },
  { _tag: 'Missing', path: [ 'age' ], message: 'is missing' }
]
*/
```

## React Hook Form

如果您正在使用 React 并且需要表单验证，`@hookform/resolvers` 为 `effect/Schema` 提供了一个适配器，可以与 React Hook Form 集成以增强表单验证过程。这种集成允许您在 React 应用程序中利用 `effect/Schema` 的强大功能。

有关如何使用 `@hookform/resolvers` 将 `effect/Schema` 与 React Hook Form 集成的更详细说明和示例，您可以访问官方 npm 包页面：
