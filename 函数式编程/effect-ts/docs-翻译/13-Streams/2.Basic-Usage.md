**基础用法**

学习定义和使用基础模式，包括原始类型、字面量、联合类型和结构体，以实现有效的数据验证和转换。

## 原始类型

Schema 模块为常见的原始类型提供了内置模式。

| Schema | 等效 TypeScript 类型 |
| ------ | ------------------- |
| `Schema.String` | `string` |
| `Schema.Number` | `number` |
| `Schema.Boolean` | `boolean` |
| `Schema.BigIntFromSelf` | `BigInt` |
| `Schema.SymbolFromSelf` | `symbol` |
| `Schema.Object` | `object` |
| `Schema.Undefined` | `undefined` |
| `Schema.Void` | `void` |
| `Schema.Any` | `any` |
| `Schema.Unknown` | `unknown` |
| `Schema.Never` | `never` |

**示例**（使用原始类型模式）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.String

// 推断类型为 string
//
//     ┌─── string
//     ▼
type Type = typeof schema.Type

// 尝试解码一个 null 值，会抛出解析错误
Schema.decodeUnknownSync(schema)(null)
/*
抛出:
ParseError: Expected string, actual null
*/
```

## asSchema

为了更容易处理模式，内置模式在可能的情况下以更短的不透明类型暴露。

`Schema.asSchema` 函数允许你将任何模式视为 `Schema<Type, Encoded, Context>`。

**示例**（使用 `asSchema` 展开模式）

例如，虽然 `Schema.String` 被定义为一个类型为 `typeof Schema.String` 的类，但使用 `Schema.asSchema` 会提供其展开形式 `Schema<string, string, never>`。

```ts twoslash
import { Schema } from "effect"

//     ┌─── typeof Schema.String
//     ▼
const schema = Schema.String

//     ┌─── Schema<string, string, never>
//     ▼
const nomalized = Schema.asSchema(schema)
```

## 唯一符号

你可以使用 `Schema.UniqueSymbolFromSelf` 为唯一符号创建模式。

**示例**（为唯一符号创建模式）

```ts twoslash
import { Schema } from "effect"

const mySymbol = Symbol.for("mySymbol")

const schema = Schema.UniqueSymbolFromSelf(mySymbol)

//     ┌─── typeof mySymbol
//     ▼
type Type = typeof schema.Type

Schema.decodeUnknownSync(schema)(null)
/*
抛出:
ParseError: Expected Symbol(mySymbol), actual null
*/
```

## 字面量

字面量模式表示[字面量类型](https://www.typescriptlang.org/docs/handbook/2/everyday-types.html#literal-types)。你可以使用它们来指定类型必须具有的确切值。

字面量可以是以下类型：

- `string`
- `number`
- `boolean`
- `null`
- `bigint`

**示例**（定义字面量模式）

```ts twoslash
import { Schema } from "effect"

// 定义各种字面量模式
Schema.Null // 等同于 S.Literal(null)
Schema.Literal("a") // 字符串字面量
Schema.Literal(1) // 数字字面量
Schema.Literal(true) // 布尔字面量
Schema.Literal(2n) // BigInt 字面量
```

**示例**（为 `"a"` 定义字面量模式）

```ts twoslash
import { Schema } from "effect"

//     ┌─── Literal<["a"]>
//     ▼
const schema = Schema.Literal("a")

//     ┌─── "a"
//     ▼
type Type = typeof schema.Type

console.log(Schema.decodeUnknownSync(schema)("a"))
// 输出: "a"

console.log(Schema.decodeUnknownSync(schema)("b"))
/*
抛出:
ParseError: Expected "a", actual "b"
*/
```

### 字面量联合

你可以通过向 `Schema.Literal` 构造函数传递多个字面量参数来创建多个字面量的联合：

**示例**（定义字面量联合）

```ts twoslash
import { Schema } from "effect"

//     ┌─── Literal<["a", "b", "c"]>
//     ▼
const schema = Schema.Literal("a", "b", "c")

//     ┌─── "a" | "b" | "c"
//     ▼
type Type = typeof schema.Type

Schema.decodeUnknownSync(schema)(null)
/*
抛出:
ParseError: "a" | "b" | "c"
├─ Expected "a", actual null
├─ Expected "b", actual null
└─ Expected "c", actual null
*/
```

如果你想为整个字面量联合设置自定义错误消息，可以使用 `override: true` 选项（详见[自定义错误消息](/docs/schema/error-messages/#custom-error-messages)）来指定统一消息。

**示例**（为字面量联合添加自定义消息）

```ts twoslash
import { Schema } from "effect"

// 为每个字面量分别设置消息的模式
const individualMessages = Schema.Literal("a", "b", "c")

console.log(Schema.decodeUnknownSync(individualMessages)(null))
/*
抛出:
ParseError: "a" | "b" | "c"
├─ Expected "a", actual null
├─ Expected "b", actual null
└─ Expected "c", actual null
*/

// 为所有字面量设置统一自定义消息的模式
const unifiedMessage = Schema.Literal("a", "b", "c").annotations({
  message: () => ({ message: "Not a valid code", override: true })
})

console.log(Schema.decodeUnknownSync(unifiedMessage)(null))
/*
抛出:
ParseError: Not a valid code
*/
```

### 暴露的值

你可以使用 `literals` 属性访问字面量模式中定义的字面量：

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Literal("a", "b", "c")

//      ┌─── readonly ["a", "b", "c"]
//      ▼
const literals = schema.literals
```

### pickLiteral 工具

你可以对字面量模式使用 `Schema.pickLiteral` 来缩小其可能的值范围。

**示例**（使用 `pickLiteral` 缩小值范围）

```ts twoslash
import { Schema } from "effect"

// 从更大的集合中为字面量子集（"a" 和 "b"）创建模式
//
//      ┌─── Literal<["a", "b"]>
//      ▼
const schema = Schema.Literal("a", "b", "c").pipe(
  Schema.pickLiteral("a", "b")
)
```

有时，你可能需要在代码的其他部分重用字面量模式。下面是一个演示如何操作的示例：

**示例**（从字面量模式创建子类型）

```ts twoslash
import { Schema } from "effect"

// 定义水果类别的基础集合
const FruitCategory = Schema.Literal("sweet", "citrus", "tropical")

// 使用基础类别集合定义通用的水果模式
const Fruit = Schema.Struct({
  id: Schema.Number,
  category: FruitCategory
})

// 仅为 "sweet" 和 "citrus" 类别定义特定的水果模式
const SweetAndCitrusFruit = Schema.Struct({
  id: Schema.Number,
  category: FruitCategory.pipe(Schema.pickLiteral("sweet", "citrus"))
})
```

在这个例子中，`FruitCategory` 作为不同水果类别的唯一真实来源。我们重用它来创建 `Fruit` 的子类型 `SweetAndCitrusFruit`，确保只允许指定的类别（`"sweet"` 和 `"citrus"`）。这种方法有助于在代码中保持一致性，并在类别定义更改时提供类型安全。

## 模板字面量

在 TypeScript 中，[模板字面量类型](https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html)允许你在字符串字面量中嵌入表达式。`Schema.TemplateLiteral` 构造函数允许你为这些模板字面量类型创建模式。

**示例**（定义模板字面量）

```ts twoslash
import { Schema } from "effect"

// 这会为 `a${string}` 创建一个模式
//
//      ┌─── TemplateLiteral<`a${string}`>
//      ▼
const schema1 = Schema.TemplateLiteral("a", Schema.String)

// 这会为以下内容创建一个模式：
// `https://${string}.com` | `https://${string}.net`
const schema2 = Schema.TemplateLiteral(
  "https://",
  Schema.String,
  ".",
  Schema.Literal("com", "net")
)
```

**示例**（来自[模板字面量类型](https://www.typescriptlang.org/docs/handbook/2/template-literal-types.html)文档）

让我们看一个更复杂的例子。假设你有两组用于电子邮件和页脚的本地化 ID。你可以使用 `Schema.TemplateLiteral` 构造函数创建一个组合这些 ID 的模式：

```ts twoslash
import { Schema } from "effect"

const EmailLocaleIDs = Schema.Literal("welcome_email", "email_heading")
const FooterLocaleIDs = Schema.Literal("footer_title", "footer_sendoff")

// 这会为以下内容创建一个模式：
// "welcome_email_id" | "email_heading_id" |
// "footer_title_id" | "footer_sendoff_id"
const schema = Schema.TemplateLiteral(
  Schema.Union(EmailLocaleIDs, FooterLocaleIDs),
  "_id"
)
```

### 支持的跨度类型

`Schema.TemplateLiteral` 构造函数支持以下类型的跨度：

- `Schema.String`
- `Schema.Number`
- 字面量：`string | number | boolean | null | bigint`。这些可以用 `Schema.Literal` 包装，也可以直接使用
- 上述类型的联合
- 上述类型的品牌（brand）

**示例**（在模板字面量中使用品牌字符串）

```ts twoslash
import { Schema } from "effect"

// 为授权令牌创建一个品牌字符串模式
const AuthorizationToken = Schema.String.pipe(
  Schema.brand("AuthorizationToken")
)

// 这会为以下内容创建一个模式：
// `Bearer ${string & Brand<"AuthorizationToken">}`
const schema = Schema.TemplateLiteral("Bearer ", AuthorizationToken)
```

### TemplateLiteralParser

`Schema.TemplateLiteral` 构造函数虽然作为一个简单的验证器很有用，但它只通过将模板字面量定义转换为正则表达式来验证输入是否符合特定的字符串模式。类似地，[`Schema.pattern`](/docs/schema/filters/#string-filters) 直接使用正则表达式达到相同目的。验证后，这两种方法都需要额外的手动解析来将验证后的字符串转换为可用的数据格式。

为了解决这些限制并消除手动后验证解析的需要，开发了 `Schema.TemplateLiteralParser` API。它不仅能验证输入格式，还能自动将其解析为更结构化和类型安全的输出，具体来说是**元组**格式。

`Schema.TemplateLiteralParser` 构造函数支持与 `Schema.TemplateLiteral` 相同类型的[跨度](#supported-span-types)。

**示例**（使用 TemplateLiteralParser 进行解析和编码）

```ts twoslash
import { Schema } from "effect"

//      ┌─── Schema<readonly [number, "a", string], `${string}a${string}`>
//      ▼
const schema = Schema.TemplateLiteralParser(
  Schema.NumberFromString,
  "a",
  Schema.NonEmptyString
)

console.log(Schema.decodeSync(schema)("100afoo"))
// 输出: [ 100, 'a', 'foo' ]

console.log(Schema.encodeSync(schema)([100, "a", "foo"]))
// 输出: '100afoo'
```

## 原生枚举

Schema 模块提供了对原生 TypeScript 枚举的支持。你可以使用 `Schema.Enums` 为枚举定义模式，从而验证属于该枚举的值。

**示例**（为枚举定义模式）

```ts twoslash
import { Schema } from "effect"

enum Fruits {
  Apple,
  Banana
}

//      ┌─── Enums<typeof Fruits>
//      ▼
const schema = Schema.Enums(Fruits)

//     ┌─── Fruits
//     ▼
type Type = typeof schema.Type
```

### 暴露的值

枚举可以通过模式的 `enums` 属性访问。你可以使用此属性检索单个成员或整个枚举值集合。

```ts twoslash
import { Schema } from "effect"

enum Fruits {
  Apple,
  Banana
}

const schema = Schema.Enums(Fruits)

schema.enums // 返回所有枚举成员
schema.enums.Apple // 访问 Apple 成员
schema.enums.Banana // 访问 Banana 成员
```

## 联合类型

Schema 模块包含一个内置的 `Schema.Union` 构造函数，用于创建“或”类型，允许你定义可以表示多种类型的模式。

**示例**（定义联合模式）

```ts twoslash
import { Schema } from "effect"

//      ┌─── Union<[typeof Schema.String, typeof Schema.Number]>
//      ▼
const schema = Schema.Union(Schema.String, Schema.Number)

//     ┌─── string | number
//     ▼
type Type = typeof schema.Type
```

### 联合成员求值顺序

解码时，联合成员按照它们定义的顺序进行求值。如果一个值与第一个成员匹配，它将使用该模式进行解码。如果不匹配，解码过程将继续到下一个成员。

如果多个模式可以解码同一个值，顺序就很重要。将更通用的模式放在更具体的模式之前可能会导致属性丢失，因为第一个匹配的模式将被使用。

**示例**（处理联合中的重叠模式）

```ts twoslash
import { Schema } from "effect"

// 定义两个重叠的模式

const Member1 = Schema.Struct({
  a: Schema.String
})

const Member2 = Schema.Struct({
  a: Schema.String,
  b: Schema.Number
})

// ❌ 定义 Member1 在前的联合
const Bad = Schema.Union(Member1, Member2)

console.log(Schema.decodeUnknownSync(Bad)({ a: "a", b: 12 }))
// 输出: { a: 'a' }  (Member1 先匹配，所以 `b` 被忽略了)

// ✅ 定义 Member2 在前的联合
const Good = Schema.Union(Member2, Member1)

console.log(Schema.decodeUnknownSync(Good)({ a: "a", b: 12 }))
// 输出: { a: 'a', b: 12 } (Member2 先匹配，所以 `b` 被包含)
```

### 字面量联合

虽然你可以通过组合单个字面量模式来创建字面量联合：

**示例**（使用单个字面量模式）

```ts twoslash
import { Schema } from "effect"

//      ┌─── Union<[Schema.Literal<["a"]>, Schema.Literal<["b"]>, Schema.Literal<["c"]>]>
//      ▼
const schema = Schema.Union(
  Schema.Literal("a"),
  Schema.Literal("b"),
  Schema.Literal("c")
)
```

你可以通过将多个字面量直接传递给 `Schema.Literal` 构造函数来简化过程：

**示例**（定义字面量联合）

```ts twoslash
import { Schema } from "effect"

//     ┌─── Literal<["a", "b", "c"]>
//     ▼
const schema = Schema.Literal("a", "b", "c")

//     ┌─── "a" | "b" | "c"
//     ▼
type Type = typeof schema.Type
```

如果你想为整个字面量联合设置自定义错误消息，可以使用 `override: true` 选项（详见[自定义错误消息](/docs/schema/error-messages/#custom-error-messages)）来指定统一消息。

**示例**（为字面量联合添加自定义消息）

```ts twoslash
import { Schema } from "effect"

// 为每个字面量分别设置消息的模式
const individualMessages = Schema.Literal("a", "b", "c")

console.log(Schema.decodeUnknownSync(individualMessages)(null))
/*
抛出:
ParseError: "a" | "b" | "c"
├─ Expected "a", actual null
├─ Expected "b", actual null
└─ Expected "c", actual null
*/

// 为所有字面量设置统一自定义消息的模式
const unifiedMessage = Schema.Literal("a", "b", "c").annotations({
  message: () => ({ message: "Not a valid code", override: true })
})

console.log(Schema.decodeUnknownSync(unifiedMessage)(null))
/*
抛出:
ParseError: Not a valid code
*/
```

### 可空类型

Schema 模块包含用于定义允许可空类型的模式的实用函数，帮助处理可能为 `null`、`undefined` 或两者兼有的值。

**示例**（创建可空模式）

```ts twoslash
import { Schema } from "effect"

// 表示字符串或 null 值的模式
Schema.NullOr(Schema.String)

// 表示字符串、null 或 undefined 值的模式
Schema.NullishOr(Schema.String)

// 表示字符串或 undefined 值的模式
Schema.UndefinedOr(Schema.String)
```

### 可辨识联合

TypeScript 中的[可辨识联合](https://www.typescriptlang.org/docs/handbook/2/narrowing.html#discriminated-unions)是一种建模复杂数据结构的方式，这些结构可能根据一组特定的条件或属性呈现不同的形式。它们允许你定义一个表示多个相关形状的类型，其中每个形状由一个共享的可辨识属性唯一标识。

在可辨识联合中，联合的每个变体都有一个公共属性，称为可辨识属性。可辨识属性是一个字面量类型，这意味着它只能有有限的一组可能值。基于可辨识属性的值，TypeScript 可以推断当前正在使用的是联合的哪个变体。

**示例**（在 TypeScript 中定义可辨识联合）

```ts twoslash
type Circle = {
  readonly kind: "circle"
  readonly radius: number
}

type Square = {
  readonly kind: "square"
  readonly sideLength: number
}

type Shape = Circle | Square
```

在 `Schema` 模块中，你可以通过为每种类型指定一个字面量字段作为可辨识属性来类似地定义可辨识联合。

**示例**（使用 Schema 定义可辨识联合）

```ts twoslash
import { Schema } from "effect"

const Circle = Schema.Struct({
  kind: Schema.Literal("circle"),
  radius: Schema.Number
})

const Square = Schema.Struct({
  kind: Schema.Literal("square"),
  sideLength: Schema.Number
})

const Shape = Schema.Union(Circle, Square)
```

在这个例子中，`Schema.Literal` 构造函数将 `kind` 属性设置为 `Circle` 和 `Square` 模式的可辨识属性。`Shape` 模式然后表示这两种类型的联合，允许 TypeScript 根据 `kind` 值推断具体的形状。

### 将简单联合转换为可辨识联合

如果你从一个简单联合开始，并希望将其转换为可辨识联合，你可以为每个成员添加一个特殊属性。这允许 TypeScript 根据可辨识属性的值自动推断正确的类型。

**示例**（初始简单联合）

例如，假设你定义了一个 `Shape` 联合，作为 `Circle` 和 `Square` 的组合，没有任何特殊属性：

```ts twoslash
import { Schema } from "effect"

const Circle = Schema.Struct({
  radius: Schema.Number
})

const Square = Schema.Struct({
  sideLength: Schema.Number
})

const Shape = Schema.Union(Circle, Square)
```

为了使代码更易于管理，你可能希望将简单联合转换为可辨识联合。这样，TypeScript 将能够根据特定属性的值自动确定你正在处理联合的哪个成员。

为了实现这一点，你可以为联合的每个成员添加一个特殊属性，这将允许 TypeScript 在运行时知道它正在处理哪种类型。以下是你可以如何[转换](/docs/schema/transformations/#transform) `Shape` 模式为表示可辨识联合的另一个模式的方法：

**示例**（添加可辨识属性）

```ts twoslash
import { Schema } from "effect"

const Circle = Schema.Struct({
  radius: Schema.Number
})

const Square = Schema.Struct({
  sideLength: Schema.Number
})

const DiscriminatedShape = Schema.Union(
  Schema.transform(
    Circle,
    // 向 Circle 添加一个值为 "circle" 字面量的 "kind" 属性
    Schema.Struct({ ...Circle.fields, kind: Schema.Literal("circle") }),
    {
      strict: true,
      // 向 Circle 添加可辨识属性
      decode: (circle) => ({ ...circle, kind: "circle" as const }),
      // 移除可辨识属性
      encode: ({ kind: _kind, ...rest }) => rest
    }
  ),

  Schema.transform(
    Square,
    // 向 Square 添加一个值为 "square" 字面量的 "kind" 属性
    Schema.Struct({ ...Square.fields, kind: Schema.Literal("square") }),
    {
      strict: true,
      // 向 Square 添加可辨识属性
      decode: (square) => ({ ...square, kind: "square" as const }),
      // 移除可辨识属性
      encode: ({ kind: _kind, ...rest }) => rest
    }
  )
)

console.log(Schema.decodeUnknownSync(DiscriminatedShape)({ radius: 10 }))
// 输出: { radius: 10, kind: 'circle' }

console.log(
  Schema.decodeUnknownSync(DiscriminatedShape)({ sideLength: 10 })
)
// 输出: { sideLength: 10, kind: 'square' }
```

之前的解决方案效果很好，并展示了如何随意向模式添加属性，使消费结果在我们的领域模型中更容易。然而，它需要大量的样板代码。幸运的是，有一个专门为此用例设计的 API 叫做 `Schema.attachPropertySignature`，它允许我们用更少的努力实现相同的结果：

**示例**（使用 `Schema.attachPropertySignature` 减少代码量）

```ts twoslash
import { Schema } from "effect"

const Circle = Schema.Struct({
  radius: Schema.Number
})

const Square = Schema.Struct({
  sideLength: Schema.Number
})

const DiscriminatedShape = Schema.Union(
  Circle.pipe(Schema.attachPropertySignature("kind", "circle")),
  Square.pipe(Schema.attachPropertySignature("kind", "square"))
)

// 解码
console.log(Schema.decodeUnknownSync(DiscriminatedShape)({ radius: 10 }))
// 输出: { radius: 10, kind: 'circle' }

// 编码
console.log(
  Schema.encodeSync(DiscriminatedShape)({
    kind: "circle",
    radius: 10
  })
)
// 输出: { radius: 10 }
```

<Aside type="caution" title="仅添加属性">
  请注意，使用 `Schema.attachPropertySignature` 时，你只能添加属性，不能替换或覆盖现有属性。
</Aside>

### 暴露的值

你可以以元组形式访问联合模式的各个成员：

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Union(Schema.String, Schema.Number)

// 访问联合的成员
const members = schema.members

//      ┌─── typeof Schema.String
//      ▼
const firstMember = members[0]

//      ┌─── typeof Schema.Number
//      ▼
const secondMember = members[1]
```

## 元组

Schema 模块允许你定义元组，这是元素的有序集合，可能具有不同的类型。你可以定义带有必需元素、可选元素或剩余元素的元组。

### 必需元素

要定义带有必需元素的元组，你可以使用 `Schema.Tuple` 构造函数，并按顺序列出元素模式：

**示例**（定义带有必需元素的元组）

```ts twoslash
import { Schema } from "effect"

// 定义一个元组，包含一个字符串和一个数字作为必需元素
//
//      ┌─── Tuple<[typeof Schema.String, typeof Schema.Number]>
//      ▼
const schema = Schema.Tuple(Schema.String, Schema.Number)

//     ┌─── readonly [string, number]
//     ▼
type Type = typeof schema.Type
```

### 追加必需元素

你可以使用扩展运算符向现有元组追加额外的必需元素：

**示例**（向现有元组添加元素）

```ts twoslash
import { Schema } from "effect"

const tuple1 = Schema.Tuple(Schema.String, Schema.Number)

// 向现有元组追加一个布尔值
const tuple2 = Schema.Tuple(...tuple1.elements, Schema.Boolean)

//     ┌─── readonly [string, number, boolean]
//     ▼
```

### 可选元素

要定义可选元素，请使用 `Schema.optionalElement` 构造函数。

**示例**（定义带有可选元素的元组）

```ts twoslash
import { Schema } from "effect"

  Schema.String, // 必需元素
  Schema.optionalElement(Schema.Number) // 可选元素
)

//     ┌─── readonly [string, number?]
//     ▼

```

### 剩余元素

要定义剩余元素，请在必需或可选元素列表之后添加它。剩余元素允许元组接受特定类型的额外元素。

**示例**（使用剩余元素）

```ts twoslash
import { Schema } from "effect"

  [Schema.String, Schema.optionalElement(Schema.Number)], // 元素
  Schema.Boolean // 剩余元素
)

//     ┌─── readonly [string, number?, ...boolean[]]
//     ▼
type Type = typeof schema.Type
```

你也可以在剩余元素之后包含其他元素：

**示例**（在剩余元素之后包含其他元素）

```ts twoslash
import { Schema } from "effect"

// 定义一个元组，包含必需元素、一个剩余元素和一个额外元素
const schema = Schema.Tuple(
  [Schema.String, Schema.optionalElement(Schema.Number)], // 元素
  Schema.Boolean, // 剩余元素

//     ┌─── readonly [string, number | undefined, ...boolean[], string]
//     ▼

```

### 注解

注解对于向元组元素添加元数据很有用，使得描述它们的目的或要求更加容易。这对于生成文档或 JSON 模式特别有帮助。

```ts twoslash
输出:

*/
```

## 记录

Schema 模块提供了对定义记录类型的支持，记录是键值对的集合，其中键可以是字符串、符号或其他类型，值具有定义的模式。

### 字符串键

你可以定义具有字符串键和指定值类型的记录。

**示例**（字符串键与数字值）

```ts twoslash
import { Schema } from "effect"

// 定义一个具有字符串键和数字值的记录模式
//
//      ┌─── Record$<typeof Schema.String, typeof Schema.Number>
//      ▼
const schema = Schema.Record({ key: Schema.String, value: Schema.Number })

//     ┌─── { readonly [x: string]: number; }
//     ▼
type Type = typeof schema.Type
```

### 符号键

记录也可以使用符号作为键。

**示例**（符号键与数字值）

```ts twoslash
import { Schema } from "effect"

// 定义一个具有符号键和数字值的记录模式
const schema = Schema.Record({
  key: Schema.SymbolFromSelf,
  value: Schema.Number
})

//     ┌─── { readonly [x: symbol]: number; }
//     ▼
type Type = typeof schema.Type
```

### 字面量键的联合

使用字面量联合将键限制为一组特定的值。

**示例**（字符串字面量作为键的联合）

```ts twoslash
import { Schema } from "effect"

// 定义一个记录模式，其中键被限制为特定的字符串字面量（"a" 或 "b"）
const schema = Schema.Record({
  key: Schema.Union(Schema.Literal("a"), Schema.Literal("b")),
  value: Schema.Number
})

//     ┌─── { readonly a: number; readonly b: number; }
//     ▼
type Type = typeof schema.Type
```

### 模板字面量键

记录可以使用模板字面量作为键，允许更复杂的键模式。

**示例**（模板字面量键与数字值）

```ts twoslash
import { Schema } from "effect"

// 定义一个记录模式，其键匹配模板字面量模式 "a${string}"
const schema = Schema.Record({
  key: Schema.TemplateLiteral(Schema.Literal("a"), Schema.String),
  value: Schema.Number
})

//     ┌─── { readonly [x: `a${string}`]: number; }
//     ▼
type Type = typeof schema.Type
```

### 精炼键

你可以使用额外的约束来精炼键类型。

**示例**（按最小长度筛选键）

```ts twoslash
import { Schema } from "effect"

// 定义一个记录模式，其中键是最小长度为 2 的字符串
const schema = Schema.Record({
  key: Schema.String.pipe(Schema.minLength(2)),
  value: Schema.Number
})

//     ┌─── { readonly [x: string]: number; }
//     ▼
type Type = typeof schema.Type
```

对键的精炼充当过滤器而不是导致解码失败。如果键不满足约束（例如模式或最小长度检查），它将被从解码输出中移除，而不是触发错误。

**示例**（不满足约束的键被移除）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Record({
  key: Schema.String.pipe(Schema.minLength(2)),
  value: Schema.Number
})

console.log(Schema.decodeUnknownSync(schema)({ a: 1, bb: 2 }))
// 输出: { bb: 2 } ("a" 因为太短而被移除)
```

如果你希望在键不满足约束时解码失败，可以将 [`onExcessProperty`](/docs/schema/getting-started/#managing-excess-properties) 设置为 `"error"`。

**示例**（在无效键上强制报错）

```ts twoslash "onExcessProperty"
import { Schema } from "effect"

const schema = Schema.Record({
  key: Schema.String.pipe(Schema.minLength(2)),
  value: Schema.Number
})

console.log(
  Schema.decodeUnknownSync(schema, { onExcessProperty: "error" })({
    a: 1,
    bb: 2
  })
)
/*
抛出:
ParseError: { readonly [x: minLength(2)]: number }
└─ ["a"]
   └─ is unexpected, expected: minLength(2)
*/
```

### 转换键

`Schema.Record` API 不支持对键模式进行转换。尝试对键应用转换将导致 `Unsupported key schema` 错误：

**示例**（尝试转换键）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Record({
  key: Schema.Trim,
  value: Schema.NumberFromString
})
/*
抛出:
Error: Unsupported key schema
schema (Transformation): Trim
*/
```

<Aside type="note" title="为什么不允许键转换">
  这个限制是因为如果多个键在转换后映射到相同的值，转换可能会产生冲突。要防止这些问题，键转换必须由用户显式处理。
</Aside>

要修改记录键，你必须在 `Schema.Record` 之外应用转换。一种常见的方法是使用 [Schema.transform](/docs/schema/transformations/#transform) 在解码期间调整键。

**示例**（解码时修剪键）

```ts twoslash
import { Schema, Record, identity } from "effect"

const schema = Schema.transform(
  // 定义具有未处理键的输入模式
  Schema.Record({
    key: Schema.String,
    value: Schema.NumberFromString
  }),
  // 定义具有转换后键的输出模式
  Schema.Record({
    key: Schema.Trimmed,
    value: Schema.Number
  }),
  {
    strict: true,
    // 解码时修剪键
    decode: (record) => Record.mapKeys(record, (key) => key.trim()),
    encode: identity
  }
)

console.log(
  Schema.decodeUnknownSync(schema)({ " key1 ": "1", key2: "2" })
)
// 输出: { key1: 1, key2: 2 }
```

### 可变记录

默认情况下，`Schema.Record` 生成的类型被标记为 `readonly`。要创建可变记录的模式，你可以使用 `Schema.mutable` 函数，它以**浅层**方式使记录类型变为可变。

**示例**（创建可变记录模式）

```ts twoslash
import { Schema } from "effect"

  Schema.Record({ key: Schema.String, value: Schema.Number })

//     ┌─── { [x: string]: number; }
//     ▼

```

### 暴露的值

你可以使用 `key` 和 `value` 属性访问记录模式的 `key` 和 `value` 类型：

**示例**（访问键和值类型）


## 结构体

### 属性签名

`Schema.Struct` 构造函数为具有特定属性的对象定义模式。

**示例**（定义结构体模式）

这个例子定义了一个结构体模式，用于具有以下属性的对象：

- `name`：一个字符串
- `age`：一个数字

```ts twoslash
import { Schema } from "effect"

//      ┌─── Schema.Struct<{
//      │      name: typeof Schema.String;
//      │      age: typeof Schema.Number;
//      │    }>
//      ▼
const schema = Schema.Struct({
  name: Schema.String,
  age: Schema.Number
})

// 从模式推断的 TypeScript 类型
//
//     ┌─── {
//     │      readonly name: string;
//     │      readonly age: number;
//     │    }
//     ▼
type Type = typeof schema.Type
```

<Aside type="caution" title="空结构体允许任何数据">
  使用 `Schema.Struct({})` 会产生 TypeScript 类型 `{}`，其行为类似于 `unknown`。这意味着任何数据都将被认为是有效的，因为没有定义的约束。
</Aside>

### 索引签名

`Schema.Struct` 构造函数可以选择接受一组表示索引签名的键/值对，允许你定义额外的动态属性。

```ts showLineNumbers=false
declare const Struct: (props, ...indexSignatures) => Struct<...>
```

**示例**（添加索引签名）

```ts twoslash
import { Schema } from "effect"

// 定义一个具有特定属性 "a" 的结构体
// 以及允许额外属性的索引签名
const schema = Schema.Struct(
  // 定义的属性
  { a: Schema.Number },
  // 索引签名：允许具有数字值的额外字符串键
  { key: Schema.String, value: Schema.Number }
)

// 推断的 TypeScript 类型：
//
//     ┌─── {
//     │      readonly [x: string]: number;
//     │      readonly a: number;
//     │    }
//     ▼
type Type = typeof schema.Type
```

**示例**（使用 `Schema.Record`）

你可以使用 `Schema.Record` 实现相同的结果：

```ts twoslash
import { Schema } from "effect"

// 定义一个具有固定属性 "a" 的结构体
// 以及使用 Schema.Record 的动态索引签名
const schema = Schema.Struct(
  { a: Schema.Number },
  Schema.Record({ key: Schema.String, value: Schema.Number })
)

// 推断的 TypeScript 类型：
//
//     ┌─── {
//     │      readonly [x: string]: number;
//     │      readonly a: number;
//     │    }
//     ▼
type Type = typeof schema.Type
```

### 多个索引签名

你可以为每种键类型（`string` 或 `symbol`）定义**一个**索引签名。不允许定义相同类型的多个索引签名。

**示例**（有效的多个索引签名）

```ts twoslash
import { Schema } from "effect"

// 定义一个具有固定属性 "a" 的结构体
// 以及字符串和符号的有效索引签名
const schema = Schema.Struct(
  { a: Schema.Number },
  // 字符串索引签名
  { key: Schema.String, value: Schema.Number },
  // 符号索引签名
  { key: Schema.SymbolFromSelf, value: Schema.Number }
)

// 推断的 TypeScript 类型：
//
//     ┌─── {
//     │      readonly [x: string]: number;
//     │      readonly [x: symbol]: number;
//     │      readonly a: number;
//     │    }
//     ▼
type Type = typeof schema.Type
```

定义相同键类型（`string` 或 `symbol`）的多个索引签名将导致错误。

**示例**（无效的多个索引签名）

```ts twoslash
import { Schema } from "effect"

Schema.Struct(
  { a: Schema.Number },
  // 尝试定义多个字符串索引签名
  { key: Schema.String, value: Schema.Number },
  { key: Schema.String, value: Schema.Boolean }
)
/*
抛出:
Error: Duplicate index signature
details: string index signature
*/
```

### 冲突的索引签名

当定义带有索引签名的模式时，如果固定属性与索引签名允许的值类型不同，可能会产生冲突。这可能导致意外的 TypeScript 行为。

**示例**（冲突的索引签名）

```ts twoslash
import { Schema } from "effect"

// 尝试定义一个带有冲突索引签名的结构体
// - 固定属性 "a" 是字符串
// - 索引签名要求所有值都是数字
const schema = Schema.Struct(
  { a: Schema.String },
  { key: Schema.String, value: Schema.Number }
)

// ❌ 错误的 TypeScript 类型：
//
//     ┌─── {
//     │      readonly [x: string]: number;
//     │      readonly a: string;
//     │    }
//     ▼
type Type = typeof schema.Type
```

当手动定义类型时，TypeScript 编译器会将其标记为错误：

```ts twoslash
// @errors: 2411
// 这种类型无效，因为索引签名与固定属性 `a` 冲突
type Test = {
  readonly a: string
  readonly [x: string]: number
}
```

这是因为 TypeScript 不允许索引签名与固定属性相矛盾。

#### 冲突索引签名的解决方法

在处理模式时，如果固定属性与索引签名允许的值类型不同，可能会发生冲突。这种情况通常发生在处理不遵循严格 TypeScript 约定的外部 API 时。

为了防止冲突，你可以将固定属性与索引属性分开，并将它们作为模式的不同部分进行处理。

**示例**（提取固定属性和索引属性）

考虑一个对象，其中：

- `"a"` 是类型为 `string` 的固定属性。
- 所有其他键存储数字，这与 `"a"` 冲突。

```ts twoslash
// @errors: 2411
// 这种类型无效，因为索引签名与固定属性 `a` 冲突
type Test = {
  a: string
  [x: string]: number
}
```

为了避免这个问题，我们可以将属性分成两种不同的类型：

```ts showLineNumbers=false
// 固定属性模式
type FixedProperties = {
  readonly a: string
}

// 索引签名属性模式
type IndexSignatureProperties = {
  readonly [x: string]: number
}

// 最终输出将两种属性分组到一个元组中
type OutputData = readonly [FixedProperties, IndexSignatureProperties]
```

通过使用 [Schema.transform](/docs/schema/transformations/#transform) 和 [Schema.compose](/docs/schema/transformations/#composition)，你可以在验证之前预处理输入数据。这种方法确保固定属性和索引签名属性被独立处理。

```ts twoslash
import { Schema } from "effect"

// 为固定属性 "a" 定义模式
const FixedProperties = Schema.Struct({
  a: Schema.String
})

// 为索引签名属性定义模式
const IndexSignatureProperties = Schema.Record({
  // 排除 FixedProperties 中已经存在的键
  key: Schema.String.pipe(
    Schema.filter(
      (key) => !Object.keys(FixedProperties.fields).includes(key)
    )
  ),
  value: Schema.Number
})

// 创建一个将对象复制为两部分的模式
const Duplicate = Schema.transform(
  Schema.Object,
  Schema.Tuple(Schema.Object, Schema.Object),
  {
    strict: true,
    // 创建一个包含输入两次的元组
    decode: (a) => [a, a] as const,
    // 编码时合并两个部分
    encode: ([a, b]) => ({ ...a, ...b })
  }
)

//      ┌─── Schema<readonly [
//      |      { readonly a: string; },
//      |      { readonly [x: string]: number; }
//      |    ], object>
//      ▼
const Result = Schema.compose(
  Duplicate,
  Schema.Tuple(FixedProperties, IndexSignatureProperties).annotations({
    parseOptions: { onExcessProperty: "ignore" }
  })
)

// 解码：分离固定属性和索引属性
console.log(Schema.decodeUnknownSync(Result)({ a: "a", b: 1, c: 2 }))
// 输出: [ { a: 'a' }, { b: 1, c: 2 } ]

// 编码：将它们合并回对象
console.log(Schema.encodeSync(Result)([{ a: "a" }, { b: 1, c: 2 }]))
// 输出: { a: 'a', b: 1, c: 2 }
```


### 可变结构体

默认情况下，`Schema.Struct` 生成的类型属性被标记为 `readonly`。要创建可变版本的结构体，请使用 `Schema.mutable` 函数，它以**浅层**方式使属性变为可变。

**示例**（创建可变结构体模式）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.mutable(
  Schema.Struct({ a: Schema.String, b: Schema.Number })
)

//     ┌─── { a: string; b: number; }
//     ▼
type Type = typeof schema.Type
```

## 标记结构体

在 TypeScript 中，标记通过提供一种简单而强大的方式来定义和识别不同的数据类型，帮助增强类型区分和模式匹配。

### 什么是标记？

标记是添加到数据结构中的字面量值，常用于结构体，以区分标记联合中的各种对象类型或变体。这个字面量充当一个可辨识属性，使得正确高效地处理和操作不同类型的数据变得更加容易。

### 使用 tag 构造函数

`Schema.tag` 构造函数专门设计用于创建一个持有特定字面量值的属性签名，作为对象类型的可辨识属性。

**示例**（定义标记结构体）

```ts twoslash
import { Schema } from "effect"

const User = Schema.Struct({
  _tag: Schema.tag("User"),
  name: Schema.String,
  age: Schema.Number
})

//     ┌─── { readonly _tag: "User"; readonly name: string; readonly age: number; }
//     ▼
type Type = typeof User.Type

console.log(User.make({ name: "John", age: 44 }))
/*
输出:
{ _tag: 'User', name: 'John', age: 44 }
*/
```

在上面的例子中，`Schema.tag("User")` 向 `User` 结构体模式附加了一个 `_tag` 属性，有效地将此类结构体类型的对象标记为 "User"。当使用 `make` 方法创建新实例时，这个标签会被自动应用，简化了对象创建并确保了一致的标记。

### 使用 TaggedStruct 简化标记结构体

`Schema.TaggedStruct` 构造函数通过将标记直接集成到结构体定义中，简化了创建标记结构体的过程。这种方法为构建带有嵌入式可辨识属性的数据结构提供了更清晰、更声明式的方式。

**示例**（使用 `TaggedStruct` 简化标记结构体）

```ts twoslash
import { Schema } from "effect"

const User = Schema.TaggedStruct("User", {
  name: Schema.String,
  age: Schema.Number
})

// 构造实例时自动应用 `_tag`
console.log(User.make({ name: "John", age: 44 }))
// 输出: { _tag: 'User', name: 'John', age: 44 }

// 从未知源解码时需要 `_tag`
console.log(Schema.decodeUnknownSync(User)({ name: "John", age: 44 }))
/*
抛出:
ParseError: { readonly _tag: "User"; readonly name: string; readonly age: number }
└─ ["_tag"]
   └─ is missing
*/
```

在这个例子中：

- 使用 `make` 构造实例时，`_tag` 属性是可选的，允许模式自动应用它。
- 解码未知数据时，需要 `_tag` 来确保正确的类型识别。这种实例构造和解码之间的区别有助于在简化实例创建的同时保持标记作为类型可辨识属性的作用。

如果你需要 `_tag` 在解码期间也自动应用，你可以创建一个自定义版本的 `Schema.TaggedStruct`：

**示例**（自定义 `TaggedStruct`，在解码期间也应用 `_tag`）

```ts twoslash
import type { SchemaAST } from "effect"
import { Schema } from "effect"

const TaggedStruct = <
  Tag extends SchemaAST.LiteralValue,
  Fields extends Schema.Struct.Fields
>(
  tag: Tag,
  fields: Fields
) =>
  Schema.Struct({
    _tag: Schema.Literal(tag).pipe(
      Schema.optional,
      Schema.withDefaults({
        constructor: () => tag, // 在实例构造期间应用 _tag
        decoding: () => tag // 在解码期间应用 _tag
      })
    ),
    ...fields
  })

const User = TaggedStruct("User", {
  name: Schema.String,
  age: Schema.Number
})

console.log(User.make({ name: "John", age: 44 }))
// 输出: { _tag: 'User', name: 'John', age: 44 }

console.log(Schema.decodeUnknownSync(User)({ name: "John", age: 44 }))
// 输出: { _tag: 'User', name: 'John', age: 44 }
```

### 多个标记

虽然一个主要标记通常就足够了，但 TypeScript 允许你定义多个标记以满足更复杂的数据结构需求。这里有一个示例，演示了在单个结构体中使用多个标记：

**示例**（向结构体添加多个标记）

这个例子定义了一个产品模式，带有一个主要标记（`"Product"`）和一个额外的类别标记（`"Electronics"`），为数据结构增加了进一步的特异性。

```ts twoslash
import { Schema } from "effect"

const Product = Schema.TaggedStruct("Product", {
  category: Schema.tag("Electronics"),
  name: Schema.String,
  price: Schema.Number
})

// 创建实例时 `_tag` 和 `category` 是可选的
console.log(Product.make({ name: "Smartphone", price: 999 }))
/*
输出:
{
  _tag: 'Product',
  category: 'Electronics',
  name: 'Smartphone',
  price: 999
}
*/
```

## instanceOf

当你需要为通过 `class` 定义的自定义数据类型定义模式时，最方便快捷的方法是使用 `Schema.instanceOf` 构造函数。

**示例**（使用 `instanceOf` 定义模式）

```ts twoslash
import { Schema } from "effect"

// 定义一个自定义类
class MyData {
  constructor(readonly name: string) {}
}

// 为类创建模式
const MyDataSchema = Schema.instanceOf(MyData)

//     ┌─── MyData
//     ▼
type Type = typeof MyDataSchema.Type

console.log(Schema.decodeUnknownSync(MyDataSchema)(new MyData("name")))
// 输出: MyData { name: 'name' }

console.log(Schema.decodeUnknownSync(MyDataSchema)({ name: "name" }))
/*
抛出:
ParseError: Expected MyData, actual {"name":"name"}
*/
```

`Schema.instanceOf` 构造函数只是 [Schema.declare](/docs/schema/advanced-usage/#declaring-new-data-types) API 的一个轻量级包装器，后者是 `effect/Schema` 中用于声明新自定义数据类型的原始方式。

### 私有构造函数

注意，`Schema.instanceOf` 只能用于暴露**公共构造函数**的类。如果你尝试将其用于由于某种原因将构造函数标记为 `private` 的类，你会收到一个 TypeScript 错误：

**示例**（私有构造函数的错误）

```ts twoslash
import { Schema } from "effect"

class MyData {
  static make = (name: string) => new MyData(name)
  private constructor(readonly name: string) {}
}

// @errors: 2345
const MyDataSchema = Schema.instanceOf(MyData)
```

在这种情况下，你不能使用 `Schema.instanceOf`，必须像这样依赖 [Schema.declare](/docs/schema/advanced-usage/#declaring-new-data-types)：

**示例**（对私有构造函数使用 `Schema.declare`）

```ts twoslash
import { Schema } from "effect"

class MyData {
  static make = (name: string) => new MyData(name)
  private constructor(readonly name: string) {}
}

const MyDataSchema = Schema.declare(
  (input: unknown): input is MyData => input instanceof MyData
).annotations({ identifier: "MyData" })

console.log(Schema.decodeUnknownSync(MyDataSchema)(MyData.make("name")))
// 输出: MyData { name: 'name' }

console.log(Schema.decodeUnknownSync(MyDataSchema)({ name: "name" }))
/*
抛出:
ParseError: Expected MyData, actual {"name":"name"}
*/
```

### 验证实例的字段

要验证类实例的字段，你可以使用[过滤器](/docs/schema/filters/)。这种方法将实例验证与对实例字段的额外检查相结合。

**示例**（向实例模式添加字段验证）

```ts twoslash
import { Either, ParseResult, Schema } from "effect"

class MyData {
  constructor(readonly name: string) {}
}

const MyDataFields = Schema.Struct({
  name: Schema.NonEmptyString
})

// 为类实例定义模式，添加额外的字段验证
const MyDataSchema = Schema.instanceOf(MyData).pipe(
  Schema.filter((a, options) =>
    // 验证实例的字段
    ParseResult.validateEither(MyDataFields)(a, options).pipe(
      // 为过滤器反转成功和失败
      Either.flip,
      // 如果验证成功则返回 undefined，失败则返回错误
      Either.getOrUndefined
    )
  )
)

// 示例：有效实例
console.log(Schema.validateSync(MyDataSchema)(new MyData("John")))
// 输出: MyData { name: 'John' }

// 示例：无效实例（空名称）
console.log(Schema.validateSync(MyDataSchema)(new MyData("")))
/*
抛出:
ParseError: { MyData | filter }
└─ Predicate refinement failure
   └─ { readonly name: NonEmptyString }
      └─ ["name"]
         └─ NonEmptyString
            └─ Predicate refinement failure
               └─ Expected a non empty string, actual ""
*/
```

## 选择

每个结构体模式上可用的 `pick` 静态函数可用于通过从现有 `Struct` 中选择特定属性来创建新的 `Struct`。

**示例**（从结构体中选择属性）

```ts twoslash
import { Schema } from "effect"

// 定义具有属性 "a"、"b" 和 "c" 的结构体模式
const MyStruct = Schema.Struct({
  a: Schema.String,
  b: Schema.Number,
  c: Schema.Boolean
})

// 创建一个选择属性 "a" 和 "c" 的新模式
//
//      ┌─── Struct<{
//      |      a: typeof Schema.String;
//      |      c: typeof Schema.Boolean;
//      |    }>
//      ▼
const PickedSchema = MyStruct.pick("a", "c")
```

`Schema.pick` 函数可以更广泛地应用，不仅仅限于 `Struct` 类型，例如与模式联合一起使用。但它返回一个通用的 `SchemaClass`。

**示例**（从联合中选择属性）

```ts twoslash
import { Schema } from "effect"

// 定义两个结构体模式的联合
const MyUnion = Schema.Union(
  Schema.Struct({ a: Schema.String, b: Schema.String, c: Schema.String }),
  Schema.Struct({ a: Schema.Number, b: Schema.Number, d: Schema.Number })
)

// 创建一个选择属性 "a" 和 "b" 的新模式
//
//      ┌─── SchemaClass<{
//      |      readonly a: string | number;
//      |      readonly b: string | number;
//      |    }>
//      ▼
const PickedSchema = MyUnion.pipe(Schema.pick("a", "b"))
```

## 省略

每个结构体模式中可用的 `omit` 静态函数可用于通过从现有 `Struct` 中排除特定属性来创建新的 `Struct`。

**示例**（从结构体中省略属性）

```ts twoslash
import { Schema } from "effect"

// 定义具有属性 "a"、"b" 和 "c" 的结构体模式
```

## partial

`Schema.partial` 函数使模式中的所有属性变为可选。

**示例**（使所有属性变为可选）

```ts twoslash
import { Schema } from "effect"

// 创建具有可选属性 "a" 的模式
const schema = Schema.partial(Schema.Struct({ a: Schema.String }))

//     ┌─── { readonly a?: string | undefined; }
//     ▼
type Type = typeof schema.Type
```

默认情况下，`Schema.partial` 操作会向每个属性的类型添加 `undefined`。如果你想避免这种情况，可以使用 `Schema.partialWith` 并传递 `{ exact: true }` 作为参数。

**示例**（定义精确的部分模式）

```ts twoslash
import { Schema } from "effect"

// 创建具有可选属性 "a" 但不允许 undefined 的模式
const schema = Schema.partialWith(
  Schema.Struct({
    a: Schema.String
  }),
  { exact: true }
)

//     ┌─── { readonly a?: string; }
//     ▼
type Type = typeof schema.Type
```

## required

`Schema.required` 函数确保模式中的所有属性都是必需的。

**示例**（使所有属性变为必需）

```ts twoslash
import { Schema } from "effect"

// 创建一个模式并使所有属性变为必需
const schema = Schema.required(
  Schema.Struct({
    a: Schema.optionalWith(Schema.String, { exact: true }),
    b: Schema.optionalWith(Schema.Number, { exact: true })
  })
)

//     ┌─── { readonly a: string; readonly b: number; }
//     ▼
type Type = typeof schema.Type
```

在这个例子中，尽管 `a` 和 `b` 最初被定义为可选的，但它们都变为必需的。

## keyof

`Schema.keyof` 操作创建一个表示给定对象模式键的模式。

**示例**（从对象模式中提取键）

```ts twoslash
import { Schema } from "effect"

const schema = Schema.Struct({
  a: Schema.String,
  b: Schema.Number

const keys = Schema.keyof(schema)
```
