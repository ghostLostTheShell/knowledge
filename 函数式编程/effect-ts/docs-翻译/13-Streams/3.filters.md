开发者可以定义超出基本类型检查的自定义验证逻辑，从而对数据验证方式拥有更多控制权。

## 声明过滤器

过滤器使用 `Schema.filter` 函数声明。此函数需要两个参数：要验证的模式和谓词函数。谓词函数由用户定义，用于确定数据是否满足条件。如果数据未能通过验证，可以提供错误消息。

**示例**（定义最小字符串长度过滤器）

```ts twoslash
import { Schema } from "effect"

// 定义一个字符串模式，使用过滤器确保字符串
// 至少有 10 个字符长
const LongString = Schema.String.pipe(
  Schema.filter(
    // 对于长度小于 10 个字符的字符串的自定义错误消息
    (s) => s.length >= 10 || "a string at least 10 characters long"
  )
)

//     ┌─── string
//     ▼
type Type = typeof LongString.Type

console.log(Schema.decodeUnknownSync(LongString)("a"))
/*
throws:
ParseError: { string | filter }
└─ Predicate refinement failure
   └─ a string at least 10 characters long
*/
```

请注意，过滤器不会改变模式的 `Type`：

```ts showLineNumbers=false
//     ┌─── string
//     ▼
type Type = typeof LongString.Type
```

过滤器添加额外的验证约束，而不修改模式的底层类型。

<Aside type="tip">
  如果您需要修改 `Type`，请考虑使用[品牌类型](/docs/schema/advanced-usage/#branded-types)。
</Aside>

## 谓词函数

过滤器中的谓词函数遵循以下结构：

```ts
type Predicate = (
  a: A,
  options: ParseOptions,
  self: AST.Refinement
) => FilterReturnType
```

其中

```ts
interface FilterIssue {
  readonly path: ReadonlyArray<PropertyKey>
  readonly issue: string | ParseResult.ParseIssue
}

type FilterOutput =
  | undefined
  | boolean
  | string
  | ParseResult.ParseIssue
  | FilterIssue

type FilterReturnType = FilterOutput | ReadonlyArray<FilterOutput>
```

过滤器的谓词可以返回几种类型的值，每种都会以不同方式影响验证：

| 返回类型                   | 行为                                                                                         |
| ----------------------------- | ------------------------------------------------------------------------------------------------ |
| `true` 或 `undefined`         | 数据满足过滤器的条件并通过验证。                                 |
| `false`                       | 数据不符合条件，且未提供特定的错误消息。                 |
| `string`                      | 验证失败，并使用提供的字符串作为错误消息。                      |
| `ParseResult.ParseIssue`      | 验证失败，并提供详细的错误结构，指定失败的位置和原因。        |
| `FilterIssue`                 | 允许使用特定路径提供更详细的错误消息，从而增强错误报告。 |
| `ReadonlyArray<FilterOutput>` | 如果需要报告多个验证错误，可以返回问题数组。            |

<Aside type="tip" title="Effectful Filters">
  普通过滤器仅处理同步、非副作用的验证。如果
  您需要涉及异步逻辑或副作用的过滤器，
  请考虑使用
  [Schema.filterEffect](/docs/schema/transformations/#effectful-filters)。
</Aside>

## 添加注解

在模式中嵌入元数据，如标识符、JSON 模式规范和描述，可以增强对模式约束和目的的理解和分析。

**示例**（使用注解添加元数据）

```ts twoslash
import { Schema, JSONSchema } from "effect"

const LongString = Schema.String.pipe(
  Schema.filter(
    (s) =>
      s.length >= 10 ? undefined : "a string at least 10 characters long",
    {
      identifier: "LongString",
      jsonSchema: { minLength: 10 },
      description: "Lorem ipsum dolor sit amet, ..."
    }
  )
)

console.log(Schema.decodeUnknownSync(LongString)("a"))
/*
throws:
ParseError: LongString
└─ Predicate refinement failure
   └─ a string at least 10 characters long
*/

console.log(JSON.stringify(JSONSchema.make(LongString), null, 2))
/*
Output:
{
  "$schema": "http://json-schema.org/draft-07/schema#",
  "$defs": {
    "LongString": {
      "type": "string",
      "description": "Lorem ipsum dolor sit amet, ...",
      "minLength": 10
    }
  },
  "$ref": "#/$defs/LongString"
}
*/
```

## 指定错误路径

在验证表单或结构化数据时，可以将特定的错误消息与特定字段或路径关联。这增强了错误报告，尤其在与 [react-hook-form](https://react-hook-form.com/) 等库集成时非常有用。

**示例**（匹配密码）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Password = Schema.Trim.pipe(Schema.minLength(2))

const MyForm = Schema.Struct({
  password: Password,
  confirm_password: Password
}).pipe(
  // 添加过滤器以确保密码匹配
  Schema.filter((input) => {
    if (input.password !== input.confirm_password) {
      // 返回与 "confirm_password" 字段关联的错误消息
      return {
        path: ["confirm_password"],
        message: "Passwords do not match"
      }
    }
  })
)

console.log(
  JSON.stringify(
    Schema.decodeUnknownEither(MyForm)({
      password: "abc",
      confirm_password: "abd" // 确认密码不匹配
    }).pipe(
      Either.mapLeft((error) =>
        ParseResult.ArrayFormatter.formatErrorSync(error)
      )
    ),
    null,
    2
  )
)
/*
  "_id": "Either",
  "_tag": "Left",
  "left": [
    {
      "_tag": "Type",
      "path": [
        "confirm_password"
      ],
      "message": "Passwords do not match"
    }
  ]
}
*/
```

在此示例中，我们定义了一个 `MyForm` 模式，其中包含两个密码字段（`password` 和 `confirm_password`）。我们使用 `Schema.filter` 检查两个密码是否匹配。如果不匹配，则返回错误消息，专门与 `confirm_password` 字段关联。这使得更容易 pinpoint 验证失败的确切位置。

错误使用 `ArrayFormatter` 以结构化方式格式化，便于后续处理和与表单库集成。

<Aside type="tip" title="使用 ArrayFormatter 处理结构化错误">
  `ArrayFormatter` 提供详细且结构化的错误格式，
  而不是简单的错误字符串。这在处理复杂表单或结构化数据时特别有用。有关更多信息，请参见
  [ArrayFormatter](/docs/schema/error-formatters/#arrayformatter)。
</Aside>

## 多错误报告

`Schema.filter` API 支持一次报告多个验证问题，这在表单验证等场景中特别有用，其中多个检查可能同时失败。

**示例**（报告多个验证错误）

```ts twoslash
import { Either, Schema, ParseResult } from "effect"

const Password = Schema.Trim.pipe(Schema.minLength(2))
const OptionalString = Schema.optional(Schema.String)

const MyForm = Schema.Struct({
  password: Password,
  confirm_password: Password,
  name: OptionalString,
  surname: OptionalString
}).pipe(
  Schema.filter((input) => {
    const issues: Array<Schema.FilterIssue> = []

    // 检查密码是否匹配
    if (input.password !== input.confirm_password) {
      issues.push({
        path: ["confirm_password"],
        message: "Passwords do not match"
      })
    }

    // 确保名称或姓氏至少存在一个
    if (!input.name && !input.surname) {
      issues.push({
        path: ["surname"],
        message: "Surname must be present if name is not present"
      })
    }
    return issues
  })
)

console.log(
  JSON.stringify(
    Schema.decodeUnknownEither(MyForm)({
      password: "abc",
      confirm_password: "abd" // 确认密码不匹配
    }).pipe(
      Either.mapLeft((error) =>
        ParseResult.ArrayFormatter.formatErrorSync(error)
      )
    ),
    null,
    2
  )
)
/*
{
  "_id": "Either",
  "_tag": "Left",
  "left": [
    {
      "_tag": "Type",
      "path": [
        "confirm_password"
      ],
      "message": "Passwords do not match"
    },
    {
      "_tag": "Type",
      "path": [
        "surname"
      ],
      "message": "Surname must be present if name is not present"
    }
  ]
}
*/
```

在此示例中，我们定义了一个 `MyForm` 模式，其中包含密码验证字段和可选的名称/姓氏字段。`Schema.filter` 函数检查密码是否匹配，并确保提供了名称或姓氏。如果任一验证失败，则相应的错误消息与相关字段关联，并在结构化格式中返回两个错误。

<Aside type="tip" title="使用 ArrayFormatter 处理结构化错误">
  `ArrayFormatter` 提供详细且结构化的错误格式，
  而不是简单的错误字符串。这在处理复杂表单或结构化数据时特别有用。有关更多信息，请参见
  [ArrayFormatter](/docs/schema/error-formatters/#arrayformatter)。
</Aside>

## 暴露的值

对于具有过滤器的模式，您可以使用 `from` 属性访问基础模式（应用过滤器之前的模式）：

```ts twoslash
import { Schema } from "effect"

const LongString = Schema.String.pipe(
  Schema.filter((s) => s.length >= 10)
)

// 访问基础模式，即应用过滤器之前的字符串模式
//
//      ┌─── typeof Schema.String
//      ▼
const From = LongString.from
```

## 内置过滤器

### 字符串过滤器

以下是 Schema 模块提供的有用字符串过滤器列表：

```ts twoslash
import { Schema } from "effect"

// 指定字符串的最大长度
Schema.String.pipe(Schema.maxLength(5))

// 指定字符串的最小长度
Schema.String.pipe(Schema.minLength(5))

// 等同于 minLength(1)
Schema.String.pipe(Schema.nonEmptyString())
// 或
Schema.NonEmptyString

// 指定字符串的确切长度
Schema.String.pipe(Schema.length(5))

// 指定字符串长度的范围
Schema.String.pipe(Schema.length({ min: 2, max: 4 }))

// 根据正则表达式模式匹配字符串
Schema.String.pipe(Schema.pattern(/^[a-z]+$/))

// 确保字符串以特定子字符串开头
Schema.String.pipe(Schema.startsWith("prefix"))

// 确保字符串以特定子字符串结尾
Schema.String.pipe(Schema.endsWith("suffix"))

// 检查字符串是否包含特定子字符串
Schema.String.pipe(Schema.includes("substring"))

// 验证字符串没有前导或尾随空格
Schema.String.pipe(Schema.trimmed())

// 验证字符串全部为小写
Schema.String.pipe(Schema.lowercased())

// 验证字符串全部为大写
Schema.String.pipe(Schema.uppercased())

// 验证字符串为首字母大写
Schema.String.pipe(Schema.capitalized())

// 验证字符串为非首字母大写
Schema.String.pipe(Schema.uncapitalized())
```

<Aside type="tip" title="Trim vs Trimmed">
  `trimmed` 组合器不进行任何转换，仅进行验证。如果您寻找的是修剪字符串的组合器，请查看 `trim` 组合器或 `Trim` 模式。
</Aside>

### 数字过滤器

以下是 Schema 模块提供的有用数字过滤器列表：

```ts twoslash
import { Schema } from "effect"

// 指定大于 5 的数字
Schema.Number.pipe(Schema.greaterThan(5))

// 指定大于或等于 5 的数字
Schema.Number.pipe(Schema.greaterThanOrEqualTo(5))

// 指定小于 5 的数字
Schema.Number.pipe(Schema.lessThan(5))

// 指定小于或等于 5 的数字
Schema.Number.pipe(Schema.lessThanOrEqualTo(5))

// 指定介于 -2 和 2 之间的数字（含）
Schema.Number.pipe(Schema.between(-2, 2))

// 指定值必须为整数
Schema.Number.pipe(Schema.int())
// 或
Schema.Int

// 确保值不为 NaN
Schema.Number.pipe(Schema.nonNaN())
// 或
Schema.NonNaN

// 确保提供的值为有限数字
// （排除 NaN、+Infinity 和 -Infinity）
Schema.Number.pipe(Schema.finite())
// 或
Schema.Finite

// 指定正数 (> 0)
Schema.Number.pipe(Schema.positive())
// 或
Schema.Positive

// 指定非负数 (>= 0)
Schema.Number.pipe(Schema.nonNegative())
// 或
Schema.NonNegative

// 非负整数
Schema.NonNegativeInt

// 指定负数 (< 0)
Schema.Number.pipe(Schema.negative())
// 或
Schema.Negative

// 指定非正数 (<= 0)
Schema.Number.pipe(Schema.nonPositive())
// 或
Schema.NonPositive

// 指定能被 5 整除的数字
Schema.Number.pipe(Schema.multipleOf(5))

// 8 位无符号整数 (0 到 255)
Schema.Uint8
```
