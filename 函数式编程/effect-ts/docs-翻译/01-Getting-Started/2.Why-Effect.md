# Why Effect? | 为什么选择 Effect？

编程充满挑战。当我们构建库和应用时，会依赖各种工具来应对复杂性，让日常工作变得可管理。Effect 提供了一种新的 TypeScript 编程思维方式。

Effect 是一个工具生态系统，帮助你构建更好的应用和库。因此，你也将更深入地了解 TypeScript 语言，以及如何利用类型系统让你的程序更可靠、更易维护。

在"典型"的 TypeScript（不使用 Effect）中，我们编写假设函数要么成功要么抛出异常的代码。例如：

```typescript
const divide = (a: number, b: number): number => {
  if (b === 0) {
    throw new Error("Cannot divide by zero")
  }
  return a / b
}
```

根据类型，我们无法得知这个函数可能抛出异常。只有通过阅读代码才能发现。当你只有一个函数时，这似乎不是什么大问题，但当你有数百甚至数千个函数时，问题就开始累积了。很容易忘记函数可能抛出异常，也很容易忘记处理该异常。

通常，我们会做"最简单"的事，只是用 `try/catch` 块包裹函数。这是防止程序崩溃的良好起点，但并不能让管理或理解复杂的应用/库变得更轻松。我们可以做得更好。

TypeScript 中我们最重要的工具之一是编译器。它是防范 bugs、领域错误和复杂性的第一道防线。

## The Effect Pattern | Effect 模式

虽然 Effect 是一个由多种工具组成的大型生态系统，但如果只提炼出一个核心理念，那就是：

**Effect 最重要的独特洞见是：我们可用类型系统跟踪 <u>错误</u>和<u>上下文</u>，而不仅仅是<u>成功</u>值**（如上面 divide 示例中所示）。

上面那个 divide 函数，使用 Effect 模式重写成：

```typescript
import { Effect } from "effect"

const divide = (
  a: number,
  b: number
): Effect.Effect<number, Error, never> =>
  b === 0
    ? Effect.fail(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)
```

通过这种方式，函数不再抛出异常。相反，错误作为值处理，可像成功值一样传递。类型签名也清楚地表明：

- 函数返回的 <u>成功值</u> 类型（`number`）
- 可能发生的 <u>错误</u> 类型（`Error`）
- 需要的额外 <u>上下文或依赖</u>（`never` 表示无）

```
        ┌─── 产生类型为 number 的值      
        │       ┌─── 用 Error 失败      
        │       │      ┌─── 无依赖        
        ▼       ▼      ▼
Effect<number, Error, never>
```

此外，跟踪上下文允许你在不传入所有参数的前提下，为函数提供额外信息。例如，你可以在测试时用模拟对象（mocks）替换真实的外部服务实现，而无需更改核心业务逻辑。

## Don't Re-Invent the Wheel | 不要重复造轮子

TypeScript 中的应用代码经常重复解决相同问题。与外部服务、文件系统、数据库等交互是所有应用开发者常见问题。Effect 提供丰富的生态系统，为这些问题提供标准化解决方案。你可以用这些库构建应用，也可以用它们构建自己的库。

管理像错误处理、调试、追踪、异步/Promise、重试、流处理、并发、缓存、资源管理等等这些挑战，使用 Effect 变得可管理。你不必重新发明这些问题的解决方案，也不必安装大量依赖。Effect 作为一个统一工具包，解决了许多你通常需用不同 API 的多重依赖才能解决的问题。

## Solving Practical Problems | 解决实际问题的能力

Effect 深受其他语言（如 Scala 和 Haskell）中优秀工作的启发。但重要的是要理解，Effect 的目标是成为一个 <u>实用</u>工具箱，不惜一切代价解决开发者在 TypeScript 中构建应用和库时面临的真实日常问题。

## Enjoy Building and Learning | 享受构建和学习的过程

学习 Effect 非常有趣。Effect 生态中的许多开发者用它来解决日常工作中的真实问题，同时也在试验最前沿的想法，把 TypeScript 打造为最有用的编程语言。

你不必一次使用 Effect 的所有方面，可以从最贴合你解决问题需求的生态系统部分开始。Effect 是一个工具箱，你可以挑选最符合你用例的部分使用。但是，随着代码库中越来越多的部分使用 Effect，你很可能会发现自己想要利用更多生态系统功能！

Effect 的概念对你可能是新的，一开始可能不会完全理解。这完全正常。花点时间阅读文档，努力理解核心理念——这会在你深入 Effect 生态的高级工具后获得丰厚回报。Effect 社区随时乐意帮助你学习和成长。欢迎加入我们的 [Discord](https://discord.gg/effect-ts) 或于 [GitHub](https://github.com/Effect-TS) 讨论！我们欢迎反馈和贡献，始终在寻找改进 Effect 的方法。
