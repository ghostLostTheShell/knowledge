# Importing Effect

刚开始学习时，可能会觉得 Effect 提供的各种模块和函数种类繁多而感到不知所措。

但请放心，你不必一开始就掌握所有内容。

本页面将简单介绍如何导入模块和函数，并说明安装 `effect` 包通常就足够开始使用了。

## Installing Effect

[](#installing-effect)

如果你尚未安装` effect` 包，可以在终端运行以下命令进行安装：

-   [npm](#tab-panel-94)

    ```
    npm install effect
    ```
-   [pnpm](#tab-panel-95)
    ```
    pnpm add effect
    ```
-   [Yarn](#tab-panel-96)
    ```
    yarn add effect
    ```
-   [Bun](#tab-panel-97)
    ```
    bun add effect
    ```
-   [Deno](#tab-panel-98)

    ```
    deno add npm:effect
    ```

安装此包后，你就可以使用 Effect 的核心功能。

有关 Deno 或 Bun 等平台的详细安装说明，请参考 [Installation](/docs/getting-started/installation/) 指南，其中提供了逐步说明。

## Importing Modules and Functions

安装` effect` 包后，你就可以在 project 中使用其模块和函数了。导入模块和函数很简单，遵循标准的 JavaScript/TypeScript 导入语法。

要从` effect` 包导入模块或函数，只需在文件顶部使用` import` 语句。例如，导入` Effect` 模块：

```
import { Effect } from "effect"
```

现在你可以使用 Effect 模块，这是 Effect 库的核心。它提供了创建、组合和操作 effectful 计算的多种函数。

## Namespace imports

[](#namespace-imports)

除了使用命名导入（如前面所示）导入` Effect` 模块：

```
import { Effect } from "effect"
```

你也可以使用命名空间导入：

```
import * as Effect from "effect/Effect"
```

这两种导入形式都允许你使用` Effect` 模块提供的功能。

但有一个重要的考虑是**tree shaking**（摇树优化），这是在打包应用程序时消除未使用代码的过程。当打包器不支持深层范围分析时，命名导入可能会产生摇树问题。

以下是支持深层范围分析的打包器，因此不会遇到命名导入问题：

-   Rollup
-   Webpack 5+

## Functions vs Methods

[](#functions-vs-methods)

在 Effect 生态系统中，库通常暴露函数而不是方法。这一设计选择有两个关键原因：tree shakeability 和 extendibility。

### Tree Shakeability

[](#tree-shakeability)

摇树优化是指构建系统在打包过程中消除未使用代码的能力。函数可以摇树优化，而方法不能。

当在 Effect 生态系统使用函数时，最终打包代码中只包含实际导入并使用的应用程序函数。未使用的函数会被自动移除，导致更小的打包大小和更优的性能。

另一方面，方法附加到对象或原型上，无法轻易摇树优化。即使你只使用一部分方法，与对象或原型关联的所有方法也会被包含到打包中，导致不必要的代码膨胀。

### Extendibility

[](#extendibility)

在 Effect 生态系统使用函数的另一个重要优势是易于扩展性。使用方法时，扩展现有 API 的功能通常需要修改对象的 prototype，这可能很复杂且容易出错。

相反，使用函数时扩展功能简单得多。可以定义自己的“扩展方法”作为普通函数，而无需修改对象的 prototypes。这促进了更清晰和更模块化的代码，也允许与其他库和模块更好地兼容。
