
# 创建 Effects

Effect 提供了多种创建 effect 的方式，effect 是封装副作用的计算单元。在本指南中，我们将介绍一些常用的创建 effect 的方法。

## 为什么不用抛出错误？

在传统编程中，当出错时，通常会抛出异常：

```ts twoslash
// 类型签名不显示可能的异常
const divide = (a: number, b: number): number => {
  if (b === 0) {
    throw new Error("Cannot divide by zero")
  }
  return a / b
}
```

然而，抛出错误存在问题。函数的类型签名不表明它们可能抛出异常，这使得推理潜在的错误变得困难。

为了解决这个问题，Effect 引入了专用构造函数来创建表示成功和失败的 effect：`Effect.succeed` 和 `Effect.fail`。这些构造函数允许你显式处理成功和失败情况，同时**利用类型系统跟踪错误**。

### succeed

创建始终成功返回给定值的 `Effect`。

在需要创建一个没有错误或外部依赖关系就能成功完成特定值的 effect 时使用此函数。

**示例**（创建成功的 effect）

```ts twoslash
import { Effect } from "effect"

//      ┌─── Effect<number, never, never>
//      ▼
const success = Effect.succeed(42)
```

`success` 的类型是 `Effect<number, never, never>`，意味着：

- 产生类型为 `number` 的值
- 不会产生任何错误（`never` 表示无错误）
- 不需要额外的数据或依赖项（`never` 表示无要求）

```text showLineNumbers=false
         ┌─── Produces a value of type number
         │       ┌─── Does not generate any errors
         │       │      ┌─── Requires no dependencies
         ▼       ▼      ▼
Effect<number, never, never>
```

### fail

创建表示可恢复错误的 `Effect`。

在 effect 中显式表示错误时使用此函数。错误将持续传播，除非被处理。你可以使用 `Effect.catchAll` 或 `Effect.catchTag` 等函数来处理错误。

**示例**（创建失败的 effect）

```ts twoslash
import { Effect } from "effect"

//      ┌─── Effect<never, Error, never>
//      ▼
const failure = Effect.fail(
  new Error("Operation failed due to network error")
)
```

虽然你可以使用 `Error` 对象与 `Effect.fail` 一起使用，但你也可以根据错误处理策略传递字符串、数字或更复杂的对象。

使用"标记"错误（带有 `_tag` 字段的对象）有助于识别错误类型，并与标准的 Effect 函数（如 `Effect.catchTag`）配合得很好。

**示例**（使用标记错误）

```ts twoslash
import { Effect, Data } from "effect"

class HttpError extends Data.TaggedError("HttpError")<{}> {}

//      ┌─── Effect<never, HttpError, never>
//      ▼
const program = Effect.fail(new HttpError())
```

## 错误跟踪

使用 `Effect.succeed` 和 `Effect.fail`，你可以显式处理成功和失败情况，类型系统会确保错误被跟踪和记录。

**示例**（重写除法函数）

使用 Effect 重写 [`divide`](#why-not-throw-errors) 函数，使错误处理显式化：

```ts twoslash
import { Effect } from "effect"

const divide = (a: number, b: number): Effect.Effect<number, Error> =>
  b === 0
    ? Effect.fail(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)
```

在这个例子中，`divide` 函数在其返回类型 `Effect<number, Error>` 中表明操作可能成功返回 `number` 或失败返回 `Error`。

```text showLineNumbers=false
         ┌─── Produces a value of type number
         │       ┌─── Fails with an Error
         ▼       ▼
Effect<number, Error>
```

这种清晰的类型签名有助于确保错误被正确处理，并且任何调用函数的人都能了解可能的结果。

**示例**（模拟用户获取操作）

使用 `Effect.succeed` 和 `Effect.fail` 建模简单的用户获取操作，其中用户数据是硬编码的，这在测试场景或使用模拟数据时很有用：

```ts twoslash
import { Effect } from "effect"

// 定义 User 类型
interface User {
  readonly id: number
  readonly name: string
}

// 模拟从数据库获取用户的函数
const getUser = (userId: number): Effect.Effect<User, Error> => {
  // 正常情况下，你会在这里访问数据库或 API，但我们会用模拟数据
  const userDatabase: Record<number, User> = {
    1: { id: 1, name: "John Doe" },
    2: { id: 2, name: "Jane Smith" }
  }

  // 检查用户是否存在并返回适当的结果
  const user = userDatabase[userId]
  if (user) {
    return Effect.succeed(user)
  } else {
    return Effect.fail(new Error("User not found"))
  }
}

// 执行时，这将成功返回 id 为 1 的用户
const exampleUserEffect = getUser(1)
```

在这个例子中，`exampleUserEffect` 的类型为 `Effect<User, Error>`，会根据用户在模拟数据库中是否存在而返回 `User` 对象或 `Error`。

关于更深入地了解如何在应用中管理错误，请参考 [错误管理指南](/docs/error-management/expected-errors/)。

## 同步副作用建模

在 JavaScript 中，你可以使用"悬空函数"（thunks）来延迟同步计算的执行。

---
**Thunks**
> 悬空函数是一个不接受参数并可能返回值的函数。
---

悬空函数可用于延迟值的计算，直到它被需要时。

为了建模同步副作用，Effect 提供了 `Effect.sync` 和 `Effect.try` 构造函数，它们接受一个悬空函数。

### sync

创建表示同步副作用计算的 `Effect`。

在确定操作不会失败时使用 `Effect.sync`。

提供的函数（悬空函数）不能抛出错误；如果抛出，错误将被视为 [defect](/docs/error-management/unexpected-errors/)。

defect 不是标准错误，而是表明本应无错误的逻辑中存在缺陷。你可以将其视为程序中的意外崩溃，可以使用 `Effect.catchAllDefect` 等工具进一步管理或记录日志。这个功能确保应用程序中即使发生意外失败也不会丢失，也可以得到适当处理。

**示例**（记录消息）

在下例中，`Effect.sync` 用于延迟向控制台写入的副作用：

```ts twoslash
import { Effect } from "effect"

const log = (message: string) =>
  Effect.sync(() => {
    console.log(message) // 副作用
  })

//      ┌─── Effect<void, never, never>
//      ▼
const program = log("Hello, World!")
```

包含在 `program` 中的副作用（记录到控制台）只有在显式运行 effect 时才会发生（详见 [运行 Effects](/docs/getting-started/running-effects/) 部分）。这使得你可以在代码的某一点定义副作用，并控制何时激活它们，从而提高了大型应用中副作用的可管理性和可预测性。

### try

创建可能失败的同步计算的 `Effect`。

在需要执行可能失败的同步操作时（例如解析 JSON），你可以使用 `Effect.try` 构造函数。该构造函数旨在处理可能抛出异常的操作，通过捕获这些异常并将其转换为可管理的错误。

**示例**（安全的 JSON 解析）

假设你有一个尝试解析 JSON 字符串的函数。如果输入字符串不是有效格式的 JSON，此操作可能会失败并抛出错误：

```ts twoslash
import { Effect } from "effect"

const parse = (input: string) =>
  // 如果输入不是有效的 JSON，这里可能会抛出错误
  Effect.try(() => JSON.parse(input))

//      ┌─── Effect<any, UnknownException, never>
//      ▼
const program = parse("")
```

在这个例子中：

- `parse` 是创建一个封装 JSON 解析操作的 effect 的函数
- 如果 `JSON.parse(input)` 由于无效输入而抛出错误，`Effect.try` 会捕获此错误，由 `program` 表示的 effect 会以 `UnknownException` 失败。这确保错误不会被静默忽略，而是在 effect 的结构化流程中被处理。

#### 自定义错误处理

你可能想要将捕获的异常转换为更具体的错误，或者在处理错误时执行其他操作。`Effect.try` 支持一个重载，允许你指定捕获的异常应该如何被转换：

**示例**（自定义错误处理）

```ts twoslash {8}
import { Effect } from "effect"

const parse = (input: string) =>
  Effect.try({
    // JSON.parse 对无效输入可能会抛出错误
    try: () => JSON.parse(input),
    // 重新映射错误
    catch: (error: unknown) => new Error(`something went wrong ${error}`)
  })

//      ┌─── Effect<any, Error, never>
//      ▼
const program = parse("")
```

你可以将此视为 JavaScript 中传统 try-catch 块的类似模式：

```ts showLineNumbers=false
try {
  return JSON.parse(input)
} catch (error: unknown) {
  throw new Error(`something went wrong ${error}`)
}
```

## 建模异步 Effects

在传统编程中，我们通常使用 `Promise` 来处理异步计算。然而，处理 Promise 中的错误可能存在问题。默认情况下，`Promise<Value>` 只提供解析值的类型 `Value`，这意味着错误不会反映在类型系统中。这限制了表达能力，并使有效处理和跟踪错误变得具有挑战性。

为了克服这些限制，Effect 引入了专用构造函数来创建在异步上下文中表示成功和失败的 effect：`Effect.promise` 和 `Effect.tryPromise`。这些构造函数允许你显式处理成功和失败情况，同时**利用类型系统跟踪错误**。

### promise

创建表示保证成功的异步计算的 `Effect`。

在确定操作不会拒绝时使用 `Effect.promise`。

提供的函数（悬空函数）返回一个永远不会被拒绝的 `Promise`；如果被拒绝，错误将被视为 [defect](/docs/error-management/unexpected-errors/)。

defect 不是标准错误，而是表明本应无错误的逻辑中存在缺陷。你可以将其视为程序中的意外崩溃，可以使用 `Effect.catchAllDefect` 等工具进一步管理或记录日志。这个功能确保应用程序中即使发生意外失败也不会丢失，也可以得到适当处理。

**示例**（延迟消息）

```ts twoslash
import { Effect } from "effect"

const delay = (message: string) =>
  Effect.promise<string>(
    () =>
      new Promise((resolve) => {
        setTimeout(() => {
          resolve(message)
        }, 2000)
      })
  )

//      ┌─── Effect<string, never, never>
//      ▼
const program = delay("Async operation completed successfully!")
```

`program` 值的类型为 `Effect<string, never, never>`，可以解释为：

- 以类型为 `string` 的值成功
- 不产生任何预期错误（`never`）
- 不需要任何上下文（`never`）

### tryPromise

创建可能失败的异步计算的 `Effect`。

与 `Effect.promise` 不同，此构造函数适用于底层 `Promise` 可能被拒绝的情况。它提供了一种捕获错误并适当处理错误的方法。默认情况下，如果发生错误，它将被捕获并作为 `UnknownException` 传播到错误通道。

**示例**（获取 TODO 项）

```ts twoslash
import { Effect } from "effect"

const getTodo = (id: number) =>
  // 捕获任何错误并将它们作为 UnknownException 传播
  Effect.tryPromise(() =>
    fetch(`https://jsonplaceholder.typicode.com/todos/${id}`)
  )

//      ┌─── Effect<Response, UnknownException, never>
//      ▼
const program = getTodo(1)
```

`program` 值的类型为 `Effect<Response, UnknownException, never>`，可以解释为：

- 以类型为 `Response` 的值成功
- 可能产生错误（`UnknownException`）
- 不需要任何上下文（`never`）

#### 自定义错误处理

如果你希望对传播到错误通道的内容有更多控制权，可以使用 `Effect.tryPromise` 的一个重载，它接受一个转换函数：

**示例**（自定义错误处理）

```ts twoslash {7}
import { Effect } from "effect"

const getTodo = (id: number) =>
  Effect.tryPromise({
    try: () => fetch(`https://jsonplaceholder.typicode.com/todos/${id}`),
    // 重新映射错误
    catch: (error: unknown) => new Error(`something went wrong ${error}`)
  })

//      ┌─── Effect<Response, Error, never>
//      ▼
const program = getTodo(1)
```

## 基于回调函数创建

基于回调的异步函数创建 `Effect`。

有时你必须处理一些不支持 `async/await` 或 `Promise`、而是采用回调风格的 API。为了处理这类 API，Effect 提供了 `Effect.async` 构造器。

**示例**（包装回调 API）

让我们将 Node.js 的 `fs` 模块中的 `readFile` 函数包装成基于 Effect 的 API（确保已安装 `@types/node`）：

```ts twoslash
import { Effect } from "effect"
import * as NodeFS from "node:fs"

const readFile = (filename: string) =>
  Effect.async<Buffer, Error>((resume) => {
    NodeFS.readFile(filename, (error, data) => {
      if (error) {
        // 如果发生错误，以失败的 Effect 恢复
        resume(Effect.fail(error))
      } else {
        // 如果成功，以成功的 Effect 恢复
        resume(Effect.succeed(data))
      }
    })
  })

//      ┌─── Effect<Buffer, Error, never>
//      ▼
const program = readFile("example.txt")
```

在上面的例子中，我们手动为调用 `Effect.async` 注解类型：

```ts showLineNumbers=false "<Buffer, Error>"
Effect.async<Buffer, Error>((resume) => {
  // ...
})
```

因为 TypeScript 无法根据回调体内的返回值推断回调的类型参数。对类型进行注解确保提供给 `resume` 的值与期望的类型匹配。

`Effect.async` 内部的 `resume` 函数应该被调用恰好一次。超出一次的调用将被忽略。

**示例**（忽略后续的 `resume` 调用）

```ts twoslash
import { Effect } from "effect"

const program = Effect.async<number>((resume) => {
  resume(Effect.succeed(1))
  resume(Effect.succeed(2)) // 此行将被忽略
})

// 运行程序
Effect.runPromise(program).then(console.log) // 输出：1
```

### 高级用法

对于更高级的用例，传递给 Effect.async 的回调可以返回一个 Effect，当运行此 effect 的 fiber 被中断时将执行该 Effect。这可用于在执行操作时执行清理。

**示例**（使用清理处理中断）

在这个例子中：

- `writeFileWithCleanup` 函数将数据写入文件
- 如果运行此 effect 的 fiber 被中断，清理 effect（删除文件）将被执行
- 这确保当操作被取消时，像打开的文件句柄这样的资源会得到正确清理

```ts twoslash
import { Effect, Fiber } from "effect"
import * as NodeFS from "node:fs"

// 模拟长时间运行写入文件的操作
const writeFileWithCleanup = (filename: string, data: string) =>
  Effect.async<void, Error>((resume) => {
    const writeStream = NodeFS.createWriteStream(filename)

    // 开始向文件写入数据
    writeStream.write(data)

    // 当流完成时，以成功恢复
    writeStream.on("finish", () => resume(Effect.void))

    // 如果在写入期间发生错误，以失败恢复
    writeStream.on("error", (err) => resume(Effect.fail(err)))

    // 通过返回清理 effect 处理中断
    return Effect.sync(() => {
      console.log(`Cleaning up ${filename}`)
      NodeFS.unlinkSync(filename)
    })
  })

const program = Effect.gen(function* () {
  const fiber = yield* Effect.fork(
    writeFileWithCleanup("example.txt", "Some long data...")
  )
  // 模拟在 1 秒后中断 fiber
  yield* Effect.sleep("1 second")
  yield* Fiber.interrupt(fiber) // 这将触发清理
})

// 运行程序
Effect.runPromise(program)
/*
输出:
Cleaning up example.txt
*/
```

如果包装的操作支持中断，`resume` 函数可以接收一个 `AbortSignal` 来直接处理中断请求。

**示例**（使用 `AbortSignal` 处理中断）

```ts twoslash
import { Effect, Fiber } from "effect"

// 一个支持使用 AbortSignal 中断的任务
const interruptibleTask = Effect.async<void, Error>((resume, signal) => {
  // 模拟长时间运行的任务
  const timeoutId = setTimeout(() => {
    console.log("Operation completed")
    resume(Effect.void)
  }, 2000)

  // 处理中断
  signal.addEventListener("abort", () => {
    console.log("Abort signal received")
    clearTimeout(timeoutId)
  })
})

const program = Effect.gen(function* () {
  const fiber = yield* Effect.fork(interruptibleTask)
  // 模拟在 1 秒后中断 fiber
  yield* Effect.sleep("1 second")
  yield* Fiber.interrupt(fiber)
})

// 运行程序
Effect.runPromise(program)
/*
输出:
Abort signal received
*/
```

## 挂起的 Effects

`Effect.suspend` 用于延迟 effect 的创建。
它允许你将 effect 的评估延迟到实际需要时。
`Effect.suspend` 函数接受一个代表 effect 的悬空函数，并将其包装在挂起的 effect 中。

**语法**

```ts showLineNumbers=false
const suspendedEffect = Effect.suspend(() => effect)
```

让我们探索一些 `Effect.suspend` 证明有用的常见场景。

### 惰性求值

当你想要推迟一个 Effect 的求值，直到它真正被需要时。这在优化 Effect 的执行时非常有用，特别是在某些 Effect 并不总是需要执行，或者它们的计算开销非常昂贵的情况下。

此外，当创建具有副作用或作用域捕获的 effect 时，使用 `Effect.suspend` 以便每次调用时重新执行。

**示例**（带副作用的延迟评估）

```ts twoslash
import { Effect } from "effect"

let i = 0

const bad = Effect.succeed(i++)

const good = Effect.suspend(() => Effect.succeed(i++))

console.log(Effect.runSync(bad)) // 输出：0
console.log(Effect.runSync(bad)) // 输出：0

console.log(Effect.runSync(good)) // 输出：1
console.log(Effect.runSync(good)) // 输出：2
```

<Aside type="note" title="运行 Effects">
  本例使用 `Effect.runSync` 执行 effect 并显示其结果（详见 [运行
  Effects](/docs/getting-started/running-effects/#runsync) 了解更多信息）。
</Aside>

在这个例子中，`bad` 是调用 `Effect.succeed(i++)` 的结果，该调用递增了作用域变量但返回其原始值。`Effect.runSync(bad)` 不会导致任何新计算，因为 `Effect.succeed(i++)` 已经被调用过了。另一方面，每次调用 `Effect.runSync(good)` 时，传递给 `Effect.suspend()` 的悬空函数都会执行，输出作用域变量的最新值。

### 处理循环依赖

`Effect.suspend` 有助于管理 effect 之间的循环依赖，其中一个 effect 依赖另一个，反之亦然。
例如，`Effect.suspend` 常用于递归函数中以逃避急切调用。

**示例**（递归 Fibonacci）

```ts twoslash
import { Effect } from "effect"

const blowsUp = (n: number): Effect.Effect<number> =>
  n < 2
    ? Effect.succeed(1)
    : Effect.zipWith(blowsUp(n - 1), blowsUp(n - 2), (a, b) => a + b)

// console.log(Effect.runSync(blowsUp(32)))
// crash: JavaScript heap out of memory

const allGood = (n: number): Effect.Effect<number> =>
  n < 2
    ? Effect.succeed(1)
    : Effect.zipWith(
        Effect.suspend(() => allGood(n - 1)),
        Effect.suspend(() => allGood(n - 2)),
        (a, b) => a + b
      )

console.log(Effect.runSync(allGood(32))) // 输出：3524578
```
---
**运行 Effects**
  
>本例使用 `Effect.zipWith` 组合两个 effect 的结果 详见关于
  [组合](/docs/getting-started/control-flow/#zipwith)的文档了解更多详情。
---

`blowsUp` 函数创建了一个没有延迟执行的递归 Fibonacci 序列。对 `blowsUp` 的每次调用都会触发进一步的立即递归调用，迅速增加 JavaScript 调用栈大小。

相反，`allGood` 通过使用 `Effect.suspend` 延迟递归调用来避免栈溢出。这个机制不立即执行递归 effect，而是安排它们稍后运行，从而保持调用栈浅入并防止崩溃。

### 统一返回类型

在 TypeScript 难以统一返回 effect 类型的情况下，可以使用 `Effect.suspend` 来解决此问题。

**示例**（使用 `Effect.suspend` 帮助 TypeScript 推断类型）

```ts twoslash
import { Effect } from "effect"

/*
  没有 suspend 时，TypeScript 可能在类型推断上遇到困难。

  推断类型：
    (a: number, b: number) =>
      Effect<never, Error, never> | Effect<number, never, never>
*/
const withoutSuspend = (a: number, b: number) =>
  b === 0
    ? Effect.fail(new Error("Cannot divide by zero"))
    : Effect.succeed(a / b)

/*
  使用 suspend 统一返回类型。

  推断类型：
    (a: number, b: number) => Effect<number, Error, never>
*/
const withSuspend = (a: number, b: number) =>
  Effect.suspend(() =>
    b === 0
      ? Effect.fail(new Error("Cannot divide by zero"))
      : Effect.succeed(a / b)
  )
```
