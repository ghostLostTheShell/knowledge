# Effect 类型

`Effect` 类型是对**惰性**执行的工作流或操作的描述。这意味着当你创建一个 `Effect` 时，它不会立即运行，而是定义了一个可能成功、失败或需要某些额外上下文才能完成的程序。

`Effect` 的一般形式如下：

```
         ┌─── 代表成功的类型
         │        ┌─── 代表错误的类型
         │        │      ┌─── 代表所需的依赖项
         ▼        ▼      ▼

Effect<Success, Error, Requirements>
```

该类型表示一个 effect：

- 成功并返回类型为 `Success` 的值
- 失败并抛出类型为 `Error` 的错误
- 可能需要类型为 `Requirements` 的某些上下文依赖项来执行

概念上，你可以将 `Effect` 视为以下函数类型的 effectful 版本：

```typescript
type Effect<Success, Error, Requirements> = (
  context: Context<Requirements>
) => Error | Success
```

然而，effects 实际上并不是函数。它们可以建模同步、异步、并发和资源操作。

* **不可变性**。`Effect` 值是不可变的，Effect 库中的每个函数都会生成一个新的 `Effect` 值。

* **建模交互**。这些值本身不会执行任何操作，它们只是建模或描述 effectful 交互。

* **执行**。`Effect` 可以通过 [Effect 运行时系统](/docs/runtime/) 执行，该系统将其解释为与外部世界的实际交互。理想情况下，这种执行发生在应用程序中的单个入口点，例如启动 effectful 操作的主函数。

## 类型参数

`Effect` 类型有三个类型参数，含义如下：

| 参数 | 描述 |
|------|------|
| **Success** | 表示 effect 成功时返回的值类型。如果该类型参数为 `void`，意味着 effect 不产生有用的信息；如果为 `never`，意味着 effect 永远运行（或直到失败）。 |
| **Error** | 表示执行 effect 时可能出现的预期错误类型。如果该类型参数为 `never`，意味着 effect 不会失败，因为 `never` 类型没有值。 |
| **Requirements** | 表示执行 effect 所需的上下文数据。这些数据存储在名为 `Context` 的集合中。如果该类型参数为 `never`，意味着 effect 没有要求，`Context` 集合为空。 |

### Effect 类型参数缩写

在 Effect 生态系统中，你经常会遇到 `Effect` 的类型参数缩写为 `A`、`E` 和 `R`。这分别是成功值、**A**bbreviation、**E**rrror 和 **R**equirements 的简写。

## 提取推断类型

通过使用工具类型 `Effect.Success`、`Effect.Error` 和 `Effect.Context`，可以从 effect 中提取相应的类型。

### 示例（提取 Success、Error 和 Context 类型）

```typescript
import { Effect, Context } from "effect"

// 假设我们有一个 effect，成功返回数字，
// 失败返回 Error，并需要 SomeContext
declare const program: Effect<number, Error, SomeContext>

// 提取成功类型，即 number
type A = Effect.Success<typeof program>

// 提取错误类型，即 Error
type E = Effect.Error<typeof program>

// 提取上下文类型，即 SomeContext
type R = Effect.Context<typeof program>
```
