# Devtools

Effect 提供强大的开发工具来增强编码体验，帮助您编写更安全、更易维护的代码。这些工具会直接集成到您的编辑器中，提供实时反馈、智能重构和有用的诊断信息。

## Effect LSP

[](#effect-lsp)

Effect LSP（语言服务器协议）为您的编辑器添加了 Effect 专用功能。它分析您的 Effect 代码，通过诊断、快速信息、代码补全和自动重构提供智能辅助。

它支持所有支持标准 TypeScript LSP 的编辑器，如 VS Code、Cursor、Zed、NVim 等。

### Installation

[](#installation)

在项目安装 Effect 语言服务：

1. 安装作为开发依赖：
    
    对于 monorepo 项目，建议在主目录下安装语言服务。对于单一包的 project，安装在包的目录下。
    
    -   [npm](#tab-panel-86)
    -   [pnpm](#tab-panel-87)
    -   [Yarn](#tab-panel-88)
    -   [Bun](#tab-panel-89)
    
    Terminal window
    
    ```
    npm install @effect/language-service --save-dev
    ```
    
    Terminal window
    
    ```
    pnpm add -D @effect/language-service
    ```
    
    Terminal window
    
    ```
    yarn add --dev @effect/language-service
    ```
    
    Terminal window
    
    ```
    bun add --dev @effect/language-service
    ```
    
2. 在 `tsconfig.json` 中添加插件：
    
    tsconfig.json
    
    ```
    1{2  "compilerOptions": {3    "plugins": [4      {5        "name": "@effect/language-service"6      }7    ]8  }9}
    ```
    
3. 确保编辑器使用工作区的 TypeScript 版本：
    
    这一步对语言服务的正常运行至关重要。插件必须使用您在项目中安装的 TypeScript 版本，而不是编辑器自带的版本。
    
    Tip
    
    在 VS Code 或 Cursor 中，您可以打开一个 TypeScript 文件，点击状态栏上的 TypeScript 版本号，然后选择"Use Workspace Version"来使用工作区的 TypeScript 版本。
    
4. 可以开始使用了！
    
    在您的 project 下的 file.ts 文件中编写以下代码，应该会看到一个错误诊断，提示 Effect 值必须被 yield 或赋值给变量：
    
    ```
    1import { Effect } from "effect"2
    3Effect.log("Hello world!")4// ^- should be run or assigned to a variable!
    ```
    

### Features

[](#features)

Effect 语言服务提供了一组全面的功能来增强您的开发工作流：

#### Intelligent Quick Info

[](#intelligent-quick-info)

悬停在 Effect 值上查看扩展的类型信息和详细洞察：

-   **Effect 类型**：查看 Effect 值的完整类型信息
-   **Generator 参数**：在`yield*`悬停时（在`Effect.gen` 中）查看已 yield 值的详细信息
-   **Layer 组合**：使用交互式图表可视化层依赖，展示层如何组合
-   **服务依赖**：一目了然地了解服务需求和它们的关系

#### Real-time Diagnostics

[](#real-time-diagnostics)

编写代码时捕捉常见错误和问题：

-   **Floating Effects**：检测到未赋值或 yield 的 Effect 值，防止静默 bug
-   **Layer Issues**：在运行时之前检测层要求泄漏和范围违规
-   **Unnecessary Code**：识别冗余的 `Effect.gen` 或 `pipe()` 调用
-   **Error Handling**：检测不能失败的 Effect 上的 catch 函数误用
-   **版本冲突**：检测到您的 project 中有多个 Effect 版本

#### Smart Completions

[](#smart-completions)

通过上下文感知的建议来加速编码：

-   **Generator Boilerplate**：快速搭建`Effect.gen` 函数
-   **Scaffolds**：用于`Effect.Service`、`Data.TaggedError` 等
-   **Self Parameters**：服务声明中`Self` 参数的自动完成

#### Powerful Refactors

[](#powerful-refactors)

通过智能自动重构转换代码：

-   **Async to Effect**：使用`gen` 或`fn` 语法将 async 函数转换为 Effect
-   **Error Generation**：从基于 promise 的代码生成标记错误
-   **Service Accessors**：自动实现服务访问器函数
-   **Pipe Conversion**：将函数调用转换为 pipe 语法
-   **Pipe Styles**：在不同 pipe 风格格式之间切换
-   **Layer Magic**：自动组合具有正确依赖的层

### Configuration

[](#configuration)

Effect LSP 也提供了大量配置选项，如更改严重级别或禁用诊断消息。

查看完整的功能选项和特性列表，请访问 [LSP 仓库的 README](https://github.com/Effect-TS/language-service)。

### Build-Time Diagnostics

[](#build-time-diagnostics)

虽然 LSP 只在编辑会话期间激活，但您可能希望在构建过程中捕捉诊断信息。

通常这是通过 linting 规则完成的，但由于几乎所有的 Effect 诊断都依赖于类型，这意味着需要启用意识到的 linting，这意味着需要在 project 文件上再次执行类型检查。

为了解决这个问题，Effect 语言服务允许您修补本地 TypeScript 安装，使诊断在类型检查时发出。

要启用它，运行以下命令修改本地 TypeScript 安装：

Terminal window

```
effect-language-service patch
```

要使所有开发者都能自动执行此操作，将其添加到 `package.json`：

package.json

```
1{2  "scripts": {3    "prepare": "effect-language-service patch"4  }5}
```

这确保语言服务在标准` tsc` 命令编译时运行。

## VS Code / Cursor Extension

[](#vs-code--cursor-extension)

Caution

编辑器扩展不包含 Effect LSP！该扩展的安装应按每个 project 进行，这允许更精细地控制何时加载它、针对哪些 project 并与您的仓库 lockfile 使用的版本固定。

编辑器扩展提供了帮助您调试 Effect 应用程序的工具。

目前仅支持 VS Code 和像 Cursor 这样的 VS Code fork 版本。

### Installation

[](#installation-1)

插件可以直接在您的编辑器扩展页面中搜索安装，或者从 [Code Marketplace](https://marketplace.visualstudio.com/items?itemName=effectful-tech.effect-vscode) 或 [Open VSX Marketplace](https://open-vsx.org/extension/effectful-tech/effect-vscode) 安装。

### Debugger Features

[](#debugger-features)

使用 Effect 扩展，您会在编辑器的 Debug 部分找到几个新部分，在您暂停执行时，它们会显示有用的调试信息。

-   **Context**：允许您检查当前暂停的 Effect Fiber 的上下文。
-   **Span Stack**：显示导致当前暂停 Effect 执行的遥测 span 栈。
-   **Fibers**：列出您的应用程序中运行的所有 Effect Fibers，允许您检查如中断能力等信息，并可以请求中断它们。
-   **Breakpoints**：允许启用"pause on defect"；让您的调试器当 Effect Fiber 以 defect 失败时暂停。

### Built-in Tracer and Metrics

[](#built-in-tracer-and-metrics)

内置的 tracer 和 metrics 视图允许您无需启动整个遥测服务即可快速查看应用程序的 Effect Spans 和 Metrics。

要启用它，需要在您的 project 中安装以下依赖：

-   [npm](#tab-panel-90)
-   [pnpm](#tab-panel-91)
-   [Yarn](#tab-panel-92)
-   [Bun](#tab-panel-93)

Terminal window

```
npm install @effect/experimental
```

Terminal window

```
pnpm install @effect/experimental
```

Terminal window

```
yarn add @effect/experimental
```

Terminal window

```
bun add @effect/experimental
```

然后在您的 Effect app 中导入并使用 DevTools 模块：

```
1import { DevTools } from "@effect/experimental"2import { NodeRuntime, NodeSocket } from "@effect/platform-node"3import { Effect, Layer } from "effect"4
5const program = Effect.log("Hello!").pipe(6  Effect.delay(2000),7  Effect.withSpan("Hi", { attributes: { foo: "bar" } }),8  Effect.forever,9)10const DevToolsLive = DevTools.layer()11
12program.pipe(Effect.provide(DevToolsLive), NodeRuntime.runMain)
```

如果您的 project 中使用`@effect/opentelemetry`，则确保在 tracing layers 之前提供 DevTools layer，以便 tracer 正确修补。

现在启动您的 editor 和应用程序。在 Effect panel 的 clients 部分，您将看到新连接的客户。

在您的 editor 底部，靠近终端的地方，还会出现一个新选项卡"Effect Tracer"，以可视化方式实时显示您的 spans。
