
## 概述

Effect 管道允许对值进行操作的组合和序列化，以简洁且模块化方式实现数据的转换和操作。

## 为什么管道对结构化应用很好

管道是结构化应用和处理数据转换的极佳方式，它们提供几个优势：

1. **可读性**：管道允许以可读且序列化的方式组合函数。你可以清晰看到数据流和应用于它的操作，使代码更易理解和维护。
    
2. **代码组织**：使用管道，可以将复杂操作分解为更小的、可管理的函数。每个函数执行特定任务，使代码更模块化、更易推理。
    
3. **可复用性**：管道促进函数复用。通过将操作分解为更小的函数，可以在不同管道或上下文中复用它们，提高代码复用并减少重复。
    
4. **类型安全**：通过利用类型系统，管道帮助在编译时捕获错误。管道中的函数具有明确定义的输入和输出类型，确保数据正确流过管道并最小化运行时错误。
    

## 函数 vs 方法

Effect 生态系统库中使用函数对于实现**可摇树性（tree shakeability）**和确保**扩展性**非常重要。函数通过消除未使用代码实现高效的打包，并提供灵活模块化的方法来扩展库的功能。

### 可摇树性（Tree Shakeability）

可摇树性指的是构建系统在打包过程中消除未使用代码的能力。函数是可摇树的，而方法不是。

当在 Effect 生态系统中使用函数时，只有实际导入并在应用中使用的函数会被包含在最终打包的代码中。未使用的函数会被自动移除，产生更小的打包尺寸并提高性能。

另一方面，方法附加到对象或原型上，不能被轻松摇树。即使你只使用部分方法，与对象或原型关联的所有方法也会被包含在打包中，导致不必要的代码膨胀。

### 扩展性（Extensibility）

在 Effect 生态系统中使用函数的另一个重要优势是扩展的简单易行。对于方法，扩展现有 API 的功能通常需要修改对象的原型，这很复杂且容易出错。

相比之下，使用函数扩展功能要简单得多。你可以定义自己的"扩展方法"作为普通函数，无需修改对象的原型。这促进了更干净、更模块化的代码，并允许与其他库和模块有更好的兼容性。

## pipe

`pipe`函数是一个工具，允许我们以可读且序列化的方式组合函数。它取一个函数的输出并将其作为输入传递给管道中的下一个函数。这使得我们可以通过级联多个函数来构建复杂的转换。

**语法**

```typescript
import { pipe } from "effect"

const result = pipe(input, func1, func2, ..., funcN)
```

在此语法中，`input`是初始值，`func1`、`func2`、…、`funcN`是依次应用的函数。每个函数的结果成为下一个函数的输入，最终返回最终结果。

以下是`pipe`工作原理的图示：

```text
┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐    ┌───────┐    ┌────────┐
│ input │───►│ func1 │───►│ func2 │───►│  ...  │───►│ funcN │───►│ result │
└───────┘    └───────┘    └───────┘    └───────┘    └───────┘    └────────┘
```

需要注意的是，传递给`pipe`的函数必须具有**单个参数**，因为它们仅与单个参数调用。

让我们看一个例子来更好地理解`pipe`的工作方式。

**示例**（级联算术运算）

```typescript
import { pipe } from "effect"

// 定义简单的算术运算
const increment = (x: number) => x + 1
const double = (x: number) => x * 2
const subtractTen = (x: number) => x - 10

// 使用`pipe` 顺序应用这些运算
const result = pipe(5, increment, double, subtractTen)

console.log(result)
// 输出：2
```

在上述示例中，我们从输入值 `5` 开始。`increment`函数将 `1` 添加到初始值，结果为 `6`。然后，`double`函数将值加倍，给我们 `12`。最后，`subtractTen` 函数从 `12` 中减去 `10`，得到最终输出 `2`。

结果等价于`subtractTen(double(increment(5)))`，但使用`pipe`使代码更易读，因为操作从左到右顺序排列，而不是由内向外嵌套。

## map

通过应用函数转换 effect 中的值。

**语法**

```typescript
const mappedEffect = pipe(myEffect, Effect.map(transformation))
// 或
const mappedEffect = Effect.map(myEffect, transformation)
// 或
const mappedEffect = myEffect.pipe(Effect.map(transformation))
```

`Effect.map` 接受一个函数并将其应用于 effect 中包含的值，创建一个具有转换值的新 effect。

---
**注意：Effects 是不可变的**
> 值得注意的是，effects 是不可变的，这意味着原始 effect 不会被修改。相反，返回一个带有更新值的新 effect。
---

 **示例**（添加服务费）

这是一个实用示例，我们对交易金额应用服务费：

```typescript
import { pipe, Effect } from "effect"

// 添加服务费到交易金额的函数
const addServiceCharge = (amount: number) => amount + 1

// 模拟从数据库获取交易金额的异步任务
const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

// 对交易金额应用服务费
const finalAmount = pipe(
  fetchTransactionAmount,
  Effect.map(addServiceCharge)
)

Effect.runPromise(finalAmount).then(console.log) // 输出：101
```

## as

用常量值替换 effect 中的值。

`Effect.as` 允许你忽略 effect 中的原始值并用新常量值替换它。

---
**注意：Effects 是不可变的**
> effects 是不可变的，这意味着原始 effect 不会被修改。相反，返回一个带有更新值的新 effect。
---

**示例**（替换值）

```typescript
import { pipe, Effect } from "effect"

// 将值 5 替换为常量"new value"
const program = pipe(Effect.succeed(5), Effect.as("new value"))

Effect.runPromise(program).then(console.log) // 输出："new value"
```

## flatMap

级联 effects 以产生新的 `Effect` 实例，用于组合依赖于先前结果的操作。

**语法**

```typescript
const flatMappedEffect = pipe(myEffect, Effect.flatMap(transformation))
// 或
const flatMappedEffect = Effect.flatMap(myEffect, transformation)
// 或
const flatMappedEffect = myEffect.pipe(Effect.flatMap(transformation))
```

在上述代码中，`transformation`是接受值并返回 `Effect`的函数，`myEffect` 是正在被转换的初始`Effect`。

当需要级联多个 effects 时使用`Effect.flatMap`，确保每个步骤产生新的`Effect`，同时扁平化可能出现的嵌套 effects。

它类似于数组中使用的`flatMap`，但专门用于`Effect`实例，使你能够避免深层嵌套的 effects 结构。

---
**注意：Effects 是不可变的**
> effects 是不可变的，这意味着原始 effect 不会被修改。相反，返回一个带有更新值的新 effect。
---

**示例**（应用折扣）

```typescript
import { pipe, Effect } from "effect"

// 安全地对交易金额应用折扣的函数
const applyDiscount = (
  total: number,
  discountRate: number
): Effect.Effect<number, Error> =>
  discountRate === 0
    ? Effect.fail(new Error("Discount rate cannot be zero"))
    : Effect.succeed(total - (total * discountRate) / 100)

// 模拟从数据库获取交易金额的异步任务
const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

// 使用`flatMap` 级联获取和应用折扣
const finalAmount = pipe(
  fetchTransactionAmount,
  Effect.flatMap((amount) => applyDiscount(amount, 5))
)

Effect.runPromise(finalAmount).then(console.log)
// 输出：95
```

### 确保考虑所有 Effects

确保`Effect.flatMap` 中的所有 effects 都贡献于最终计算。如果你忽略了一个 effect，会导致意外行为：

```typescript
Effect.flatMap((amount) => {
  // 这个 effect 将被忽略
  Effect.sync(() => console.log(`Apply a discount to: ${amount}`))
  return applyDiscount(amount, 5)
})
```

在此情况下，`Effect.sync` 调用的被忽略，不影响`applyDiscount(amount, 5)`的结果。要正确处理 effects，请确保使用`Effect.map`、`Effect.flatMap`、`Effect.andThen`或`Effect.tap`等函数显式级联它们。

## andThen

级联两个操作，其中第二个操作可以依赖于第一个操作的结果。

**语法**

```typescript
const transformedEffect = pipe(myEffect, Effect.andThen(anotherEffect))
// 或
const transformedEffect = Effect.andThen(myEffect, anotherEffect)
// 或
const transformedEffect = myEffect.pipe(Effect.andThen(anotherEffect))
```

当需要按顺序运行多个操作，且第二个操作依赖于第一个操作的结果时使用`andThen`。这对于组合 effects 或必须按顺序处理的操作很有用。

第二个操作可以是：

1. 一个值（类似于`Effect.as`）
2. 返回值的函数（类似于`Effect.map`）
3. 一个`Promise`
4. 返回`Promise`的函数
5. 一个`Effect`
6. 返回`Effect`的函数（类似于`Effect.flatMap`）

**示例**（基于获取的金额应用折扣）

让我们看一个示例，比较`Effect.andThen`与 `Effect.map`和`Effect.flatMap`：

```typescript
import { pipe, Effect } from "effect"

// 安全地对交易金额应用折扣的函数
const applyDiscount = (
  total: number,
  discountRate: number
): Effect.Effect<number, Error> =>
  discountRate === 0
    ? Effect.fail(new Error("Discount rate cannot be zero"))
    : Effect.succeed(total - (total * discountRate) / 100)

// 模拟从数据库获取交易金额的异步任务
const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

// 使用 Effect.map 和 Effect.flatMap
const result1 = pipe(
  fetchTransactionAmount,
  Effect.map((amount) => amount * 2),
  Effect.flatMap((amount) => applyDiscount(amount, 5))
)

Effect.runPromise(result1).then(console.log) // 输出：190

// 使用 Effect.andThen
const result2 = pipe(
  fetchTransactionAmount,
  Effect.andThen((amount) => amount * 2),
  Effect.andThen((amount) => applyDiscount(amount, 5))
)

Effect.runPromise(result2).then(console.log) // 输出：190
```

### Option 和 Either 使用 andThen

[Option](/docs/data-types/option/#interop-with-effect) 和 [Either](/docs/data-types/either/#interop-with-effect) 都常用于处理可选或缺失值或简单错误情况。这些类型与`Effect.andThen` 很好地集成。当与`Effect.andThen` 一起使用时，操作被归类为场景 5 和 6（如前所述），因为`Option` 和`Either` 在这种情况下被视为 effects。

**示例**（带 Option）

```typescript
import { pipe, Effect, Option } from "effect"

// 模拟从数据库获取数字的异步任务
const fetchNumberValue = Effect.tryPromise(() => Promise.resolve(42))

//      ┌─── Effect<number, UnknownException | NoSuchElementException, never>
//      ▼
const program = pipe(
  fetchNumberValue,
  Effect.andThen((x) => (x > 0 ? Option.some(x) : Option.none()))
)
```

你可能期望`program` 的类型是`Effect<Option<number>, UnknownException, never>`，但实际上是`Effect<number, UnknownException | NoSuchElementException, never>`。

这是因为`Option<A>`被解释为类型`Effect<A, NoSuchElementException>`的 effect，因此可能的错误被合并到并集类型中。

---
**提示：Option 作为 Effect**
> 类型为`Option<A>`的值被解释为类型 `Effect<A, NoSuchElementException>` 的 effect。
---

**示例**（带 Either）

```typescript
import { pipe, Effect, Either } from "effect"

// 将一个可能失败的字符串解析为整数的函数
const parseInteger = (input: string): Either.Either<number, string> =>
  isNaN(parseInt(input))
    ? Either.left("Invalid integer")
    : Either.right(parseInt(input))

// 模拟从数据库获取字符串的异步任务
const fetchStringValue = Effect.tryPromise(() => Promise.resolve("42"))

//      ┌─── Effect<number, string | UnknownException, never>
//      ▼
const program = pipe(
  fetchStringValue,
  Effect.andThen((str) => parseInteger(str))
)
```

虽然可能期望`program` 的类型是 `Effect<Either<number, string>, UnknownException, never>`，但实际上是`Effect<number, string | UnknownException, never>`。

这是因为`Either<A, E>`被解释为类型 `Effect<A, E>`的 effect，意味着错误被合并到并集类型中。

---
**提示：Either 作为 Effect**
> 类型为`Either<A, E>`的值被解释为类型`Effect<A, E>`的 effect。
---

## tap

运行 effect 的结果的副作用，但不改变原始值。

当你想要执行副作用（如日志记录或跟踪）而不修改主值时使用`Effect.tap`。这是当你需要观察或记录操作但希望原始值传递给下一步时很有用。

`Effect.tap` 类似于`Effect.flatMap`，但它忽略传递给它的函数的结果。前一个 effect 的值仍然可用于链条的下一部分。请注意，如果副作用失败，整个链条也会失败。

**示例**（在管道中记录步骤）

```typescript
import { pipe, Effect, Console } from "effect"

// 安全地对交易金额应用折扣的函数
const applyDiscount = (
  total: number,
  discountRate: number
): Effect.Effect<number, Error> =>
  discountRate === 0
    ? Effect.fail(new Error("Discount rate cannot be zero"))
    : Effect.succeed(total - (total * discountRate) / 100)

// 模拟从数据库获取交易金额的异步任务
const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

const finalAmount = pipe(
  fetchTransactionAmount,
  // 记录获取的交易金额
  Effect.tap((amount) => Console.log(`Apply a discount to: ${amount}`)),
  // `amount` 仍然可用！
  Effect.flatMap((amount) => applyDiscount(amount, 5))
)

Effect.runPromise(finalAmount).then(console.log)
/*
输出：
Apply a discount to: 100
95
*/
```

在此示例中，使用`Effect.tap`在应用折扣之前记录交易金额，不修改值本身。原始值（`amount`）仍然可用于下一个操作（`applyDiscount`）。

使用`Effect.tap`允许我们在计算期间执行副作用而不改变结果。这对于日志记录、执行额外操作或观察中间值而不经干扰主要计算流很有用。

## all

将多个 effects 组合成一个，根据输入结构返回结果。

当你需要运行多个 effects 并将其结果组合成单个输出时使用`Effect.all`。它支持元组、迭代器、结构和记录，对不同输入类型很灵活。

例如，如果输入是元组：

```typescript
//         ┌─── effects 的元组
//         ▼
Effect.all([effect1, effect2, ...])
```

effects 按顺序执行，结果是一个包含结果作为元组的新 effect。元组中的结果与传递给`Effect.all`的 effects 的顺序匹配。

默认情况下，`Effect.all` 顺序运行 effects 并产生具有结果的元组或对象。如果任何 effect 失败，它停止执行（短路）并传播错误。

有关如何使用`Effect.all` 更多信息，请参见 [收集内容](/docs/getting-started/control-flow/#all)。

**示例**（组合配置和数据库检查）

```typescript
import { Effect } from "effect"

// 模拟从文件读取配置的函数
const webConfig = Effect.promise(() =>
  Promise.resolve({ dbConnection: "localhost", port: 8080 })
)

// 模拟测试数据库连接性的函数
const checkDatabaseConnectivity = Effect.promise(() =>
  Promise.resolve("Connected to Database")
)

// 组合两个 effects 执行启动检查
const startupChecks = Effect.all([webConfig, checkDatabaseConnectivity])

Effect.runPromise(startupChecks).then(([config, dbStatus]) => {
  console.log(
    `Configuration: ${JSON.stringify(config)}\nDB Status: ${dbStatus}`
  )
})
/*
输出：
Configuration: {"dbConnection":"localhost","port":8080}
DB Status: Connected to Database
*/
```

## 构建你的第一个管道

现在让我们结合`pipe`函数、`Effect.all` 和`Effect.andThen` 创建一个执行一系列转换的管道。

**示例**（构建交易管道）

```typescript
import { Effect, pipe } from "effect"

// 添加服务费到交易金额的函数
const addServiceCharge = (amount: number) => amount + 1

// 安全地对交易金额应用折扣的函数
const applyDiscount = (
  total: number,
  discountRate: number
): Effect.Effect<number, Error> =>
  discountRate === 0
    ? Effect.fail(new Error("Discount rate cannot be zero"))
    : Effect.succeed(total - (total * discountRate) / 100)

// 模拟从数据库获取交易金额的异步任务
const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

// 模拟从配置文件获取折扣率的异步任务
const fetchDiscountRate = Effect.promise(() => Promise.resolve(5))

// 使用 effects 的管道组装程序
const program = pipe(
  // 组合两个获取 effects 获取交易金额和折扣率
  Effect.all([fetchTransactionAmount, fetchDiscountRate]),

  // 对交易金额应用折扣
  Effect.andThen(([transactionAmount, discountRate]) =>
    applyDiscount(transactionAmount, discountRate)
  ),

  // 将服务费添加到折扣后金额
  Effect.andThen(addServiceCharge),

  // 格式化最终结果以便显示
  Effect.andThen(
    (finalAmount) => `Final amount to charge: ${finalAmount}`
  )
)

// 执行程序并记录结果
Effect.runPromise(program).then(console.log)
// 输出："Final amount to charge: 96"
```

这个管道展示了如何通过将不同 effects 组合成清晰、可读的流程来结构化你的代码。

## The pipe 方法

Effect 提供了一个`pipe` 方法，类似于在 [rxjs](https://rxjs.dev/api/index/function/pipe) 中找到的`pipe` 方法。这个方法允许你级联多个操作，使代码更简洁和可读。

**语法**

```typescript
const result = effect.pipe(func1, func2, ..., funcN)
```

这相当于像这样使用 `pipe`**函数**：

```typescript
const result = pipe(effect, func1, func2, ..., funcN)
```

`pipe` 方法在所有 effects 和许多其他数据类型上可用，无需导入`pipe` 函数并节省你的按键次数。

**示例**（使用`pipe` 方法）

让我们重写一个 [前面的示例](#build-your-first-pipeline)，这次使用 `pipe` 方法。

```typescript
import { Effect } from "effect"

const addServiceCharge = (amount: number) => amount + 1

const applyDiscount = (
  total: number,
  discountRate: number
): Effect.Effect<number, Error> =>
  discountRate === 0
    ? Effect.fail(new Error("Discount rate cannot be zero"))
    : Effect.succeed(total - (total * discountRate) / 100)

const fetchTransactionAmount = Effect.promise(() => Promise.resolve(100))

const fetchDiscountRate = Effect.promise(() => Promise.resolve(5))

const program = Effect.all([
  fetchTransactionAmount,
  fetchDiscountRate
]).pipe(
  Effect.andThen(([transactionAmount, discountRate]) =>
    applyDiscount(transactionAmount, discountRate)
  ),
  Effect.andThen(addServiceCharge),
  Effect.andThen(
    (finalAmount) => `Final amount to charge: ${finalAmount}`
  )
)
```

## Cheatsheet（速查表）

让我们总结一下到目前为止看到的转换函数：

| API | 输入| 输出|
| --- |---| --- |
| map | Effect<A, E, R>, A => B | Effect<B, E, R> |
| flatMap | Effect<A, E, R>, A => Effect<B, E, R> | Effect<B, E, R> |
| andThen | Effect<A, E, R>, \* | Effect<B, E, R>|
| tap| Effect<A, E, R>, A => Effect<B, E, R> | Effect<A, E, R>|
| all | [Effect<A, E, R>, Effect<B, E, R>, ...] | Effect<[A, B, ...], E, R> |
