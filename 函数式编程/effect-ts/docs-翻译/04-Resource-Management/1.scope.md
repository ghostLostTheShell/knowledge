`Scope` 数据类型是 Effect 中以安全且可组合的方式管理资源的核心结构。

一个作用域（Scope）代表了一个或多个资源的**生命周期**。当作用域关闭时，其中的所有资源都会被释放，从而确保没有资源泄漏。作用域还允许添加**终结器 (finalizers)**，用于定义如何释放资源。

通过 `Scope` 数据类型，你可以：

- **添加终结器**：终结器指定了资源的清理逻辑。
- **关闭作用域**：当作用域关闭时，所有资源都会被释放，并执行终结器。

**示例**（管理作用域）

```ts twoslash
import { Scope, Effect, Console, Exit } from "effect"

const program =
  // 创建一个新作用域
  Scope.make().pipe(
    // 添加终结器 1
    Effect.tap((scope) =>
      Scope.addFinalizer(scope, Console.log("终结器 1"))
    ),
    // 添加终结器 2
    Effect.tap((scope) =>
      Scope.addFinalizer(scope, Console.log("终结器 2"))
    ),
    // 关闭作用域
    Effect.andThen((scope) =>
      Scope.close(scope, Exit.succeed("作用域已成功关闭"))
    )
  )

Effect.runPromise(program)
/*
输出:
终结器 2 <-- 终结器按相反顺序关闭
终结器 1
*/
```

在上面的例子中，终结器被添加到作用域中，当作用域关闭时，终结器会**按相反的顺序执行**。

这种反序执行非常重要，因为它确保了资源按正确的顺序释放。

例如，如果你获取了一个网络连接，然后访问了远程服务器上的一个文件，那么文件必须在网络连接断开之前关闭，以避免错误。

## addFinalizer

`Effect.addFinalizer` 函数是一个高级 API，允许你向一个 Effect 的作用域中添加终结器。终结器是一段保证在相关联的作用域关闭时运行的代码。终结器的行为可以根据 [Exit](/docs/data-types/exit/) 值而变化，该值表示作用域是如何关闭的——是成功关闭还是带错关闭。

**示例**（在成功时添加终结器）

<Tabs syncKey="pipe-vs-gen">

<TabItem label="使用 Effect.gen">

```ts twoslash
import { Effect, Console } from "effect"

//      ┌─── Effect<string, never, Scope>
//      ▼
const program = Effect.gen(function* () {
  yield* Effect.addFinalizer((exit) =>
    Console.log(`终结器已执行。退出状态: ${exit._tag}`)
  )
  return "一些结果"
})

// 将 Effect 包装在作用域中
//
//      ┌─── Effect<string, never, never>
//      ▼
const runnable = Effect.scoped(program)

Effect.runPromiseExit(runnable).then(console.log)
/*
输出:
终结器已执行。退出状态: Success
{ _id: 'Exit', _tag: 'Success', value: '一些结果' }
*/
```

</TabItem>

<TabItem label="使用 pipe">

```ts twoslash
import { Effect, Console } from "effect"

const program = Effect.addFinalizer((exit) =>

).pipe(Effect.andThen(Effect.succeed("一些结果")))

// 将 Effect 包装在作用域中
//
//      ┌─── Effect<string, never, never>
//      ▼
```

</TabItem>

在这个例子中，我们使用 `Effect.addFinalizer` 添加了一个终结器，在作用域关闭后记录退出状态。终结器将在 Effect 完成时执行，并记录 Effect 是成功完成还是失败。

类型签名：

```ts showLineNumbers=false "Scope"
const program: Effect<string, never, Scope>
```

表明该工作流运行需要一个 `Scope`。你可以使用 `Effect.scoped` 函数来提供此 `Scope`，该函数会创建一个新作用域，在其中运行 Effect，并确保在作用域关闭时执行终结器。

<Aside type="note" title="终结器执行顺序">
  终结器按添加顺序的相反顺序执行，确保资源按正确的序列释放，就像栈回溯（stack unwinding）一样。
</Aside>

## 手动创建和关闭作用域

当你在单个操作中处理多个具有作用域的资源时，理解它们的作用域如何交互很重要。
默认情况下，这些作用域会合并为一个，但你可以通过手动创建和关闭作用域来更精细地控制每个作用域的关闭时机。

首先，让我们看看作用域默认是如何合并的：

**示例**（合并作用域）

```ts twoslash
import { Effect, Console } from "effect"

const task1 = Effect.gen(function* () {
  console.log("任务 1")
  yield* Effect.addFinalizer(() => Console.log("任务 1 后的终结器"))
})

const task2 = Effect.gen(function* () {
  console.log("任务 2")
  yield* Effect.addFinalizer(() => Console.log("任务 2 后的终结器"))
})

const program = Effect.gen(function* () {
  // 两个任务的作用域合并为一个
  yield* task1
  yield* task2
})

Effect.runPromise(Effect.scoped(program))
/*
输出:
任务 1
任务 2
任务 2 后的终结器
任务 1 后的终结器
*/
```

在这种情况下，`task1` 和 `task2` 的作用域被合并为一个单一作用域。

如果你想更多地控制每个作用域何时关闭，可以手动创建和关闭它们：

**示例**（手动创建和关闭作用域）

```ts twoslash
import { Console, Effect, Exit, Scope } from "effect"

const task1 = Effect.gen(function* () {
  console.log("任务 1")
  yield* Effect.addFinalizer(() => Console.log("任务 1 后的终结器"))
})

const task2 = Effect.gen(function* () {
  console.log("任务 2")
  yield* Effect.addFinalizer(() => Console.log("任务 2 后的终结器"))
})

const program = Effect.gen(function* () {
  const scope1 = yield* Scope.make()
  const scope2 = yield* Scope.make()

  // 将 task1 的作用域扩展到 scope1 中
  yield* task1.pipe(Scope.extend(scope1))

  // 将 task2 的作用域扩展到 scope2 中
  yield* task2.pipe(Scope.extend(scope2))

  // 手动关闭 scope1 和 scope2
  yield* Scope.close(scope1, Exit.void)
  yield* Console.log("正在做其他事情")
  yield* Scope.close(scope2, Exit.void)
})

Effect.runPromise(program)
/*
输出:
任务 1
任务 2
任务 1 后的终结器
正在做其他事情
任务 2 后的终结器
*/
```

<Aside type="note" title="扩展作用域 (Extending a Scope)">
  `Scope.extend` 函数允许你将一个需要作用域的 Effect 工作流扩展到另一个作用域中，且在工作流执行结束时不会关闭该作用域。这允许你将一个受限的值扩展到更大的作用域中。
</Aside>

你可能会好奇，如果作用域关闭了，但作用域内的一个任务尚未完成会发生什么。
关键点在于：**关闭作用域并不会强制中断该任务**。

**示例**（关闭带有待处理任务的作用域）

```ts twoslash
import { Console, Effect, Exit, Scope } from "effect"

const task = Effect.gen(function* () {
  yield* Effect.sleep("1 second")
  console.log("已执行")
  yield* Effect.addFinalizer(() => Console.log("任务终结器"))
})

const program = Effect.gen(function* () {
  const scope = yield* Scope.make()

  // 立即关闭作用域
  yield* Scope.close(scope, Exit.void)
  console.log("作用域已关闭")

  // 即使作用域已关闭，此任务仍将执行
  yield* task.pipe(Scope.extend(scope))
})

Effect.runPromise(program)
/*
输出:
作用域已关闭
已执行 <-- 1 秒后
任务终结器
*/
```

## 定义资源

### acquireRelease

`Effect.acquireRelease(acquire, release)` 函数允许你定义在获取后、不再需要时能被安全释放的资源。这对于管理文件句柄、数据库连接或网络套接字非常有用。

使用 `Effect.acquireRelease` 需要定义两个动作：

1. **获取资源**：描述资源获取的 Effect，例如打开文件或建立数据库连接。
2. **释放资源**：确保资源被正确释放的清理 Effect，例如关闭文件或连接。

获取过程是**不可中断的**，以确保部分资源获取不会让系统处于不一致的状态。

`Effect.acquireRelease` 保证一旦资源成功获取，当 `Scope` 关闭时，其释放步骤总会执行。

**示例**（定义一个简单资源）

```ts twoslash
import { Effect } from "effect"

interface MyResource {
  readonly contents: string
  readonly close: () => Promise<void>
}

const getMyResource = (): Promise<MyResource> =>
  Promise.resolve({
    contents: "lorem ipsum",
    close: () =>
      new Promise((resolve) => {
        console.log("资源已释放")
        resolve()
      })
  })

const acquire = Effect.tryPromise({
  try: () =>
    getMyResource().then((res) => {
      console.log("资源已获取")
      return res
    }),
  catch: () => new Error("getMyResourceError")
})

const release = (res: MyResource) => Effect.promise(() => res.close())

// 创建资源管理工作流
//      ┌─── Effect<MyResource, Error, Scope>
//      ▼
const resource = Effect.acquireRelease(acquire, release)
```

这意味着工作流需要一个 `Scope` 才能运行，资源会在作用域关闭时自动释放。

### 示例模式：顺序操作 (Sequencing Operations)

在某些场景下，你可能需要执行一系列链式操作，其中每个操作的成功都取决于前一个。然而，如果任何一个操作失败，你希望**撤销所有之前成功操作的影响**。当你需要确保要么所有操作都成功，要么所有操作都没有产生任何影响时，这种模式非常有价值。

让我们看一个实现该模式的例子。假设我们要创建一个“工作空间 (Workspace)”，包括创建一个 S3 存储桶、一个 ElasticSearch 索引，以及一个依赖前两者的数据库条目。

首先，我们定义所需[服务](/docs/requirements-management/services/)的领域模型：

```ts twoslash
import { Effect, Context, Data } from "effect"

class S3Error extends Data.TaggedError("S3Error")<{}> {}
interface Bucket { readonly name: string }

class S3 extends Context.Tag("S3")<
  S3,
  {
    readonly createBucket: Effect.Effect<Bucket, S3Error>
    readonly deleteBucket: (bucket: Bucket) => Effect.Effect<void>
  }
>() {}

// ... ElasticSearch 和 Database 的定义类似
```

接下来，我们为工作空间定义三个创建动作和整体事务 (`make`)。

```ts twoslash
// ... (之前的服务定义)

// 创建存储桶，并定义释放函数：如果操作失败，则删除存储桶。
const createBucket = Effect.gen(function* () {
  const { createBucket, deleteBucket } = yield* S3
  return yield* Effect.acquireRelease(createBucket, (bucket, exit) =>
    // 如果主 Effect 失败，Exit.isFailure(exit) 为 true，执行回滚
    Exit.isFailure(exit) ? deleteBucket(bucket) : Effect.void
  )
})

// ... createIndex 的定义类似

const createEntry = (bucket: Bucket, index: Index) =>
  Effect.gen(function* () {
    const { createEntry, deleteEntry } = yield* Database
    return yield* Effect.acquireRelease(
      createEntry(bucket, index),
      (entry, exit) =>
        Exit.isFailure(exit) ? deleteEntry(entry) : Effect.void
    )
  })

const make = Effect.scoped(
  Effect.gen(function* () {
    const bucket = yield* createBucket
    const index = yield* createIndex
    return yield* createEntry(bucket, index)
  })
)
```

我们可以通过提供不同的 `FailureCase` 来测试回滚逻辑。例如，如果 `Database` 创建失败：

```ansi showLineNumbers=false
[S3] creating bucket
[ElasticSearch] creating index
[Database] creating entry for bucket <bucket.name> and index <index.id>
[ElasticSearch] delete index <index.id>
[S3] delete bucket <bucket.name>
{ _id: 'Either', _tag: 'Left', left: { _tag: 'DatabaseError' } }
```

你可以观察到，一旦发生 `Database` 错误，就会触发完整的**回滚**：先删除 `ElasticSearch` 索引，然后删除关联的 `S3` 存储桶。结果是一个失败结果。
