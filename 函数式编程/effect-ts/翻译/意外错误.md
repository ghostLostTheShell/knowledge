# 意外错误

在某些情况下，您可能会遇到意外错误，并需要决定如何处理它们。Effect 提供了处理此类场景的函数，使您能够在执行您的 Effect 期间发生错误时采取适当的行动。

## 创建不可恢复的错误

[](#creating-unrecoverable-errors)

就像与杠杆利用例如 [Effect.fail](/docs/getting-started/creating-effects/#fail) 的 Comb赋能以创建类型为 `Effect<never, E, never>` 的值一样[]，Effect 库提供了工具来创建缺陷。

创建缺陷是在从业务逻辑角度无法从中恢复的错误中是常见的必要性，例如尝试建立连接在多次重试后被拒绝。

在这些情况下，终止 Effect 的执行并通过输出（如 stdout 或某些外部监控服务）进行报告移动到最有效的解决方案。

下列的函数和组合允许等效的终止，并经常用于与将类型 `Effect<A, E, R>` 的值转换到类型 `Effect<A, never, R>` 允许程序员从要处理和从没有任何理智方式恢复的错误获得逃生舱。

### die

[](#die)

创建一个终止带有指定错误的纤维的 Effect。

使用 `Effect.die` 时，当遇到应该不作为常规错误处理而是代表不可恢复的缺陷的意外条件时。

`Effect.die` 函数用于表示缺陷，这代表代码中的关键和意外错误。当调用时，它产生一个也不处理错误而是终止纤维的 Effect。

最终等效的错误通道类型为 `never`，表明它不能从这种失败中恢复。

**示例** （终止除以零带有指定的错误）

```
1import { Effect } from "effect"
2const divide: (a: number, b: number) => Effect<number, never, never> = (a: number, b: number) =>  b === 0    ? Effect.die(new Error("Cannot divide by zero"))    : Effect.succeed(a / b)
//      ┌─── Effect<number, never, never>//      ▼const program = divide(1, 0)
Effect.runPromise(program).catch(console.error)// Output:// (FiberFailure) Error: Cannot divide by zero//   ...stack trace...
```

### dieMessage

[](#diemessage)

创建一个终止带有包含指定消息的 `RuntimeException` 的纤维的 Effect。

使用 `Effect.dieMessage` 时，当您想由于不可恢复的缺陷而终止纤维并且在消息中包含清晰解释时。

`Effect.dieMessage` 函数用于表示缺陷，代表代码中的关键和意外错误。当调用时，它产生一个带有带有给定消息的 `RuntimeException` 的纤维终止的 Effect。

最终等效的错误通道类型为 `never`，表明它也不处理或从中恢复的错误。

**示例** （终止乘以除以零带有指定的消息）

```
1import { Effect } from "effect"
2const divide = (a: number, b: number) =>  b === 0    ? Effect.dieMessage("Cannot divide by zero")    : Effect.succeed(a / b)
//      ┌─── Effect<number, never, never>//      ▼const program = divide(1, 0)
Effect.runPromise(program).catch(console.error)// Output:// (FiberFailure) RuntimeException: Cannot divide by zero//   ...stack trace...
```

## 将失败转换为缺陷

[](#converting-failures-to-defects)

### orDie

[](#ordie)

将 Effect 的失败转换成纤维的终止，从 Effect 的类型中移除错误。

使用 `Effect.orDie` 时，当失败应该作为不可恢复的缺陷处理并且不需要任何错误处理时。

`Effect.orDie` 函数用于当您遇到不想要处理或从中恢复的错误。它从 Effect 中移除错误类型并确保任何失败都将终止纤维。这非常有用以将失败传播为缺陷，表明它们不应该在 Effect 中被处理。

**示例** （将错误作为一个缺陷传播）

```
1import { Effect } from "effect"
2const divide = (a: number, b: number) =>  b === 0    ? Effect.fail(new Error("Cannot divide by zero"))    : Effect.succeed(a / b)
//      ┌─── Effect<number, never, never>//      ▼const program = Effect.orDie(divide(1, 0))
Effect.runPromise(program).catch(console.error)// Output:// (FiberFailure) Error: Cannot divide by zero//   ...stack trace...
```

### orDieWith

[](#ordiewith)

将 Effect 的失败转换成带有自定义错误的纤维的终止。

使用 `Effect.orDieWith` 时，当失败应该终止纤维为缺陷，并且你想自定义错误用于清晰或调试目的时。

`Effect.orDieWith` 函数行为像 [Effect.orDie](#ordie) ，但是它允许您提供映射函数在终止纤维之前转换错误。这在您要包含更详细或用户友好的错误并且失败被传播为缺陷情况下非常有用。

**示例** （自定义缺陷）

```
1import { Effect } from "effect"
2const divide = (a: number, b: number) =>  b === 0    ? Effect.fail(new Error("Cannot divide by zero"))    : Effect.succeed(a / b)
//      ┌─── Effect<number, never, never>//      ▼const program = Effect.orDieWith(  divide(1, 0),  (error) => new Error(`defect: ${error.message}`))
Effect.runPromise(program).catch(console.error)// Output:// (FiberFailure) Error: defect: Cannot divide by zero//   ...stack trace...
```

## 捕获所有缺陷

[](#catching-all-defects)

没有理智的方式从缺陷中恢复。我们要讨论的函数只应该在 Effect 和外部系统之间的边界使用，以传达缺陷用于诊断或解释目的。

### exit

[](#exit)

`Effect.exit` 函数转换成 `Effect<A, E, R>` 的 Effect 封装在 [Exit](/docs/data-types/exit/) 数据类型：

```
Effect<A, E, R> -> Effect<Exit<A, E>, never, R>
```

这意味着如果具有下列类型的等效：

```
Effect<string, HttpError, never>
```

并调用 `Effect.exit` 于其上，类型变成：

```
Effect<Exit<string, HttpError>, never, never>
```

最终等效不能失败因为潜在失败现在被代表在 `Exit` 的 `Failure` 类型。返回的等效的错误类型被指定为 `never`，确认等效被构造的不失败。

通过产生 `Exit`，我们获得"模式匹配"的这种类型的能力在生成器函数内处理失败和成功案例。

**示例** （使用 `Effect.exit` 捕获缺陷）

```
import { Effect, Cause, Console, Exit } from "effect"
// Simulating a runtime error
const task = Effect.dieMessage("Boom!")
const program = Effect.gen(function* () {
  const exit = yield* Effect.exit(task)
  if (Exit.isFailure(exit)) {
    const cause = exit.cause
    if (
      Cause.isDieType(cause) &&
      Cause.isRuntimeException(cause.defect)
    ) {
      yield* Console.log(
        `RuntimeException defect caught: ${cause.defect.message}`
      )
    } else {
      yield* Console.log("Unknown failure caught.")
    }
  }
})
// We get an Exit.Success because we caught all failures
Effect.runPromiseExit(program).then(console.log)
// Output:
// RuntimeException defect caught: Boom!
// {
//   _id: "Exit",
//   _tag: "Success",
//   value: undefined
// }
```

## 捕获一些缺陷

[](#catching-some-defects)

当模型中有若干个特定的安全，最有效的策略只是将这些特定的安全作为失败来调用。

### catchSomeDefect

[](#catchsomedefect)

`catchSomeDefect` 函数类似于 [Effect.catchAll](/docs/error-management/matching/#catchall) 但是只能捕获例外情况的一个子类（例如，可以修补子类的路由错误或摄取错误）。

**示例**

```
import { Effect, Console } from "effect"

const connect = Effect.tryPromise({
  try: () => {
    console.log("Attempting to connect...")
    if (Math.random() > 0.5) throw new Error("Network connection failed")
    if (Math.random() > 0.5) throw new TypeError("Connection can only be made via TCP")
    return 42
  },
  catch: (error) => {
    console.error("[COMBINED ERROR]", error)
  }
})

const program = Effect.catchSomeDefect(connect, ([name, error]) =>
  name === "TypeError" ?
    Effect.succeed("Failed to connect because connection only supports TCP") :
    Effect.fail(error.default)
)

//      ┌─── Effect<number, never, never>      ▼
Effect.runPromise(program).then(console.log)
// Output:
// Attempting to connect...
// [COMBINED ERROR] [TypeError: Connection can only be made via TCP]
// Failed to connect because connection only supports TCP
```
