
## 类型
1. 强类型
不允许类型之间隐式转换
2. 弱类型
类型规则松，可以自动转换或混合类型
3. 静态类型
类型检查时机在编译时
4. 动态态类型
类型检查时机在运行时

好的，我们来系统总结 **强类型、弱类型、静态类型、动态类型**，并区分它们之间的概念。为了避免混淆，我会用表格和例子对比，非常直观。


## 类型的四种组合

| 类型系统组合 | 例子                | 特点                           |
| ------ | ----------------- | ---------------------------- |
| 强 + 静态 | Haskell, Java, C# | 类型检查严格且在编译时完成                |
| 强 + 动态 | Python, Ruby      | 类型安全，但类型在运行时才确定              |
| 弱 + 静态 | C（某些情况下）          | 编译时类型检查，但允许隐式转换（如 int→float） |
| 弱 + 动态 | JavaScript        | 类型灵活，但容易产生隐式转换错误             |

## 代数效应

代数效应是一种函数式编程的概念，它允许一个函数在执行过程中“暂停”其本身的逻辑，将某些“效应”（如异步操作、异常、状态变化等）的“如何执行”交给其调用者（或更外层的“处理器”）去处理，处理完毕后，再“恢复”函数的执行，并获取处理结

它有两个核心特点：

1. 分离“做什么”和“怎么做”：函数（组件）只声明它需要什么（如获取数据），但不关心具体怎么实现。

2. 保持函数的纯粹性和可预测性：从函数自身的视角看，它像是“同步”地获得了结果，这使得逻辑更容易理解和测试。
